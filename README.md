# VoxalBlast

六面贴块消除小游戏，使用 Vite + 原生 JavaScript + Three.js。

> 当前实现基线：**v0.9.2**（`package.json`）。本轮修回"方位微调左右对称"的回归（停靠角度改为由相机派生），见 [交互与表现需求 §2.1](docs/Planning/03-交互与表现需求.md)；上一轮的竖屏尺寸与发牌难度见 v0.9.1 / [发牌与渐进难度 P1 实现记录](docs/Technical/DEALING_P1.md)。不代表远端部署版本。

## 当前游戏

- **刷新即进单局**：加载/刷新直接落到一局（有未完成局则续玩，否则开新局），不再停在主页；主页只从局内设置的「回到主页」进入。
- **六面共享棋盘**：5×5×5 外壳，98 个唯一格；每面 5×5，棱角在相邻面共享，不往内部填块，无重力。
- **开场两阶段动画**：进入一局时六面体被一道斜向（屏幕左下 → 右上）波次**先造出来再上色**——第一阶段 98 格穿上同族三档冷灰蓝底漆（不含任何木色与漆色），停一拍后第二阶段用同一道波次把每块刷成它自己的正式色，约 2.8 秒。参数在 `INTRO_STYLE`；`prefers-reduced-motion` 时退化为 0.18 秒整盘淡入直接落到正式色。
- **三块一批、十五类形状**：候选朝向固定，旋转棋盘选面；六种四格件各权重 2，`Line 4` 显式权重 1，`Block 9` 降到 0.4，其余各 1（总权重 20.4）。四格件占 58.8%、四格及以上占 75.5%，不是旧十类池的 75%。
- **盘面感知发牌（v0.9.0）**：一批三块不再由三次独立抽取决定——每批先抽最多 36 个互不重复的组合，逐个**证明**在当前盘面上能不能三块放完，再按"首步容错区间"和"整批压力变化"挑选，最后才发出去。已证明无解的组合直接淘汰；**发死手不在机制里**。一批最多一个 `Block 9`，发出后三次自然换批内不再出现它；换批道具走同一套发牌，且不扣次数除非真的发得出来。
- **30/60/90 三级节点**：每成功落子算一步，`tier = min(3, 步数/30)`；新局前 3 批是 warmup，之后按 2～3 批 build → 一次 2/3/4/5 步的 challenge → 1 批 relief 循环。转面、道具、换批都不算步。
- **竖屏六面体缩小 10%（v0.9.1）**：只对竖屏生效（窗口朝向判定，不是画布比例）。六面体屏幕宽度 390×844 下 313.5px → 282.0px；横屏 844×390 的 198px 与桌面 1280×900 的 463px 逐值不变。系数是标定出来的（尺寸对系数次线性），实现在 解算相机距离处除以 `portraitCubeScale`。
- **方位微调左右对称（v0.9.2）**：静止停靠角度不再写死，改为**从相机派生**（`CAMERA_BEARING_YAW = atan2(cameraDirection.x, cameraDirection.z)`，当前 26°），即"正面正对镜头"的那一档。于是往左拨和往右拨露出的侧面**一样大**（实测两端各 10.0%，分别落在画面中心左侧 x = −0.186 与右侧 x = +0.194），静止时两侧面各 0%。v0.8.26 曾用写死的角度达到同一效果，随后被换相机的提交带跑偏（偏轴 10° → 静止 0% vs 10%、两端 0% vs 21.1%），这正是本次修回的回归。
- **同批消除**：每次成功落子检查六面满行/满列，共享格只删除一次；支持连击、跨面与荣誉计分。
- **有限道具救场**：每局换批 ×2、锤子 ×1、火箭 ×1、炸弹 ×1；没有局内补给、广告领取或购买。剩余候选都放不下时，先提示换批；无换批但清理道具有余量时保留局面；四项均耗尽才结算。只查次数，不保证道具一定救活。
- **交互与存档**：鼠标/触摸拖放、取消、世界轴翻面、方位微调、键盘旋转、滚轮缩放；主页、设置、单局续玩、本地纪录与荣誉墙。
- **参考图田园视觉**：98 个实时 3D 亮面方块，奶油桃木色空格；生成的透明 UI 切图、横竖屏田园背景和花草石台随包发布，背景加载失败时使用程序 SVG 兜底。

**尚不能宣称已完成**：全球排行榜、平台广告闭环、阶位标定、六面制霸徽章、道具获取系统、每日挑战。短局目标和机器人模拟都不等于真人体验验证。详见 [已知缺口](docs/Technical/KNOWN_GAPS.md)。

## 开发与按需验证

```sh
npm ci                 # 按锁文件安装依赖
npm run dev            # 开发服务器
npm test               # 规则层检查
npm run build          # 生产构建
npm run preview        # 预览生产产物
npm run shot           # 无头浏览器十组截图/断言，需可访问开发服务
npm run probe:intro    # 开场两阶段动画（启动入口、底漆/上色、节奏、结束位姿，并录下启动帧序）
npm run probe:swipe     # 手势方向
npm run probe:framing   # 24 朝向构图与方位微调
npm run probe:rescue    # 卡手后的三个救局分支
npm run probe:fragility # 3×3 形状空位几何对照
npm run probe:shapes    # 形状几何指标对照
```

浏览器探针依赖本机 Edge/Chrome、可用的全局 WebSocket 与开发入口；移动视口模拟**不是物理手机测试**。脚本入口与副作用见 [技术结构](docs/Technical/ARCHITECTURE.md)。纯文档修订只检查事实、链接、差异，不要求重新构建、截图或全量模拟。

## 维护规则

1. 当前行为以源码为准：规则查 `src/game/`，交互/道具/结束流程查 `src/main.js`，视觉与手感参数查 `src/rendering/config.js`。
2. 修改行为时同步对应文档；纯文档整理不升级游戏版本，不修改锁文件。
3. 实现、提案、历史实验和验证结果分开写；记录验证时注明版本、环境、范围，不能把旧勾选搬成当前通过。
4. 功能或视觉变更按 [04 回归清单](docs/Planning/04-MVP验收清单.md) 选取相关检查；视觉改动先读 [05 美术规范](docs/Planning/05-美术方向与视觉规范.md)。
5. 难度先看 [十四类池报告](docs/Technical/DIFFICULTY_CURVE_POOL14.md)。实验工具里的 `current` 是冻结的历史十类池，不能按名字误认为正式池；`soft75` 跟随正式权重，名字也不代表当前四格件占比。
6. 版本演变与当时验收保留在 [04](docs/Planning/04-MVP验收清单.md) 和各具名实验报告；本地成功不证明远端部署、CrazyGames 接口或物理手机已验收。
