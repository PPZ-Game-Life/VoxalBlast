# VoxalBlast

六面贴块消除小游戏。Vite + 原生 JavaScript + Three.js。积木使用实时 3D 几何、程序材质和灯光；UI 与图标由 CSS / SVG 绘制，田园布景使用随项目发布的 AI 绘制 WebP，加载前或失败时回退到程序 SVG。

```sh
npm install
npm run dev        # 开发服务器
npm test           # 规则层自测（tools/rule-tests.mjs）
npm run build      # 生产构建
npm run preview    # 预览产物
npm run shot       # 桌面 + 移动端实机截图（需先跑 dev）
npm run probe:swipe # 手势方向实机断言：左右侧带自转是否跟手（需先跑 dev）
npm run probe:framing # 停稳构图实机断言：24 朝向主面占比 + 旋转轴屏幕方向（需先跑 dev）
```

当前版本 **0.8.9**：给"方位微调"加了安全边界——每轴各自、不对称的 `bearingBand`（偏航 −30°…+4°、俯仰 −4°…+30°）。此前微调区间对称 ±30°，而"更正视"方向只有约 10° 余量，玩家能把六面体拨成纯平面板（实测偏航 +25°/俯仰 −25° → 主面 100%、另两面 0%），并且因为方位跨翻面保留、还写进存档，**会一直卡在那个状态**。现在拨到边界就停住，六个面始终都在。玩法、输入映射、阈值与其余画面沿用 v0.8.8。

v0.8.8：停稳角度改成玩家可微调的**方位**——阈值（≈30°）以内的拖动保留为新的停稳角度（不回弹、不二次动画），翻面时记住这个方位；"方位 + 本次拖动"越出 ±30° 才翻面。平面自转不留残角，方位随续玩存档保存。停稳构图（出厂方位）主面占三个可见面投影面积 71.4%（24 种标准朝向零离散），竖直棱恒为铅直。

v0.8.7：3/4 视角回到**相机**（`cameraDirection` 约 18.8°/17.6°），停稳的额外转角由一层固定在屏幕空间的倾斜提供，逻辑姿态与它分离。主面 71.4%、右面 18.1%、顶面 10.5%。

v0.8.6：~~相机改正视、由六面体双轴倾斜提供 3/4 感（主面 82.8%）~~ **已被制作人实测否决并废弃**——正面近似正视会让每一格都成近正方形，画面退化成平面网格，且双轴倾斜把棋盘压歪 −4.77°。保留下来的是探针（`faces()` / `poseAxisScreen()`）、easeOutCubic 吸附与"存档只存逻辑姿态"。

v0.8.5：方块质感优化——暖木色、三组云状表面纹理、独立凹凸与粗糙度贴图、柔亮倒角，以及随旋转变化的暖色接触阴影。棋盘仍为 98 个唯一实时 3D 方块，玩法、发牌和存档沿用 v0.8.4；本轮未新增 AI 贴图文件。参数与管线见 [美术规范](docs/Planning/05-美术方向与视觉规范.md)。

v0.8.4：**候选池改为加权发牌**——六种四格件（2×2、L、J、T、S、Z）各 2 份权重、四种小块各 1 份，即 75% 四格件 / 25% 小块，**十种形状全部保留**。依据与测量见 [紧张度测量](docs/Technical/DIFFICULTY_TENSION.md)。

v0.8.3 及更早：仍然是测量工具与文档——`tools/reachability.mjs` 新增 `--faces=`（换晶格尺寸）、`--seed=` / `--rng=mulberry32`（换随机源）与 `stepsWhenEnded` 指标，并据此复核了"缩小棋盘能不能加大难度"：**不能**，4×4（56 格）在同一套 4 格池下自然结束率 19.5%，低于现行 5×5 的 28.3%。同时修正了 v0.8.2 的随机源偏差（旧 LCG 按种子把整局聚簇，E 池的数字从 42.3% 修正为 28.3%）。矩阵与判读见 [难度与单局长度测量](docs/Technical/DIFFICULTY_BASELINE.md)。

2026-09-17 在同一工作树补了第二轮测量：新工具 `tools/difficulty-abcd.mjs` 做结构化开局 × 阶段发牌的 2×2 对照（2400 局 noise＋600 局 space）。结论是**阶段发牌**把弱机器人的自然结束率从 1.0% 抬到 12.5%（S(300) 100%→95.8%），**结构化开局**在本设置下没有分辨力（94.5% 的基线盘面本来就合格，配对差恒为 0），换成更强策略后阶段发牌的差异又归零——距"中位 60–120 步"的目标仍很远。报告见 [结构化开局 × 阶段发牌 A/B/C/D](docs/Technical/DIFFICULTY_ABCD.md)。本轮只加测量工具与文档，**未改玩法、未升版本号**。

第三轮把候选池按同一口径扫完（5 个压缩池 × 2 种发牌，7200＋750 局）：池子成分是目前幅度最大的杠杆——只留六种四格件把弱机器人结束率抬到 **34.2%**（现行池 1.0%），**但更强策略下 5 个臂 750 局全部 0 自然结束**；另外同为四格件，去掉 Square 会让结束率掉到 9.8%（机制未定）。报告见 [候选池与权重测量](docs/Technical/DIFFICULTY_POOL.md)。**人工终止条件已按制作人决定否决**，局终只能是"手上三块同时无处可放"。

第四轮扫开局预置密度（5 档 × 300 局 × 3 种子＋space 敏感性）：把开局从 0 格填到实测 41.6 格（98 格的 42%），结束率只在 1.0%–1.7% 之间摆动、配对差 ≤0.7pp——**零结果**；它只把"前 3 步有消除"从 71% 顶到 97%（现行预置基本已吃满）。报告见 [开局密度测量](docs/Technical/DIFFICULTY_OPENING.md)。至此规则内可测的旋钮已全部扫完，单局长度在**不改规则**的前提下没有可用杠杆。

第五轮把靶子从"局长"换成"每步有没有代价"（"太轻松"≠"太长"）：新增紧张度面板后测得现行配置下贪心打法 **100.0% 的步数里三块全都放得下**、一局最紧时刻仍有 19 个落点，而纯乱放 **99.7% 必死、中位 92 步**——**压力曲线是断的**，"快撑不住但还能救"的中间段几乎不存在。所有现有旋钮只能改变余量（熟练玩家 325 → 265 个落点），改变不了可能性（三块全可放始终 100%）。报告见 [紧张度测量](docs/Technical/DIFFICULTY_TENSION.md)。

第六轮补测了**真正不删形状**的加权发牌（此前把 `w90` 说成"不删形状"是错的——它的 Dot/Line 2/Corner 权重为 0，与 `d` 组成员相同）：十种全留、只把四格件权重调高，`soft75`/`soft82` 把典型打法结束率从 1.0% 抬到 **6.5%/8.8%**、最紧时刻 9 → 6/5 个落点。

**v0.8.4（本次）把它落地**：`src/game/shapes.js` 新增 `SHAPE_WEIGHTS`（四格件 2 份、小块 1 份 = 送出 75% 四格件，**十种形状一个不删**）与 `pickShape()`，`src/main.js` 三处发牌统一走它；开局预置与渲染未动。回滚只需把权重改回 1。规则口径见 [02 核心规则与数值](docs/Planning/02-核心规则与数值.md) §3，依据见 [紧张度测量](docs/Technical/DIFFICULTY_TENSION.md) §6。

## 目录

| 路径 | 内容 |
| --- | --- |
| `src/game/` | 规则层（棋盘、形状、计分、荣誉、排行、存档），不依赖渲染 |
| `src/rendering/` | 渲染与输入。`config.js` 是全部视觉/手感参数的单一真源 |
| `src/platform/` | CrazyGames SDK 适配（无 SDK 时自动降级） |
| `src/ui/` | 代码生成的矢量图标 |
| `src/main.js` | 场景装配、拖拽落子、旋转选面、HUD 联动 |
| `src/styles.css` | 布局与历史兼容 |
| `src/toy.css` | **当前视觉权威**（木质田园材质覆盖与文件末尾的桌面尺寸规则） |
| `public/art/` | 随构建发布的田园 WebP；`README.md` 记录生成来源、提示词与尺寸 |
| `tools/` | 开发脚本：规则自测、可达性、难度测量（`difficulty-*`）、截图、手势方向探针、停稳构图探针（`cube-framing-probe`）、PNG 统计、命名撞名检索（`name-collision-check`）、推送 |
| `docs/Planning/` | 01 立项 / 02 规则 / 03 交互 / 04 验收 / 05 美术 / 06 宣传 / 07 道具 / 08 荣誉 |
| `docs/Technical/` | 架构、已知缺口、部署基线 |
| `docs/Archive/` | 历次方向的历史版本 |
| `artifacts/` | 临时产物（不入库）：实机截图、一次性探针 |

## 关键约定

- **视觉改版先读 [05 美术方向与视觉规范](docs/Planning/05-美术方向与视觉规范.md)**，它写明现行几何、材质、光照、资产边界和历史模型的问题。
- 任何规则/数值/美术口径变更，须同步 `docs/Planning/01~08` 的对应条目与各自 `> 版本：` 行，并同步 `package.json` / `package-lock.json` 的 `version`。
- 视觉参数一律进 `src/rendering/config.js`，不在 `main.js` 散落魔法数字。
- 每批改动验证：`npm test` + `npm run build` + `npm run shot`；动了手势/方向再加 `npm run probe:swipe`（实机断言三个手势的世界轴方向）；动了相机、屏占比或停稳姿态再加 `npm run probe:framing`（实机断言 24 朝向的主面占比与三条轴的屏幕方向）。
- 本轮验证记录：[v0.8.1 侧带自转方向修复验收](docs/Planning/04-MVP验收清单.md)；v0.8.0 渲染品质改版记录保留在 [04](docs/Planning/04-MVP验收清单.md)，旧版记录不代替本轮验证。
- 难度与单局长度：动候选池、棋盘尺寸或手牌大小之前先看 [v0.8.3 复核](docs/Technical/DIFFICULTY_BASELINE.md)（`npm run reachability` 加 `--pool=` / `--batch=` / `--faces=` / `--rng=` 可自行复现；结论性数字要用 `--rng=mulberry32` 加多种子）。
- 开局与发牌：讨论"结构化开局""阶段发牌""有限步数模式"之前先看 [A/B/C/D 测量](docs/Technical/DIFFICULTY_ABCD.md)，用 `node tools/difficulty-abcd.mjs`（参数拼错即报错，不给默认值兜底）复现；该实验只跑 tools，正式游戏不导入。
