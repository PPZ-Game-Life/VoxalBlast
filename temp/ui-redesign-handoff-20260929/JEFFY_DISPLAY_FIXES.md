# 主页与设置显示不全：原因与处理（给 Jeffy）

> 这是诊断交接，不是已实施的修复。依据 v0.9.29 的现有桌面/手机截图、当前 CSS、部署 PNG 与原始交付的对比。本轮没有改游戏代码，也没有新跑浏览器或真机。

## 1. 转发摘要

**切图本身与接入样式都有问题，不能只改容器高度，也不需要重做整套图标。**

| 现象 | 已确认原因 | 应改哪里 |
|---|---|---|
| 主页皇冠与高分底板脱开，露出裁切下沿 | 百分比 padding 与皇冠宽度使用了不同参考宽度；皇冠还是有遮挡缺口的素材 | 先改 CSS 组合方式，必要时补完整装饰模块 |
| 最高分牌花叶缺边、底沿蓝线 | PNG 本身已截断花叶，并带有可见的源场景蓝色像素 | 返修/重切素材；overflow 无法补回缺失像素 |
| 设置框上下有贯穿横条、矩形填色与断接 | 原 PNG 已存在内框不连续的修复区域，拉伸后更显眼 | 修干净母版，再验九宫格 |
| Restart 圆角外露出红色矩形 | 新切图已经显示，但透明角后面的旧 danger 背景没有清掉 | 只清该按钮的旧 CSS 背景，保留 border-image |

现有 1440×900、390×844 截图中，设置七行均在画面内。这里看到的“缺边”不等于整行内容被视口裁掉；短屏/真机的滚动问题需另外实测。

## 3. 主页皇冠：先修参考宽度，不是继续调整图片大小

当前 `src/reference.css:278–280`：

```css
.home-record { width: min(298px, 78vw); padding-top: 30%; }
.home-record-crown { position: absolute; top: 0; left: 50%; width: 57%; height: auto; transform: translateX(-50%); }
```

**垂直 `padding-top:30%` 按包含块的宽度计算，不是按容器高度，也不是自动按 `.home-record` 自己的宽度计算。** 这里 record 是 grid item，padding 参考 grid area 的列宽；皇冠的 57% 则参考 record 宽度。因此两者不能稳定对齐。

- 桌面列宽 400px、record 宽 298px：顶部预留 120px；皇冠高度约 `298 × .57 × 173 / 267 = 110.1px`，形成约 **9.9px 空隙**，与已有截图中的悬空一致。
- 390px 竖屏列宽 350px：预留 105px，同一皇冠高约 110.1px，反而有约 **5.1px 重叠**。
- 短横屏不能照抄上述数值。`reference.css:354` 后写的 `gap:4px` 会覆盖前面的 `column-gap:24px`；`:342/:358` 也会改 record 宽度。修后用 DOM 实测，不引用未经验证的横屏计算表。

### 建议最小修法

让皇冠与底板在同一个明确宽度的容器中参与正常布局。以下只是起点，需放在能覆盖旧样式的位置，并检查媒体查询：

```css
.home-record { display: flex; flex-direction: column; align-items: center; padding-top: 0; }
.home-record-crown {
  position: static; inset: auto; transform: none;
  display: block; width: 57%; height: auto; z-index: 1;
}
.home-record-plate {
  position: relative; width: 100%; margin-top: -3%; z-index: 2;
}
```

`-3%` 不是定稿参数：它现在基于同一个 record 宽度，先让底板轻微盖住皇冠切口，再按参考图微调。必须复位旧 `transform`，不能只把 absolute 改 static 后留下横向偏移。

浏览器只读验收：`gap = plate.getBoundingClientRect().top - crown.getBoundingClientRect().bottom`。正值是脱开，负值是重叠。以视觉正确的适量重叠为准，不以某个固定像素跨所有屏幕硬压。

## 4. 最高分素材：花叶缺失与蓝残底必须返修

`home-record.png` 是 441×220，来自原主页图裁框 `(206,716,647,936)`。对照证据图可直接看到顶部与左右装饰被切断。当前 `.home-record-plate` 使用相同 `441/220` 比例，因此不能把这些已经缺失的花叶归咎于浏览器二次裁切。

- `alphaBounds [0,0,441,220]` 表明轮廓顶到画布边缘；是否缺失由原图对照确认，不能只凭 bbox 判定。
- 底沿 x94..360、y213..217 的蓝色像素已做 alpha 过滤核验：862 个像素 alpha≥128，常见 RGBA 为 `(105,157,216,251)`，确实可见，不是全透明像素里保留的无害 RGB。
- 皇冠切片底沿也不是四面完整的独立物件，不能让它悬空展示。

### 素材处理

1. 重切时包围完整可见轮廓，保留透明缓冲，不用规则圆角蒙版直接切掉向外伸出的花叶。
2. 沿真实轮廓清掉场景残底；不要对整张图做粗暴蓝色/白色删除，避免误伤高光与花瓣。
3. 被别的物件遮住、原图根本没有的结构，需要补绘或另制素材，不能声称直接切图就能恢复。
4. **更稳的长期方案**：将大皇冠＋底板＋完整花叶做成一张透明、无字的装饰模块，`最高分` 与数字仍用 DOM 叠加，避免两张残片的接缝。不是把完整首页截图作为背景。
5. `overflow:visible`、加 padding 只能避免未来的容器裁切，无法补回源 PNG 已缺失的像素；当前问题不能以“松开裁切”结案。

## 5. 设置外框：先修母版，再检查伸缩

当前部署的 `settings-modal.png` 是 776×1148。直接查看源图及证据图，即可看到顶部约 y47–64 区域的硬横线、底部约 y1065–1100 的矩形填带与内圆角不连续；这些是视觉定位区间，不是自动修复的坐标处方。

先前无字底重建使用了色带与局部镜像补位，留下可见接缝。**这部分属于素材交付质量问题，不能全归给 Jeffy 的布局。** 现有九宫格会改变接缝的呈现，但只调切线不能消除已烘进 PNG 的矩形补色。

### 处理要求

- 修复内框的连续圆角、光照与底色，用准确的内面蒙版，避免矩形色块跨过弧形边框；不要再用整段镜像硬接破坏光照。
- 必要时把外框与干净内底分层，或用可控 CSS 圆角/描边重建内底，再由美术确认风格。
- 清干净母版后，再确定九宫格安全切线，避开曲面与装饰；在不同宽高比下检查边缘连续性。
- 九宫格的中区与边角采用不同缩放是正常机制，**不要为了让缩放比例相同而盲目加粗金边**，也不要规定一个反推的“唯一设计高度”。
- 原包没有独立设置花叶角饰。若要求完全还原概念稿，应补独立角饰资源，不是通过 CSS 找回从未交付的图层。
- 验收使用棋盘格、白底、深底与场景底；同时看原尺寸和真实 UI 尺寸，不能只看缩小联系表。

## 6. Restart 红色方角：一处明确的 CSS 遗留

`src/toy.css:47/291` 的 `.setting-action.danger` 保留了旧底色/渐变；它有两个 class，比 `src/reference.css:415–423` 中单个 `.setting-action` 的 `background:none` 更具体。`:445` 的 `#restart-setting` 只设置新 `border-image-source` 与字色，没有清背景。

**新圆角切图已经在画，不是没加载。** 旧矩形背景画在它下面，从透明四角露出来。`settings-danger.png` 角区本来透明，不需要重做整张按钮图。

```css
#settings-modal #restart-setting {
  background: none;
  border-color: transparent;
  box-shadow: none;
}
```

保留现有 `border-image-source/slice/width` 和布局 `border-width`。不要用 `border:0` 或全量 `border-image:none` 让新皮肤一起消失；也不要只加 overflow 或圆角遮住旧底色就算完成。交互、danger 语义和可访问名称保持不变。

## 7. 短屏与滚动：待验证的风险，不冒充已复现根因

- `#settings-modal` 上下 padding 为 14×2=28px，而卡片 max-height 只预留 24px，预算相差 4px。应统一预算并量实际 rect；**不能据此直接宣布所有屏幕都被切了 2px**。
- 居中布局遇到超高内容可能产生负向溢出，应检查顶部与底部是否都能滚动到达；必要时采用安全居中/正常流与明确的内滚动区域。
- `dvh`、浏览器地址栏、visualViewport 与安全区要在目标浏览器测量，不把所有浏览器的 fixed+inset 统一断言为同一种视口行为。
- 设置标题继承的 margin 可以在短屏预算中核对，但收紧留白不能修复源图横条。
- 不通过删语言行、隐藏重开、压小字号或低于 44px 的命中区来“放全”。

## 8. 给 Jeffy 的执行顺序与验收

**第一批：只修 CSS**——皇冠改同宽度参考的组合、清 Restart 旧背景。保留现有素材，截图确认这两个因果成立。

**第二批：返修素材**——完整最高分装饰轮廓及蓝残底、连续干净的设置框。同步正式资源与制作流程，再检查九宫格。不要拿旧 temp PNG 回滚 v0.9.28 的清理。

验收矩阵：1440×900、390×844、320×568、844×390；中英双语；有/无存档；七行设置、触感 disabled、键盘提示；短屏滚动与关闭按钮可达。

- 皇冠没有悬空切口，花叶完整，最高分实时数字可读。
- 设置内框没有贯穿矩形修补条；Restart 透明角外无旧红底。
- 所有设置项和点击区域完整，焦点可见；保留当前语言入口与存档分支。
- 按涉及的模块跑针对性探针与前后截图；若后续实施改代码，再按项目规则运行相应测试。本文这一轮不重跑全量测试、不升版本。
