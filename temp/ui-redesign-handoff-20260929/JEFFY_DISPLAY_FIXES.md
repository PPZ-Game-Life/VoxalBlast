## 2. 确定项一：皇冠百分比定位与残片

### 现象

主页最高分皇冠在不同视口下纵向落点不一致；皇冠轮廓边缘能看见被切掉的残留碎片。

### 判定：布局为主，叠加素材固有缺陷

**布局侧**：皇冠用**百分比偏移**挂在容器上。容器高度随视口变化（桌面与竖屏不是同一套高度），百分比基准跟着变，于是皇冠在桌面「偏高」、在竖屏「偏低」。看上去像素材没对齐，实际是定位基准不稳定。

**素材侧**：`icons/home-crown-large.png`（267×173，`alphaBounds [2,2,265,173]`）的底沿在源设计里被分数底板与花叶压住，切出来必然是不规则边。它在**装配进底板之后**成立；单独悬浮时底边就会显得像「被切过」。这是已知限制，与缩放无关。

### 为什么不把它判成「素材尺寸错误」

因为同一份素材在桌面与竖屏的偏移方向不一致，而素材本身是固定像素。偏移随视口改变，指向定位基准而不是素材尺寸。反复重切不会让位置稳定。

### 处理

1. **改成流内同容器定位**：让皇冠与「最高分」底板处于同一容器、参与同一套流式布局，作为共同参考基准；不要再让它按视口百分比独立漂移。
2. **重置继承来的定位**：显式复位 `position`、`inset`（四个方向）、`transform`，避免旧的居中/位移规则叠加进来造成二次偏移。
3. **小负 `margin` 只当起点**：允许用很小的负外边距让皇冠底沿咬进底板，但这是**起点值**，必须在桌面与竖屏各看一次再收敛；不要靠大负值硬压。
4. **残片分两种情况处理**：
   - 残片来自皇冠自身的遮挡边 → 让底板/花叶盖住，或按第 7 节做素材返修。
   - 残片来自父容器 `overflow` 裁切 → 松开父容器裁切，而不是把素材再切一刀。
5. 皇冠是装饰层：`aria-hidden="true"`；`#home-best` 仍渲染真实数字，不把数字烘进图。

### 验收点

桌面与竖屏下，皇冠与底板的相对位置关系一致；皇冠轮廓无可见残留碎片。

## 3. 确定项二：`home-record` 花叶裁切与底部蓝残底

### 现象

最高分底板左右的花叶装饰被切掉一部分；底板下沿出现一条偏蓝的残留边。

### 判定：素材为主

**蓝残底是素材问题，已定点确认**：该素材边缘存在 **862 个 alpha ≥ 128** 的像素，其中最常见色值为 **RGBA(105,157,216,251)**。这是天空蓝，不属于设计里的叶片/花朵配色；alpha 高达 251，说明它不是抗锯齿过渡边，而是被一并带进来的源图底色。**这个结论已确认，不需要再重复扫描。**

**花叶被切是素材 + 布局各占一半**：`panels/home-record.png`（441×220）的 `alphaBounds` 为 `[0,0,441,220]`，即**内容贴满整张画布、四边没有留白**。素材本身没给花叶留呼吸空间，容器一旦按边裁剪或贴合宽高，花叶就先被牺牲。

### 为什么不套用固定切边数值

结论来自「素材四边无留白 + 容器存在裁切」这个可复现关系，而不是某个固定像素数或列数。按固定数值去猜切边位置，会得到无法复现的修法。

### 处理

1. **重切素材（首选）**：在源设计图上重新裁切，给花叶**预留透明外边距**，让花叶完整落在画布内；同时按 alpha 阈值收紧外沿，剔除天空底色（目标：边缘 alpha ≥ 128 的蓝色像素归零）。
2. **布局侧配合**：
   - 重新评估容器是否需要 `overflow: hidden`；确需裁切时，把裁切区做得比素材轮廓更大。
   - 底板用**固定纵横比**（`aspect-ratio`）承载，不要在多档视口下把宽高各自拉伸，避免花叶被压扁或切掉。
   - 皇冠与底板的咬合按第 2 节的流内方式处理，别让底板上移把下沿残留边顶到可见位置。
3. **过渡方案（仅缓解）**：可在容器侧留出与素材 `alphaBounds` 等量的内边距，让花叶有地方待。**但这不能替代重切**——残留蓝色像素仍留在素材里。

### 验收点

花叶左右完整；下沿无蓝色残留边；底板在桌面与竖屏下都不变形。

## 4. 确定项三：`settings-modal` 源图硬接缝与矩形补色

### 现象

设置外框上能看到接缝痕迹，以及块状的矩形补色区域。

### 判定：素材问题

该外框来自扁平设计图的**重建**：被文字与控件覆盖的底色用同一行的干净色带修复，被花叶遮挡的角部用镜像/同族边框补位，可拉伸版还移除了角饰。这是当时就记录在案的已知限制。

接缝与矩形补色正是这种重建的可见产物：

- 同一面里色值不连续 → 形成缝；
- 用色带或镜像块填补 → 在软渐变上留下矩形边界。

它不是缩放造成的，也不会因为改变拉伸方式而消失。

### 为什么不把它判成缩放/九宫格问题

九宫格的作用是让边框在拉伸时**不变形**。这里的异常来自源图内容本身的不连续，把九宫格参数调来调去，只会在不同尺寸下把缝挪到别的位置，问题依然存在。

### 处理

1. **首选：重做外框素材**。从设计图重新取面，避免用「一行色带」或「镜像块」拼补；必须补时应先做羽化过渡，并在实际视口尺寸下确认接缝不可见。
2. **备选：改由 CSS 还原边框**。若外框本质是「圆角 + 描边 + 轻微内高光」，用 CSS 实现可完全避开重建接缝，且天然适配任意尺寸与 DPR，比拉伸一张扁平图更稳。
3. **不要用九宫格参数掩盖接缝**（理由见上）。
4. 设置页的**行底**（`settings-row.png`、`settings-danger.png`）与**关闭按钮**（`close-button.png`）是另一批素材：本轮若不换，就不要顺手一起改，避免把已稳定的部分卷进来。

### 验收点

外框四边、四角在桌面与竖屏下均无可见接缝与矩形补色块。

## 5. 确定项四：「重新开始」行的旧 danger 背景优先级

### 现象

「重新开始」行显示的是旧的红色渐变底板，而不是新切图的样式。

### 判定：布局/CSS 优先级问题

这一行的旧皮肤在样式里给 `.setting-action.danger` 设了**渐变背景**。新切图若通过 `background-image`（或 `border-image`）挂上，就会与旧声明同时竞争。同一元素上「后写覆盖先写」以及 `background` 简写与 `background-image` 长写之间的覆盖关系，决定了最终由谁生效。

现象上表现为「新素材挂上了但看不见」，也就是被旧背景压住了。**它是样式优先级问题，不是素材缺失**——素材是好的，只是没显示出来。

### 处理

1. **清掉该行的旧背景**：在接入样式里显式把旧的 `background` 渐变重置为 `none`，避免简写把 `background-image` 一起清掉后又由旧规则命中。
2. **不要顺手清 `border-image`**：新切图若依赖 `border-image` 做可拉伸边框，清 `background` 时把 `border-image` 一并重置会把新边框也拆掉。两者分别处理。
3. **保留交互与无障碍语义**：重开行为、`.danger` 语义、焦点与命中区不变，只替换视觉来源。
4. **保留设置 7 行**：当前设置包含语言行在内共 **7 行**，必须全部保留（语言、声音、触感、拖块翻面、操作说明、回到主页、重新开始）。设计图为 6 行是更早的版本，**不要为了「与图一致」删掉语言设置**。

### 验收点

「重新开始」显示新样式；其余描边配置未被清掉；该行点击仍触发重开。

## 6. CSS 处理清单（要点汇总）

- **皇冠**：流式同容器作基准 → 复位 `position` / `inset` / `transform` → 小负 `margin` 只作起点 → 桌面与竖屏各看一次再收敛。
- **底板**：用固定纵横比承载；检查父容器是否在裁切花叶；需要裁切时扩大裁切区，而不是切素材。
- **设置外框**：优先重做素材或改 CSS 边框；**不要**用九宫格参数去掩盖源图接缝。
- **重新开始行**：清旧 `background`，**保留** `border-image` 与其他描边配置。
- **样式顺序**：`styles.css → toy.css → reference.css` 不变；新样式放在能稳定生效的位置（必要时用更明确的选择器，而不是堆 `!important`）。
- **最小改动面**：本轮只处理上述四处；不重排主页结构、不改存档分支、不动计分逻辑。

### 为什么不是「只调 overflow」

第 3、4 项的缺陷信息在**素材像素里**（残留底色、重建接缝）。容器裁切只能决定「露不露出来」，不能改变素材本身携带的错误像素。只调 `overflow` 的结果是：换一个尺寸或换一个视口，问题再次出现。

### CSS 方向示意（示意结构，不是可直接覆盖的补丁）

```css
/* ① 皇冠：流内同容器基准，复位继承来的定位 */
.home-crown {
  position: static;      /* 复位定位方式 */
  inset: auto;           /* 清掉四个方向偏移 */
  transform: none;       /* 清掉旧的位移/缩放 */
  display: block;
  margin-inline: auto;
  /* 小负值只作起点，桌面与竖屏各看一次再收敛 */
  margin-bottom: -6px;
}

/* ② 底板：固定纵横比承载，别让花叶被裁 */
.home-record {
  aspect-ratio: 441 / 220;
  overflow: visible;     /* 或把裁切区做得比轮廓更大 */
}

/* ③ 设置外框：优先重做素材；若改 CSS 边框就不要再叠旧底纹 */
.settings-card {
  border-radius: 24px;
  border: 3px solid var(--gold-line);
  box-shadow: inset 0 2px 0 #fff;
}

/* ④ 重新开始行：只清旧背景，保留 border-image 与描边 */
.setting-action.danger {
  background: none;              /* 关键：清掉旧渐变 */
  /* border-image 保留原样，不要在这里一起重置 */
}
```

上面第二段的负值、第三段的色值都是**占位起点**，实际数值要在 1440×900 与 390×844 下各测一次后收敛；不要直接照抄上线。

## 9. 边界与已知限制

- 本文判定基于已有的 1440/390 截图、素材 HASH 与 alpha 定点统计；**没有新增浏览器抓取，也没有真机验证**。
- 「显示不全」在此分为两类：**素材问题**（第 3、4 项）与**布局问题**（第 1、2 项相关部分与第 5 项）。第 1、2 项是两者叠加。
- 扁平设计图不是分层工程，被 UI 覆盖的区域无法凭空还原；因此外框与底板类素材的结论是「重做或改用 CSS」，而不是「调一个参数就好」。
- 本轮**不修改 runtime 任何文件**；本文与 `diagnostics/` 下的证据仅作交接件，接入由 Jeffy 执行。
