## 0. 现状判读与本版要解决的问题

**截图类型判定：当前实现截图，不是目标参考。** 依据：画面带 `v0.5.0`、BEST、道具按钮等工程/局内 UI 元素。按"偏差审查"处理，不作为基线继承。

读码实测（v0.5.0，`main.js` + `rendering/config.js`）：

| 元素 | 几何 | 相对壳面出挑 | 问题 |
| --- | --- | --- | --- |
| 壳体 | `RoundedBox` 4.92，圆角 0.16 | 0 | 轮廓接近硬边立方体 |
| 六面"格槽"面片 | `RoundedBox(0.9, 0.9, 0.78)`，位于 `cell + 法线 0.36` | **+0.29** | 每面 25 个独立凸板，可见面共 75 个 |
| 已放方块 | 0.92³，位于 `cell + 法线 0.24`（`voxelRaise`） | **+0.24** | 比槽板还**低** 0.05 |

四条结论：

1. **层级倒挂**：槽板（0.29）高于方块（0.24）→ 深色疙瘩块成了体积主体，彩色方块沦为"贴片"。这与"方块是主角、棋盘只作承托"直接冲突。
2. **轮廓破坏**：每个面由 25 个独立圆角凸板拼出，棱线逐格起伏，立方体轮廓变成锯齿/华夫饼状。
3. **体积不足**：方块出挑 0.24、倒角 0.14 → 可见侧壁只剩约 0.10 格，读作平面贴片而不是积木。
4. **棱边错位**：`shellRaise()` 对棱/角格采用"单轴优先 Z"策略，方块朝相机横向跳位（源码注释自认 "look like odd protrusions"）——左缘紫块、右缘蓝块向外鼓出即由此而来。

> 结论：**不是"方块不够圆"，而是格槽的角色演反了——它本该是凹位，却做成了凸台。**

> 同步风险提示：v0.5.0 文档表与代码已不同步（文档写"径向抬升 0.17 / 方块倒角 0.09 / 粗糙度 0.52"，代码实为 `voxelRaise 0.24` / `voxelRadius 0.14` / `voxelRoughness 0.32`；文档"格槽"色 `#345785` 也不等于代码 `0x405875`）。本版参数**以代码实测为准**，实现落地后请回填文档。

## 1. 方向结论（一句话 + 三条硬规则）

**面要平、槽要凹、块要凸；方块是画面上唯一的体积来源。**

1. 壳体是一个连续、干净的圆角立方体，面上**不再有逐格凸起**；
2. 空格 = 与壳面齐平的深色圆角凹位（暗约 12%），只负责"这里能放"；
3. 已放方块 = 贴在该面的圆角厚片（chip），只沿**所属面的法线**出挑 0.34 格。

## 2. 棋盘几何参数（格 = 1.0，立方体边长 5）

| 元素 | 面内尺寸 | 圆角 | 厚度 | 相对壳面 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 壳体 hull | 4.92 × 4.92 × 4.92 | 0.16 → 0.20 | — | 0（基准面） | 轮廓连续，无格级起伏 |
| 空槽 socket | 0.96 × 0.96 | 0.18 | 0.06 | **+0.04**（肉眼≈齐平） | 深色凹位，不抢层级 |
| 落点预览 preview | 0.92 × 0.92 | 0.12 | 0.06 | **+0.06** | 有效绿 0.72 / 无效红 0.72 |
| 已放方块 chip | 0.92 × 0.92 | 0.12 | **0.34** | **+0.34** | 唯一体积来源，可见侧壁 ≥ 0.22 |

- 方块间隙 = 1.0 − 0.92 = 0.08 格（≈ 方块边长的 8.7%），满足可读性下限。
- 槽比方块大 0.04 格：每个已放方块四周保留一圈 0.02 格的暗色卡口，"方块嵌进槽里"的关系才成立。
- 出挑基准恒为**面法线**，一次只沿一个轴。**取消** `shellRaise()` 的多轴与"优先 Z"逻辑。
- 凸出层级只有三档：**0.04 / 0.06 / 0.34**。任何新增视觉厚度必须落进这三档或另立参数并升版本文档。

### 2.1 棱格与角格（本版关键修正）

棱格被两个面共享、角格被三个面共享。规范：**每个暴露面各出一片 chip**（棱格 2 片、角格 3 片），各自沿本面法线出挑；两片在棱上以 0.08 的缝自然分开，形成干净的"包角"，不再出现朝相机横向跳位的错位方块。

数据层不需新模型：现有面片已带 `userData.cell`，实现为"该格被占用 → 该格所有暴露面各画一片 chip"即可。

## 5. 光照与阴影

- 单一主光（左上偏前）+ 环境光；三档明暗由材质与几何实现，不靠后期 Bloom。
- 壳面、槽面、方块都接收阴影；方块与壳面接触处保留 0.02 格暗色卡口 + 软化接触阴影，这是"嵌进去"观感的关键。
- 禁用：玻璃/霓虹/发光图层、随机高光、逐块不同光向、过量后处理辉光。

## 6. 动效（沿用 v0.5 边界，本版改两处）

| 事件 | 表现 | 时长/参数 |
| --- | --- | --- |
| 落子 | chip 沿面法线从 +0.46 落到 +0.34，轻微回弹 | 140~180ms |
| 落点预览 | 0.06 薄片、透明度 0.72、位置跟手 | 即时 |
| 消线 | 沿消线轴扫过的光带 + 方向受轴约束的小方块粒子 | 180~240ms |
| 得分 | 数字弹跳 + 连击条（×2 起点亮） | 150~220ms |
| 效果起点偏移 | `feedbackSurfaceOffset` **0.58 → 0.42**（壳面即基准面，不再需要让出壳厚） | 常量 |

`prefers-reduced-motion` 行为与 v0.5.0 一致，不改动。

## 7. 反 AI 制作约束（沿用 v0.5，新增第 8 条）

1. 先写清用途/尺寸/状态/明暗方向，再从模糊提示词生成最终资产。
2. 用可复用基础几何 + 明确比例，同类资产只做少量有意变体。
3. 光源、透视、圆角半径、线宽、阴影软硬度全项目统一；发现多套光照优先返工。
4. 禁随机细节填充：随机划痕、随机高光/装饰/渐变、无意义字母、乱码。
5. 生成式素材只能当草稿，须重建为可编辑的矢量/CSS/Shader/低复杂度模型并人工检查。
6. UI 文案、图标、数值一律用明确设计稿，不让生成工具决定文字与 logo。
7. 新资产过"缩小到实际游戏尺寸"和"灰度模式"两道检查。
8. **新增：一切"体积"必须能写成一个数。** 本版把出挑量收敛为 0.04 / 0.06 / 0.34 三档；评审时若说不出某处厚度对应哪个数值，判为不可验收。

## 8. 验收清单（逐条打勾）

- [ ] 缩到 240px 宽：第一眼是"明亮的彩色积木消除游戏"，不是"深蓝疙瘩立方体"。
- [ ] 立方体轮廓连续：沿顶面/侧面棱线截图放大，无逐格起伏（≤1px）。
- [ ] 灰度模式下已放方块与壳体/空槽仍可区分（亮度差 ≥12%）。
- [ ] 空槽比壳面暗 12%±4%，外缘不超出壳面 0.06 格。
- [ ] 方块可见侧壁 ≥0.20 格（低于此值判为"贴片"）。
- [ ] 出挑只沿单一面法线；旋转 4 个方向各截一张，棱/角格无横向错位。
- [ ] 落点预览为 0.06 薄片，不遮挡相邻已放方块。
- [ ] 候选 / 拖拽 / 棋盘三者方块同角度并排截图，圆角与明暗档一致，看不出两套美术系统。

- [ ] 手机 390 宽 + PC 1440 宽各一张截图：方块可读、棋盘不被裁切。

## 9. 给开发的落地话术

> **目标一句话**：把六面的"逐格凸板"改成"齐平凹槽"，方块改成只沿本面法线出挑 0.34 的圆角厚片。
>
> **具体问题**：`buildFaceTiles()` 生成的 0.9×0.9×0.78 面片沿法线外移 0.36，实际凸出壳面 0.29；而方块只凸 0.24 → 深色凸板成为体积主体、棱线呈锯齿。这不是圆角问题，是层级问题。
>
> **建议顺序（每步可单独验收）**：
> 1. `buildFaceTiles()`：面片改 `RoundedBoxGeometry(0.96, 0.96, 0.06, 4, 0.18)`，法线偏移 `0.36 → 0.01`；`gridColor 0x405875 → 0x293D57`、`gridActiveColor → 0x344D6D`。
> 2. `shellRaise()` / `placedLocal()`：删除多轴与"优先 Z"，改为"沿**该面**法线偏移"，`voxelRaise 0.24 → 0.34`；**棱格/角格按暴露面各渲染一片**。
> 3. 方块几何：`RoundedBoxGeometry(0.92, 0.92, 0.34, 6, 0.12)`（若为最小改动保留 0.92³，则把中心抬到壳面 −0.12；等效，但棱边接缝略差）；`voxelRadius 0.14 → 0.12`、`voxelRoughness` 保持 0.32、`metalness 0`。
> 4. 落点预览：0.06 薄片，`valid 0x63F08A` / opacity 0.72，去掉半透明线框立方体。
> 5. `feedbackSurfaceOffset 0.58 → 0.42`。
> 6. UI：提示胶囊移到候选槽上方、正式构建隐藏版本号、道具徽标改橙、候选卡与棋盘统一圆角与光照。
>
> **相关文件**：`src/main.js`（buildFaceTiles / shellRaise / placedLocal / 预览）、`src/rendering/config.js`（`BOARD_STYLE`、`RENDER_PALETTE`）、`src/styles.css` + `src/toy.css`、`src/ui/icons.js`。
>
> **验收**：按 §8 清单 + 桌面 1440 / 手机 390 截图 + `npm run build` 通过；玩法、计分、存档不回归。
