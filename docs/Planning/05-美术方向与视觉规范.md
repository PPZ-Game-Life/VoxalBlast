## 0. 方向结论（一句话 + 四条硬规则）

**一座摆在田园草坡上的木质玩具：木头是物体，彩色是唯一的高饱和。**

1. **木材 = 物体**。整块棋盘就是 150 个木方块；所有可点控件、弹窗面板、候选卡托盘，全部是同一套木纹与同一套「下沿加厚」的厚度语言。
2. **彩色 = 内容**。画面上只有「已放置方块」和「落点/道具预览」允许高饱和；其余一律落在木色—奶油纸色区间。
3. **背景 = 布景**。田园风景永远在棋盘之后、永远是柔和低对比的，且**不接收任何指针事件**。
4. **一个方块只有一个尺寸**。`0.91` 边长，六面全平；邻块间隙 `0.09`。任何"某类方块要更大/更高/更厚"的需求都是错的，只会破坏"大立方体由等大方块拼成"这一条。

## 1. 资产边界（未变，仍然强制）

运行时画面**全部由代码生成**：参数化几何、CSS、代码生成内联 SVG、Canvas 动态纹理、Shader。⛔ 不依赖外部 PNG/JPG/WebP/SVG 文件、视频背景、预制粒子图集、GLTF/FBX/OBJ 或第三方素材包。

本版新增的两块资产都守这条线：

| 资产 | 实现 | 文件 |
| --- | --- | --- |
| 木纹（3D 与 UI 同一套） | Canvas 逐像素绘制 → `THREE.CanvasTexture`（3D）/ `toDataURL()` 注入 CSS 变量 `--wood-grain`（UI） | `src/rendering/woodTexture.js` |
| 田园背景 | 启动时拼出的内联 SVG（天空/云/远山/村庄/石桥/河流/树木/栅栏/花草），`preserveAspectRatio="xMidYMid slice"`，viewBox 1440×1000 | `src/rendering/pastoralBackdrop.js` |

两张画布都用**固定种子的确定性随机**（`mulberry32`）：同一次构建每次加载的木纹与花丛位置必须完全一致，否则同一版的两张截图无法比对。

## 2. 棋盘 = 150 个等大方块拼成的大六面体（本版的核心修正）

**构成模型**：棋盘不是"一个壳 + 壳上贴图案"，而是 **5×5×5 晶格外壳上的 150 个立方体**。每个方块边长 `0.91`、**六面全平**（只在棱边留 `0.05` 的小倒角），居中放在自己的晶格格里；相邻方块之间天然留出 `0.09` 的间隙。方块的外侧面正好落在**大六面体的表面**上，于是整个棋盘读作"由等大方块拼成的一整个大立方体"，缝隙是唯一区分它们的东西。

壳体（`cubeBody`）**退化为背板**：它只负责遮挡远面、以及填住那 0.09 的缝，本身被藏到方块之后 `0.22`。它比方块**深**，所以"露出来的壳体"就等于"缝的颜色"。

统一几何：`blockGeometry = RoundedBoxGeometry(blockSize, blockSize, blockSize, blockSegments, blockRadius)`，**同一个 geometry 实例**给棋盘 150 块、三个候选槽、拖拽幽灵共用——手里的块和盘上的块是同一个对象。

| 参数 | 值 | 入口 |
| --- | --- | --- |
| 方块边长 `blockSize` | 0.91（间隙 = 1 − 0.91 = 0.09） | `BOARD_STYLE` |
| 棱边倒角 `blockRadius` | 0.05（六面保持平） | `BOARD_STYLE` |
| 方块位置 | 晶格格心，无任何轴向偏移 | `buildFaceTiles` |
| 背板 `hullInset` | 0.22（藏在方块之后） | `BOARD_STYLE` |
| 背板尺寸 / 圆角 | 5 − 0.22 = 4.78 / 0.08 | `main.js` |
| 落点预览 `previewLift` | 方块外表面再外移 0.03 | `BOARD_STYLE` |

**放置一个方块 = 把那一格的材质从「原木」换成「漆」。** 不新增网格、不改尺寸、不改位置、不改朝向、不改高度。棱格/角格同一个晶格格子在每个能看见它的面上都有自己的方块，占用时按晶格坐标同时上色，所以棱/角自然形成同色的包角。

> ⚠️ 背板的圆角半径必须小（现为 0.08）。背板是 4.78 的盒子，圆角大一点就会在 8 个角上让方块背后出现空洞——从大立方体的角看进去能看穿。

## 4. 材质与光照

- **一种木纹贯穿全场**：`woodGrainTextureRepeating()` 产出的是一张「接近白色的浅灰纹理」，作为 `map` 与材质 `color` 相乘。所以同一张图同时给背板、原木方块、十种漆色方块、以及手上拿着的方块上纹——**这就是棋盘与 UI 读起来是同一种材料的原因**（05「同源」）。背板 tile 数 2.2，方块 0.5。
- **每个原木方块有自己的色调**：`main.js#toneIndexFor()` 用晶格坐标做确定性哈希，从 `blockToneSteps` 六档里取一档。150 块全同色的立方体读起来是"一体成型的木箱"，参考图里是"一块块拼起来的木头"。哈希必须确定性（同一次构建每次加载完全一致），否则同一版的两张截图无法比对。
- 原木方块 `MeshStandardMaterial` 哑光 `roughness 0.72`；漆面 `MeshPhysicalMaterial` `roughness 0.34` + `clearcoat 0.55 / clearcoatRoughness 0.22` = 一层真清漆。**棋盘上的漆面和手里拿着的方块共用同一套参数**，所以一个方块从候选槽 → 拖拽 → 落到盘上，材质全程不变。
- 背板材质：`MeshPhysicalMaterial`，`roughness 0.7` + `clearcoat 0.1` = 擦过蜡的深色原木。
- 光照（`toyLights.js`）：`HemisphereLight(0xFFF6E4, 0x6F8F4A, 1.35)`（上方日光金、下方草地绿反弹）+ 主光 `DirectionalLight(0xFFF0CF, 3.2)` 位于**左上**（必须与背景 SVG 的太阳辉光同向）+ 天空冷补光 + 暖柔光箱。
- 阴影：主光投影，壳体/槽面/方块接收；低性能档 1024、高档 2048。
- 禁用：玻璃/霓虹/发光图层、随机高光、逐块不同光向、过量后处理辉光。

## 5. 背景（田园布景）

`installPastoralBackdrop(#app)` 在启动时把 `.pastoral-backdrop` 插为 `#app` 的第一个子元素。

> ⚠️ **绘制顺序陷阱（本版踩过）**：`z-index:-1` 的层画在根层叠上下文的第 2 步，而 **`body` 自己的背景画在第 3 步——在它之上**。所以天空渐变必须挂在 `html`（传播到画布，最底层），`body` 必须是 `transparent`，否则整张田园风景会被一层纯色渐变静默盖住。`src/toy.css` 末尾的「Backdrop paint order」段即为此。

- 层序（后→前）：天空渐变 → 太阳辉光 → 云 → 远山 → 中景丘陵 → 村庄（含教堂尖顶） → 河流与石桥 → 树线 → 草坡 → 木栅栏 → 左上角大树 → 草簇与雏菊 → 地平线雾气 + 暗角。
- 取景：`viewBox 1440×1000` + `xMidYMid slice`。桌面裁上下、手机取中间约 35% 宽度——**因此草地、丘陵、河流必须横向通铺**，村庄居中而非塞在角落。
- 交互：`pointer-events: none` + `aria-hidden`，永不接收事件、不可聚焦。
- 对比度约束：布景整体低对比，画面最亮最饱和的永远是立方体。

一条材质规则：**玩家能点的是木头（木纹 + 下沿加深 = 厚度），游戏显示在木头上的内容是奶油纸内嵌。**

| 圆形按钮（设置/操作说明/道具） | 木牌同源，`border-bottom 5px`，图标改**奶油白** `#FFF4DC`（深色线稿在木头上对比不足） |

| 候选托盘 `.bottom-panel` | 木框：`border-bottom 7px solid --wood-5` + 内阴影，圆角 26 |
| 候选卡 `.piece-slot` | 奶油纸内嵌（`--cream-1..3`）+ 内阴影 + `border-bottom 5px solid --wood-4` |
| 状态提示 / toast | 奶油纸标签 + 木边 |
| 弹窗 / 设置行 | 奶油纸面板 + 木纹底 + `border-bottom 8px solid --wood-4` |
| 主页 CTA | 蜜蜡黄立体钮；主页遮罩改**半透明**（`#B6E2F88C → #FBF3E2CF`），让草坡透出来 |
| 焦点环 | `#FFB62E` |

主次原则不变：**棋盘 > 当前分数 > 候选块 > 道具/设置/版本/装饰。**

`src/toy.css` 的 v0.7 段**只覆盖颜色/边框/阴影/材质**，绝不重声明 `height/width/gap/padding/order`——那些归 `styles.css` 与 v0.5 段的媒体查询，重声明会静默改掉手机布局。新增规则必须追加在**所有 v0.5 媒体查询之后**（同优先级下后写的生效）。

## 7. 反 AI 制作约束

1. 先写清用途/尺寸/状态/明暗方向，再谈表现。
2. 用可复用基础几何 + 明确比例，同类资产只做少量有意变体。
3. 光源、透视、圆角半径、线宽、阴影软硬度全项目统一；发现多套光照优先返工。
4. 禁随机细节填充：随机划痕、随机高光/装饰/渐变、无意义字母、乱码。
5. 生成式素材只能当草稿，须重建为可编辑的矢量/CSS/Shader/低复杂度模型并人工检查。
6. UI 文案、图标、数值一律用明确设计稿。
7. 新资产过「缩小到实际游戏尺寸」和「灰度模式」两道检查。
8. **一切「体积」必须能写成一个数**（见 §0.4）。
