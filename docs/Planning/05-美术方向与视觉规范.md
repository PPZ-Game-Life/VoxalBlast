## 0. 方向结论（一句话 + 四条硬规则）

**一座摆在田园草坡上的木质玩具：木头是物体，彩色是唯一的高饱和。**

1. **木材 = 物体**。棋盘外壳、面内格槽、所有可点控件、弹窗面板、候选卡托盘，全部是同一套木纹与同一套「下沿加厚」的厚度语言。
2. **彩色 = 内容**。画面上只有「已放置方块」和「落点/道具预览」允许高饱和；其余一律落在木色—奶油纸色区间。
3. **背景 = 布景**。田园风景永远在棋盘之后、永远是柔和低对比的，且**不接收任何指针事件**。
4. **一切"体积"必须能写成一个数**。立方体上只有两个厚度：面片 `0.10`（出挑 `+0.04`）与落点薄片 `0.06`。**已放置的方块不增加任何厚度**——它只是被刷上漆的面片。评审时说不出某处厚度对应哪个数值，判为不可验收。

## 1. 资产边界（未变，仍然强制）

运行时画面**全部由代码生成**：参数化几何、CSS、代码生成内联 SVG、Canvas 动态纹理、Shader。⛔ 不依赖外部 PNG/JPG/WebP/SVG 文件、视频背景、预制粒子图集、GLTF/FBX/OBJ 或第三方素材包。

本版新增的两块资产都守这条线：

| 资产 | 实现 | 文件 |
| --- | --- | --- |
| 木纹（3D 与 UI 同一套） | Canvas 逐像素绘制 → `THREE.CanvasTexture`（3D）/ `toDataURL()` 注入 CSS 变量 `--wood-grain`（UI） | `src/rendering/woodTexture.js` |
| 田园背景 | 启动时拼出的内联 SVG（天空/云/远山/村庄/石桥/河流/树木/栅栏/花草），`preserveAspectRatio="xMidYMid slice"`，viewBox 1440×1000 | `src/rendering/pastoralBackdrop.js` |

两张画布都用**固定种子的确定性随机**（`mulberry32`）：同一次构建每次加载的木纹与花丛位置必须完全一致，否则同一版的两张截图无法比对。

## 2. 棋盘几何与表面层级（本版的核心修正）

v0.5 的层级是**倒挂**的：面片（25 个/面，0.9×0.9×0.78）沿法线外移 0.36 → 实际凸出壳面 0.29，而方块只凸 0.24。结果是深色格槽成了体积主体、彩色方块沦为贴片，且棱线呈锯齿。

v0.7 的规则：**面要平、块要齐、缝要深；六面 150 块永远同尺寸，占用只换颜色。**

基准面 = 壳体表面（立方体边长 5，壳 `RoundedBoxGeometry(4.92, 圆角 0.18)`，六面平面位于 ±2.46，晶格格心到该面平面恒为 `cs/2 = 0.5`）。`main.js` 里由 `FACE_GAP / TILE_CENTER / PLATE_CENTER` 三个常量集中表达，不允许出现第四个随手写的偏移量。

| 元素 | 面内尺寸 | 圆角 | 厚度 | 相对面平面 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 壳体 hull | 4.92³ | 0.18 | — | 0（基准面） | **比面片深**：露出它的地方就是块与块之间的凹槽 |
| 块（空格） | 0.91 × 0.91 | 0.09 | 0.30 | **+0.13** | 天然木色，`tileToneSteps` 逐块微差 |
| 块（已放） | 0.91 × 0.91 | 0.09 | 0.30 | **+0.13** | **几何完全相同，只把材质换成漆色** |
| 落点预览 preview | 0.91 × 0.91 | 0.04 | 0.06 | **+0.17** | 薄片，跟手；不是半透明线框立方体 |

- 块间隙 = 1.0 − 0.91 = 0.09 格，缝隙里露出**更深的壳体木色** —— 这就是六面体的凹槽，不需要靠立体感去表达。
- **块厚 0.30 里有 0.17 埋在壳体里**：`RoundedBoxGeometry` 的圆角半径会被几何钳到"厚度的一半"以内，面片太薄时圆角被压成 0.03、读起来是平板。厚度是买"圆润块感"的成本，可见高度只有 0.13。
- **已放置的方块不改变任何几何**：不抬高、不加厚、不换形状。放置 = 把一块的材质从「原木」换成「漆」。
- 出挑基准恒为**所属面的法线**，一次只沿一个轴。

### 2.1 棱格与角格：该格的所有面片一起变色

棱格被两个面共享、角格被三个面共享。因为面片是**按面**排列的，同一个晶格格子在每个能看见它的面上都有自己的面片；占用时**逐面片按晶格坐标查色**，所以棱格/角格会自然形成"包住棱/角"的同色块，既不需要挑一个面，也不会横向跳位，更不会从立方体底部挂出来。

> 演进记录（两版都试错掉了，别再走回去）：
> - v0.5「单轴优先 Z」——棱/角格朝相机横向跳位。
> - v0.7.0「每个暴露面各出一片 0.30 厚 chip」——几何没错但看起来错：正面下沿的角格会同时在底面长出一片，方块从立方体底部挂出来；且在掠射面上读作"贴上去"而不是"放上去"。
> - **v0.7.1（现行）**：取消 chip，占用即变色。

## 4. 材质与光照

- **一种木纹贯穿全场**：`woodGrainTextureRepeating()` 产出的是一张「接近白色的浅灰纹理」，作为 `map` 与材质 `color` 相乘。所以同一张图同时给天然木壳、原木块和十种漆色块、以及手上拿着的方块上纹——**这就是棋盘与 UI 读起来是同一种材料的原因**（05「同源」）。壳体 tile 数 2.2，块与方块 0.5。
- **每个原木块有自己的色调**：`main.js#toneIndexFor()` 用晶格坐标做确定性哈希，从 `tileToneSteps` 六档里取一档。一块全同色的立方体读起来是"一体成型的木箱"，参考图里是"一块块拼起来的木头"。哈希必须确定性（同一次构建每次加载完全一致），否则同一版的两张截图无法比对。
- 漆面材质 `MeshPhysicalMaterial`：`roughness 0.34` + `clearcoat 0.55 / clearcoatRoughness 0.22` = 一层真清漆；木块 `MeshStandardMaterial` 哑光 `roughness 0.72`。落点上的块与手上拿着的方块**共用同一套漆面参数**，所以一个方块从候选槽 → 拖拽 → 落到盘上，材质全程不变。
- 壳体材质：`MeshPhysicalMaterial`，`roughness 0.7` + `clearcoat 0.1` = 擦过蜡的深色原木。
- 光照（`toyLights.js`）：`HemisphereLight(0xFFF6E4, 0x6F8F4A, 1.35)`（上方日光金、下方草地绿反弹）+ 主光 `DirectionalLight(0xFFF0CF, 3.2)` 位于**左上**（必须与背景 SVG 的太阳辉光同向）+ 天空冷补光 + 暖柔光箱。
- 阴影：主光投影，壳体/槽面/方块接收；低性能档 1024、高档 2048。
- 禁用：玻璃/霓虹/发光图层、随机高光、逐块不同光向、过量后处理辉光。

## 5. 背景（田园布景）

`installPastoralBackdrop(#app)` 在启动时把 `.pastoral-backdrop` 插为 `#app` 的第一个子元素。

> ⚠️ **绘制顺序陷阱（本版踩过）**：`z-index:-1` 的层画在根层叠上下文的第 2 步，而 **`body` 自己的背景画在第 3 步——在它之上**。所以天空渐变必须挂在 `html`（传播到画布，最底层），`body` 必须是 `transparent`，否则整张田园风景会被一层纯色渐变静默盖住。`src/toy.css` 末尾的「Backdrop paint order」段即为此。

- 层序（后→前）：天空渐变 → 太阳辉光 → 云 → 远山 → 中景丘陵 → 村庄（含教堂尖顶） → 河流与石桥 → 树线 → 草坡 → 木栅栏 → 左上角大树 → 草簇与雏菊 → 地平线雾气 + 暗角。
- 取景：`viewBox 1440×1000` + `xMidYMid slice`。桌面裁上下、手机取中间约 35% 宽度——**因此草地、丘陵、河流必须横向通铺**，村庄居中而非塞在角落。
- 交互：`pointer-events: none` + `aria-hidden`，永不接收事件、不可聚焦。
- 对比度约束：布景整体低对比，画面最亮最饱和的永远是立方体。

| 候选卡 `.piece-slot` | 奶油纸内嵌（`--cream-1..3`）+ 内阴影 + `border-bottom 5px solid --wood-4` |
| 状态提示 / toast | 奶油纸标签 + 木边 |
| 弹窗 / 设置行 | 奶油纸面板 + 木纹底 + `border-bottom 8px solid --wood-4` |

## 7. 反 AI 制作约束

1. 先写清用途/尺寸/状态/明暗方向，再谈表现。
2. 用可复用基础几何 + 明确比例，同类资产只做少量有意变体。
3. 光源、透视、圆角半径、线宽、阴影软硬度全项目统一；发现多套光照优先返工。
4. 禁随机细节填充：随机划痕、随机高光/装饰/渐变、无意义字母、乱码。
5. 生成式素材只能当草稿，须重建为可编辑的矢量/CSS/Shader/低复杂度模型并人工检查。
6. UI 文案、图标、数值一律用明确设计稿。
7. 新资产过「缩小到实际游戏尺寸」和「灰度模式」两道检查。
8. **一切「体积」必须能写成一个数**（见 §0.4）。
