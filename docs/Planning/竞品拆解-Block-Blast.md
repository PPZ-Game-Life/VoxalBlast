# Block Blast 拆解：哪些能抄、哪些抄了会死

> 来源：Balancy 博客，2025-03-26，[How could Block Blast by Hungry Studio earn more? Monetization and gameplay deconstruction](https://balancy.co/blog/2025/03/26/how-could-block-blast-by-hungry-studio-earn-more-monetization-and-gameplay-deconstruction/)，作者 Michael Khripin（Balancy 产品负责人）。
> 抓取的正文纯文本存 `artifacts/balancy-block-blast.txt`（临时产物，不入库）；本页只保留对我们有决策价值的结论。

## 0. 一句话结论

这篇文章卖的是"Block Blast 还能怎么多赚"，但它真正值钱的是最后一段：**他们做了 3000+ 次 A/B 实验，成功率 3%**。文中那 5 条变现建议，以我们现在的阶段**一条都不该直接抄**——不是建议不对，是我们的收入管道和平台考核指标跟他们不是一套。抄错地方比不抄更贵。

## 1. 原文事实（去情绪，只留可核对的）

**变现结构**

- 底部静态 banner；每局结束插屏（短、可跳过）；激励视频**只用在复活**，每局限一次。
- **没有 IAP**：没有商店、没有体力/生命、没有"去广告"购买。想玩多久玩多久。

**参与与留存机制**

- 无限对局：强化了广告观看，代价是没有紧迫感。
- 连胜（win-streak）：**只显示计数**，里程碑无奖励、断连无惩罚。
- 连败多次触发 "God Mode"：发理想块，保证推进——作者自己的评价是"制造了 wow 效果，但让输赢变得无所谓"（meditative, not challenging）。
- 硬关通关后显示"你超过了 X% 的玩家"。
- 索评：先用自建弹窗过滤差评，只对好评跳商店。
- 要了推送权限，但不发通知。

**LiveOps**

- 全部内容 = 一个 7 天的 Adventure 模式（96 关逐格解锁一张像素图），**没有奖励承诺、没有收藏系统**。

**作者给的 5 条建议**：Undo 挂激励视频 / 高价 No Ads IAP / 连胜加奖励 / 优化推送 / Adventure 加奖励与图鉴。

## 2. 结构性差异（为什么不能照抄）

| 维度 | Block Blast | VoxalBlast |
| --- | --- | --- |
| 载体 | 移动 App（App Store / Google Play） | CrazyGames Web |
| 收入模型 | 纯广告：人均时长 × 插屏次数 = 钱 | Basic Launch 期间**无变现**（SDK 可选），Full Launch 才走平台广告分成 |
| 平台考核 | 商店排名、评分、下载量 | D1 留存、平均时长、玩法转化（上次实测 D1 1.59% / 2m28s / 45.68%） |
| 再召回通道 | 推送 + 桌面图标 + 商店更新 | **几乎没有**：没有推送、没有图标，只有平台推荐位和站外私域 |
| 对局压力设计 | 刻意做成"输赢无所谓，一直玩" | 需要通过 D1 验证"值得回来" |

**结论**：Block Blast 的"无压力设计"是它**变现模型的产物**，不是它成功的原因——它靠"一直玩、一直看插屏"收钱，所以刻意把输赢抹平。我们的钱和平台的推荐权重都挂在"第二天还回来"上。**把它的无压力照搬到我们这里，等于把病根当药方**：我们上次 2m28s 的时长，恰恰就是"没有理由留下"的表现。

## 3. 能抄的三条（低成本、直指 D1）

1. **局末给一个具体数字。** 它的"你超过了 X% 玩家"是纯心理回报、成本几乎为零。我们有本地纪录（[08 荣誉与排行榜](08-荣誉与排行榜系统.md)），但**percentile 必须有真实分布才有意义**——没接 CrazyGames SDK Leaderboards 之前只显示"本机最佳 ± 差值"，不许自己编百分比。接上 SDK 拿到真实分布后再上。
2. **把连胜从装饰变成钩子。** 作者自己把"连胜无奖励"列为他们的机会点。连胜 + 连续天数（daily streak）+ 每日挑战，是 Web 平台上少见的、不依赖推送的"第二天回来的理由"——这正好补我们最缺的那一环。
3. **一局失败不是终点。** 我们要的不是它的 God Mode（保证不输），而是"再来一局 + 一局内的第二次机会"（我们已有 4 种道具的基础）。区别很清楚：**它让输赢不重要，我们要让"下一局更好"。**
   前置条件：先修可能性。[紧张度测量](Technical/DIFFICULTY_TENSION.md) 已经测出现在三块全可放的概率是 100%，"快撑不住但还能救"的中间段几乎不存在——连差点死掉的紧张感都没有，复活机制没有存在的土壤。

## 4. 不抄的三条

- **索评前置过滤**：不做。CrazyGames 没有应用商店评分这套，而且这是灰色手段，收益不该进我们的账。
- **Undo 挂激励视频 / No Ads IAP**：现阶段不做。Basic Launch 期间本来没有变现入口，给不存在的收入打地基是最典型的错位投入。
- **推送权限**：Web 平台没有这条路。**承认这一点**：我们的再召回只能在游戏内部解决（每日挑战、streak、进度卡点）+ 站外私域，这反过来把"游戏内理由"的重要性顶到了第一位。

## 5. 真正该抄的只有一件事：实验机制

3000+ 次实验、3% 成功率，翻译过来是：**"想出一个好点子然后赌它能成"这个思路本身就是错的**，赢家是从上百次小实验里筛出来的，不是策划会上想出来的。

我们的现状是偏科的：

- **规则侧测量很齐**——`reachability`、`difficulty-*`、紧张度面板，旋钮扫了好几轮，每个结论都有数字。
- **行为侧几乎空白**——首局时长、重开率、局数分布、局内放弃点、道具使用率，一个都没有。没有行为指标，任何留存改动都是赌注，赌完还不知道输在哪。

最低可行版本（不引入平台外工具）：本地埋点 + 一个 `tools/` 读取脚本；平台侧能拿到的就是开发者后台的 D1、平均时长、玩法转化三项。

**内部门槛先定死**（是我们的验收线，不是 CrazyGames 官方 benchmark，官方阈值按品类与时间窗变化，只能从后台确认）：D1 从 1.59% 提到 **8%**、平均时长从 2m28s 提到 **5 分钟以上**、玩法转化不低于 **45.68%**。

## 6. 下一步

- [ ] 行为埋点最小集：首局时长、每局步数、重开率、道具使用、局终原因。
- [ ] 连胜 / 连续天数 + 每日挑战的最小设计（挂 08 荣誉系统）。
- [ ] 结局面板加"本机最佳 ± 差值"（不编 percentile），接 SDK 排行榜后再上真实分布。
- [ ] 复活 / 第二次机会的候选方案，与"压力曲线修复"一起评审，不单独上。
