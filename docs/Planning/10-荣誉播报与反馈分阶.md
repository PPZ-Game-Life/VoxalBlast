# VoxalBlast 荣誉播报与反馈分阶

> **文档状态：设计提案 v1.0，尚未实现。** C 路（本轮表现层改进）为定案待实施；B 路（等级即荣誉）为**目标态，未排期**。
> 实现基线：当前工作区 **v0.9.17**，静态核对 `src/game/honors.js`、`src/rendering/config.js`、`src/ui/hud.js`、`src/ui/gameOver.js`、`src/main.js`、`src/styles.css` 与 `src/i18n/locales/{zh-Hans,en}.js`。

> **本文件的编号 10 与 Archive 里的历史稿 `Archive/Planning/10-荣誉与排行榜开发交接单.md` 无关**；那份是旧交接单，不是本提案的前置。

## 0. 结论

用户提出两个问题，均已定位到具体代码位置：

1. **荣誉太多、不好理解** —— 不是数量问题，是「**一把尺子量了四次**」。`honors.js` 的注释自己写着：*"Honors are SIZE MILESTONES, not event types."* 里程碑本该是一条阶梯，现在却是四张奖状（≥3/4/5/6 线各一个名字），且局内一次性全部弹出。
2. **展示反馈很弱、没有分阶** —— 5 档里 **L1 完全静音**（无横幅无徽章），其余档位之间只差「粒子加量」（`particleScale 1→5`、`shake 0.055→0.26`、横幅字号变大）。**没有任何一档有名字**，玩家无法用一句话说出「我刚打出了第几档」。

**路子**：C 路先行——规则层一行不动，只改表现层，让分阶立刻可见；B 路为目标态，C 路把 B 路需要的 UI 载体（档位名 + 五格刻度）预先备好，B 落地时表现层不必再改第二次。

## 1. 现行基线（静态核对，非本轮实测）

### 1.1 荣誉名册（`src/game/honors.js`，6 枚）

| ID | 条件 | 奖金 | priority | broadcast |
| --- | --- | ---: | ---: | --- |
| TRIPLE | ≥3 线 | 150 | 10 | true |
| TRIFACE | ≥3 面 | 600 | 25 | true |
| QUAD | ≥4 线 | 500 | 30 | true |
| PENTA | ≥5 线 | 1500 | 40 | true |
| HEXA | ≥6 线 | 4000 | 50 | true |
| PERFECT_TWELVE | ≥12 线 | 20000 | 90 | **false** |

阈值为**累计触发**：一次 6 线落子同时命中 TRIPLE + QUAD + PENTA + HEXA，四笔奖金相加（与 08 §3 一致）。这是「荣誉太多」的直接来源。

### 1.2 反馈等级（`FEEDBACK_STYLE.levels`）

| 档 | 触发 | duration | shake | particleScale | 横幅 | badges |
| --- | --- | ---: | ---: | ---: | --- | --- |
| L0 | 0 线 | 0 | 0 | 0 | none | false |
| L1 | 1 线 | 0.35 | 0.055 | 1 | **none** | false |
| L2 | 2 线 | 0.6 | 0.09 | 1.6 | small | true |
| L3 | ≥3 线 | 0.9 | 0.14 | 2.4 | name | true |
| L4 | ≥4 线，或 ≥3 面 | 1.4 | 0.2 | 3.5 | large | true |
| L5 | ≥5 线，或「≥4 线且 ≥3 面」 | 2.2 | 0.26 | 5 | full | true（唯一带慢放 0.6×/400ms） |

`honorBannerMs` = small 700 / name 900 / large 1400 / full 2200（ms）。横幅样式只有 4 个变体（`honor-banner-small/name/large/full`），**L1 没有对应变体**。

### 1.3 三处调用点

- `src/main.js` 落子结算：`showScorePop(...)` → `showHonorBanner(honors, level)` → `spawnClearEffects(lines, level)`（同一手连调三次）。
- `src/ui/hud.js` `showScorePop()`：分数跳字里额外带一行荣誉名（`score-pop-honor`），与紧随其后的主横幅**显示同一枚荣誉**。
- `src/ui/hud.js` `showHonorBanner()`：主横幅（`primary`）+ 一行小徽章（`secondary.concat(records)`，渲染为 `.honor-badges` / `.honor-badge`）。

## 2. C 路改动清单（规则层零改动）

| # | 改动 | 定位 | 理由 |
| --- | --- | --- | --- |
| **C1** | 删除局内徽章行 | `src/ui/hud.js` `showHonorBanner()` 中 `extras` / `.honor-badges` 一段 | 「荣誉太多」的肇事者：一手 6 线弹 4 个徽章。同手只留一个主事件 |
| **C2** | 去掉同一枚荣誉的第二次露面 | `src/ui/hud.js` `showScorePop()` 的 `score-pop-honor` 行 | 同手横幅与跳字重复同一信息，玩家读到两遍、记住零遍。竖屏保留横幅（大字+刻度），跳字只留 `+分数 / N LINES / M FACES` |
| **C3** | 给 L1 反馈 | L1 现在 `banner:'none'`、`badges:false`，只有粒子 | 5 档里最静音的一档，「消 1 线」与「没消」几乎同感。按 09 FX-09 不放大横幅，只给线带确认 + 一次刻度闪 |
| **C4** | 五格刻度 pip | 新增（DOM/CSS，无新 3D 资源） | 把 L0–L5 从内部变量变成玩家可见的进度：主横幅角落一排 5 格菱形，点亮数 = 当前档 |
| **C5** | 档位语言进 i18n | 新增 `feedback.1.name` … `feedback.5.name` | 给 B 路预留同一套词条，B 落地时不必二次改文案 |

**明确不动**：`honors.js`（名册 / 奖金 / priority）、`scoring.js`、`feedbackLevel()` 判定条件、`particleScale` / `shake` 曲线、存档协议、结算流程、平台层。

### 2.1 实现要点（决定实现成败的细节）

- **`.honor-badge` 的 CSS 不能删**：结算页 `.game-over-honors` 仍在用它（`index.html` 的 `#game-over-honors` + `src/ui/gameOver.js`）。C1 只删 `hud.js` 里的局内渲染段。
- **`FEEDBACK_STYLE.levels[].badges` 字段随之退役**：它只被 `showHonorBanner()` 读取；若保留，必须标注为废弃，避免后来者以为局内仍有徽章路径。
- **结算页无需新增载体**：`src/ui/gameOver.js` 已按 `run.honorCounts` 全量列出（`t('honor.ID.title') ×次数`，按次数降序），空态文案 `gameover.noHonors` 已存在。C1 的补偿是现成的。
- **pip 不新增粒子预算**：纯 DOM/CSS，受 09 §9「新增后处理 Pass = 0」约束。`prefers-reduced-motion` 下刻度必须**静态可见**（它是必要信息，不是装饰）。
- **刻度只有 5 格**：≥5 线一律满格。六线（HEXA）、十二线（PERFECT_TWELVE）的额外性由结算页徽章与奖金表达，**不再用「多一个名字」表达大小**——这正是对问题 1 的正面回答。

## 4. 待拍板的决策点（不拍板不能开工）

**D1 —— 档位名与真实触发可能名实不符（本提案新发现）。**
L4 的触发是「≥4 线 **或** ≥3 面」。若档位名固定为「破面」，那么一次**只在单面上消掉 4 线**的落子也会显示「破面」——没有破面却叫破面。三个选项：

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| **D1-a（推荐）** | 档位名固定，横幅副行固定显示真实的 `N LINES / M FACES` | 需要横幅副行让位给数据，奖金信息移到刻度行 |
| D1-b | 档位名随触发变化（4 线→「四连爆」/ 3 面→「破面」） | 名字回到 6 个，等于把问题 1 请回来 |
| D1-c | 档位名固定为中性词（如「贯击」），放弃「破面」这个更有画面感的名字 | 损失一个记忆点 |

**D2 —— 中文界面里最大的字是英文。**
主横幅大字取 `t('honor.ID.title')`（`TRIPLE` / `QUAD`…），小字才是中文 `label`（`三连爆 · +150`）；结算页徽章也全用 `.title`。中文玩家看到的**主视觉是外语**。是否本轮一并改成「大字 = 中文档位名 / 小字 = 英文名 + 奖金」？涉及 `src/i18n/locales/*.js`，改动量极小，但会同时改变结算页观感。

**D3 —— PERFECT_TWELVE 局内彻底静默，等于关闭 08 §10 待决策 5。**
它现在靠徽章行在局内露面（`records` 并入 `extras`）。C1 之后 = 局内静默、奖金照付、只进结算页与纪录墙。这是**顺手关掉一条待决策**，需要在 08 文档记一行。

## 5. 副作用与补偿（不能只做减法）

**「一手四枚荣誉」的局内爽感会消失。** 补偿必须**同时**上，否则这一轮是纯削弱：

1. pip 一次跳到第 5 格（视觉上「顶格」比四个徽章更有冲击力）；
2. 结算页把四枚一次性列全（已有能力，不需要新代码）。

## 7. B 路目标态（未排期，只记方向）

**等级即荣誉**：废弃与 L0–L5 并行的独立荣誉名册，把五档升格为唯一语言——每档一个名字、一种视觉签名、一笔挂在档上的奖金；跨面不再单独发徽章，只作为档位内的加成记号。

- 收益：玩家只需要背 5 个词，而不是 6 个 ID + 5 个内部等级。
- 代价：`honors.js` 结构改写；08 的 `share` 频率表（按 6 枚实测）与 `tools/reachability-baseline.json` 的 `honorOccurrencesPerGame` / `honorGamesPct` 全部需要重测。
- **时机判断**：`TIER_CUTS` 至今全为 `null`、一次都没标定。荣誉改动会改奖金总和 → 改分数分布 → 改阶位切点。**趁未标定动手最便宜**，再拖就要连标定一起返工。
- **C 路不浪费**：C4 的 pip 与 C5 的档位词条就是 B 路需要的 UI 载体，B 落地时表现层不必再改第二次。
