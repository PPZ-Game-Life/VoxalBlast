# VoxalBlast 世界观规划：方块乐园

> 状态：**新世界观提案，待确认；不是已批准美术基线或已实现功能。**
> 用户边界：参考图片只借画风；核心考虑 VoxalBlast 的玩法；主题须通俗，不依赖新造名词。
> 实现依据：v0.12.0。本文规划世界观及其表现，不修改游戏规则、交互、计分、存档或平台系统，不升级版本。
> 游戏品牌仍为 **VoxalBlast**；“方块乐园”是内部世界观方向名，不是本轮改名决定。旧灯会方案停止推进，见 [11 历史提案](11-林间灯会美术与世界观提案.md)。

## 1. 一句话设定

**一座用积木搭成的微缩乐园，最受欢迎的挑战是一件六个面都能拼的大方块玩具。玩家转动它、拼满行列，在有限空间里不断刷新自己的纪录。**

玩家无需理解角色身世、能量来源、元素属性或文明危机。进入画面就能认出三件事：这是玩具，这是拼块挑战，自己可以动手玩。

世界观负责解释“在什么地方、做什么、为什么愿意再玩”，不为每次消除发明一套物理原理。

## 2. 世界的故事与气质

### 2.1 给制作团队的短故事

在方块乐园，长条、方块和转角块能搭成拱门、台阶、长凳，也能组合成各式各样的玩具。这里最受欢迎的活动不是比谁堆得最高，而是比谁更会利用空间。

广场中央摆着一件特别的六面拼图玩具。它能朝不同方向转动，每一面都可以拼；看似挤满的一面，换个方向就可能出现新的机会。填满的行列会被玩具收起，留出位置让挑战继续。有人喜欢稳稳地一排排消除，有人喜欢提前安排，在几个面同时完成漂亮的一手。

玩家来到这里，不是拯救世界，也不是修复一片废墟，而是挑战这件玩具：**再看一面，再多想一步，这局能不能比上局更好？**

这段故事供设计对齐，不做强制开场旁白，也不需要居民角色立绘才能成立。

### 2.2 气质

- **熟悉**：积木、托盘、计分牌、奖杯，都是一眼能认出的东西。
- **聪明而轻松**：乐趣来自发现空间关系，不是完成劳动订单或应付倒计时。
- **可反复尝试**：一局结束只是一次挑战结束；没有世界被毁、生命损失或队友失望。
- **有手感但不写实**：像拿在手中的玩具，轮廓扎实，材料简化，动作清脆。
- **游戏本身是主角**：没有宠物陪养、英雄身份、阵营设定或常驻剧情角色。

## 3. 玩家是谁，要做什么

**身份：来参加拼块挑战的玩家。** 不设置学徒、灯匠、训练家等额外身份门槛，不需要姓名、头像或角色创建。

| 层级 | 玩家目标 | 游戏已有的承载方式 |
| --- | --- | --- |
| 眼前 | 找到这块能放的位置 | 观察形状、空位、合法落点与翻面 |
| 一手 | 放下后腾出更多空间 | 满行／满列消除、共享棱角 |
| 一局 | 尽可能继续、取得更高分 | 当前分数、连续消除、多消与有限救场 |
| 多局 | 看懂更多空间关系，超过自己 | 最佳纪录与本地历史成绩 |

**技巧成长是主要成长线，不新增等级经验。** 世界观中的“挑战”不等于新关卡系统；现有无倒计时的单局模式保持不变。全球榜在真实数据接入前仍须明确标注示例数据，不能用虚构的“乐园居民成绩”掩盖占位数据。

## 4. 世界里最重要的物件：六面拼块台

“六面拼块台”只用于团队描述及必要的操作说明。玩家界面仍可直接称“棋盘”或“大方块”，不强制引入专名。

### 4.1 为什么是六面体

它是一件**所有面都能玩的立体拼图玩具**，不是房屋、宝箱、星球或容器。这些物件容易暗示固定屋顶、可打开的内部或重力方向，与当前玩法不合。

- 转动的是整件玩具，不是魔方那样拧动单独的一层。
- 玩家只在表面拼，不向内部塞块。
- 已放的拼块固定在表面，翻面不会掉落。
- 六面共用棱角，不是六块棋盘拼成一个外观。
- 没有一面是“永远朝上的顶面”，也没有机关正面或背面。

### 4.2 为什么消除后还能继续拼

这是可反复挑战的玩具：**填满一行或一列，拼块被收起，空位重新可用。** 玩家只需知道游戏规则，不必理解材料如何回收。

美术上，格块承载结构始终完整；消除是彩色占用状态解除，不是拆掉墙体、凿穿外壳或让剩余块坍塌。不能为了叙事制作传送带、滑槽、开盖或穿进内部的动画，导致新增结构和等待时间。

### 4.3 为什么要看别的面

世界观的核心句是：**“换一面，也许就有新办法。”**

它来自共享格和多面空间规划，而不是剧情赋予的特殊能力。操作说明可以用一个真实棱角案例表达：同一格在相邻面上都占位，移除后两侧同时腾空；不是偷偷增加一枚方块或给予两份奖励。

## 5. 规则如何变成玩家看得懂的表现

| 现行机制 | 世界内的直观理解 | 表现边界 |
| --- | --- | --- |
| 5×5×5 外壳，98 个唯一格，每面 5×5 | 一件完整的六面拼图玩具 | 不做 125 格内部填充；不把 150 个表面位置画成独立实体 |
| 开局全空 | 新一轮挑战准备好了 | 不预摆彩色块作装饰，不增加中心目标格 |
| 三个候选，十五类形状 | 托盘送来当前可用的三组积木 | 形状与现有发牌保持一致，不暗示可挑选购买 |
| 候选朝向固定，转动棋盘寻找空间 | 积木就按手中的形状拼，换面找位置 | 不新增候选旋转按钮；不画暗示可旋转的把手 |
| 不限颜色，填满行或列消除 | 排满就收起 | 无同色、属性克制、电路连接或斜线消除暗示 |
| 正常落子也有基础分 | 每次成功拼放都计成绩 | 普通得分不演成消线，不伪造连击 |
| 同批多面命中 | 一手安排让几处同时腾空 | 只展示真实命中；不强制转镜头或虚构跨面奖金 |
| 道具清理 | 一次有限的整理机会 | 不计分、不改连击，不播得分奖励 |
| 卡住但仍有道具 | 还可以试试整理空间 | 不提前结算，也不保证任何道具一定能救活 |
| 最终结束 | 这一轮挑战告一段落 | 成绩单和再来一局，不演灾难、毁坏或角色受伤 |

计分以当前结算事件为唯一依据。v2 中满棱按同一物理线去重计分；净面只认符合条件的落子面，一手最多一个；不恢复旧跨面奖金。旧局使用旧分制时也消费该局真实结算，不在美术层重算。

## 6. 场所规划：一个世界，先只做一个可玩场景

### 6.1 首期唯一场所：方块广场

它不是森林营地的换名，而是一块为拼图挑战布置的微缩活动场：

- **中心**：六面棋盘，占据注意力中心。棋盘后方用低对比纯色或大色块，让边缘和空位清楚。
- **近处**：三个候选托位与现有四道具。统一成一套玩具配件，不画复杂容器吞掉候选面积。
- **外围**：少量由长条、L 形、转角、方块搭出的台阶、矮墙和拱门。玩家刚拿过的形状，也能在世界造型中看到。
- **远处**：少量低细节、低饱和的几何轮廓。不要求树木、动物、营地建筑或特定自然地貌。
- **计分区域**：比赛记分牌式的清晰界面；SCORE、BEST 仍是事实信息，不换成金币、贡献值或乐园建设进度。

不设置可点击的场景建筑或地图入口。建筑只是布景，不能看起来像玩家尚未解锁的功能按钮。

### 6.2 “世界由方块构成”不是满屏小格子

背景用大的模块组合和剪影表达积木感，不把地面、天空、山体全切成与棋盘同尺寸的小格。否则全屏都会像可操作网格，棋盘反而失去识别。

棋盘是唯一具有明确 5×5 操作秩序的主体；其他物件不伪装成第二块棋盘。

### 6.3 后续场景只预留美术变化

以下是未来可能的场景皮肤，不是地图、关卡或本轮资源任务：

| 场所 | 视觉变化 | 必须保持的东西 |
| --- | --- | --- |
| 方块广场 | 奶油色台阶、低饱和青绿环境、彩色活动牌 | 初始核心棋盘与交互 |
| 拼搭工坊 | 少量配件架、结构图、玩具工具 | 不变成制造订单，不加生产进度 |
| 方块展厅 | 简洁展台、形状雕塑、记录展示氛围 | 不增加藏品货币或解锁条件 |

首期只推进方块广场。不绘制“六个面分别是六个世界”：那会破坏统一空位识别、共享棱角和翻面后的理解。

## 7. 画风如何落在这个世界

参考图只借**粗深色轮廓、手绘色块、简化阴影、圆钝造型和清楚的层级**。不继承宠物、战斗、森林、营地、糖果机、抽卡、星级或属性系统，也不复制角色与资产。

### 7.1 棋盘仍是真 3D，观感接近手绘卡通

- 外轮廓比内部格缝更强，不给每格描同样粗的黑边。
- 大面保持平整，靠小倒角和统一明暗体现厚度；不要圆鼓、透明、晶体或湿亮塑料感。
- 空格浅色、低饱和；占用鲜明、轮廓完整。候选、拖拽、已放状态来自同一套造型。
- 放置不改变已有格块的高度、位置或大小；共享棱角连续包色。
- 不给六个面分别上六种常驻底色，避免让玩家联想到魔方复原或颜色配对。
- 不在块上画表情、文字或固定朝上的花纹；旋转后仍然自然、可读。

### 7.2 色彩职责（打样建议，非已测材质参数）

| 用途 | 建议色 | 限制 |
| --- | --- | --- |
| 主轮廓 | `#28333F` 深蓝灰 | 不全屏纯黑重描边 |
| 空格 | `#E6E1CF` 浅暖灰 | 所有受光面均须与占用色可分 |
| 环境底色 | `#AFC9BC` 灰青绿 | 只是中性承托，不代表森林题材 |
| UI 纸面 | `#FFF3D9` 奶油白 | 承托真实 DOM 文案和数值 |
| 次要控件 | `#606A94` 灰紫蓝 | 弱于候选和棋盘 |
| 庆祝强调 | `#FFD166` 暖黄 | 用于成功瞬间，不常驻盖住格线 |

占用块的十五形状配色另做专门样板，不用本表替代现行色表。世界观不要求改颜色存档；若后续调色，必须覆盖旧 RGB 存档和候选预览，不改变形状池或发牌分布。

### 7.3 UI、动效与声音

- UI 是同一套厚轮廓玩具牌，图标清楚，数字仍为 DOM。通用功能名保留，不用主题术语替换“换批、行、列、重新开始”。
- 锤子是玩具整理锤，火箭是礼花式外观，炸弹是圆胖的玩具爆破工具；换批使用循环箭头和托盘。名字和预览先说明功能。
- 火箭的行／列选择、炸弹的 2×2 范围、单格目标与撤销入口必须准确；不画圆形大爆炸误导作用范围。
- 消除顺序：真实命中行列可见 → 占用解除／空位恢复 → 少量方形碎片或彩纸庆祝。效果不改逻辑结算和输入节奏。
- 道具没有得分庆祝；一次多消、连续消除、净面按实际事件分层，不另设“狂欢能量”。
- 声音方向为轻卡入、清脆消线、短促庆祝，不用武器轰鸣或魔法吟唱。减动画模式仍能读懂命中和结果。

## 8. 不让世界观反过来伤害玩法

以下是硬边界，不因概念图更漂亮而让步：

1. 相机、停靠与左右微调沿用玩法要求；不为展示三个面强改镜头。
2. 不在棋盘上增加固定朝上的屋顶、烟囱、挂件、台脚、锁孔或夹紧支架。
3. 环境底座若存在，须远离旋转扫掠范围和向下拖块翻面通道；无法兼容就删装饰，不挪手势门槛。
4. 背景不接收指针；保留候选和道具取消区、拖块翻面的轮廓判定与进场闩锁。
5. 继续“加载即进单局”；没有强制欢迎剧情、角色选择、乐园地图或入场动画。
6. 分数不是可消费资源；没有能量、燃料、门票、体力、金币或建设进度条。
7. 没有敌人、守护核心、倒计时、生存威胁或玩家未授权的战斗玩法。
8. 不承诺关卡、每日挑战、角色养成或皮肤解锁；这些是独立产品决策，不是世界观默认能力。

## 9. 面向玩家的叙事与文案

世界观主要让玩家“看见”，而不是“读完”。最多用一句场景说明或商店介绍，不把章节故事塞进局内。

- **对外介绍草案**：欢迎来到方块乐园。转动六面棋盘，拼满行列，让每一次消除为下一步腾出空间。
- **核心短句草案**：换一面，发现新空间。
- **规则说明**：填满一行或一列即可消除，不要求同色。
- **成绩与结算**：本局得分、最佳纪录、再来一局，保留通用语义。

短句不默认新增为常驻提示；不能在卡住时无条件说“换面就能放”，全局确实无落点时仍使用现有救场提示。后续所有可见文案走 i18n，英文默认、简体中文同步。

## 10. 首期制作范围与评审

### 10.1 首期范围

**一套棋盘与候选样式、一套方块广场布景、一套 UI／道具视觉，以及匹配的消除反馈方向。** 不需要角色、营地建筑、地图、怪物、任务表或长剧情。

先做方向稿，不直接替换全部资源：

1. **一张真实竖屏局内图**：用现有盘面、相机和 HUD 布局作骨架，证明棋盘是主角。
2. **一页四状态／共享角对照**：空位、占用、合法预览、无效预览；同一共享角翻面前后。
3. **一页消除分镜**：普通落子、正常满线、多面同时命中、道具清理的反馈区别。
4. 桌面与短横屏复核：只调整布景裁切，不把竖屏画面拉伸或挤压操作区。

本轮仅写规划，不生成上述图片，不改运行时资源。实施仍按 [视觉重做流程](../Technical/VISUAL_REWORK_WORKFLOW.md) 分轮进行；05 原规范在新方向确认与样稿验收前不被静默覆盖。

### 10.2 评审问题（待执行，不是本轮通过记录）

- [ ] 不看介绍，能否认出这是“可翻转的拼块玩具”，而不是魔方、城堡或收集宠物游戏？
- [ ] 玩家能否直接找到当前空位和手里候选，而不是先注意背景设施？
- [ ] 翻面前后是否仍认得同一共享格，没有六块独立棋盘的错觉？
- [ ] 消除看起来是腾出空间，而不是破坏世界或触发同色匹配？
- [ ] 参考画风是否已体现在棋盘、图标和 UI，而不只是换了一张背景？
- [ ] 手机尺寸、灰度和色觉模拟下，空／占／预览／无效是否可分？
- [ ] 背景设施是否没有伪装成地图、商店或未解锁按钮？
- [ ] 不加新玩法、新资源和角色系统，世界观是否仍然完整成立？
