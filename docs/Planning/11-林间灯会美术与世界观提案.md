## 1. 方向结论

**把“草坡上的木质玩具”改为“森林灯会中可翻转的六面灯芯”。玩家装填光片，填满一行或一列，让光能释放、空位回归，继续为灯会点灯。**

关键词：**粗轮廓、手绘色块、森林围景、暖光庆祝、可读的六面机关。**

这不是把背景换成森林，而是让三个核心动作有同一个解释：

- **为什么拼块？** 给灯芯表面的格位装填不同形状的光片。
- **为什么翻面？** 它是六面共用的一件装置，不是六块独立平面棋盘；要找空间，也要利用共享棱角。
- **为什么填满后消失？** 满行／满列完成一次释能，彩色能量离开，承载它的格块仍在。消除意味着交付成功，而不是破坏建设成果。

不建议采用“方块岛建房”作为本轮主叙事：刚盖好的建筑随后被消除，会让成功在语义上变成拆房；农场种植还容易暗示等待收获、作物分类和资源经营。灯会装置更贴合当前无重力、无计时、可重复填充的消除循环。

## 3. 世界观：能支撑当前游戏的最小设定

### 3.1 场所与玩家身份

森林居民在林间空地举办灯会。中央的“六面灯芯”是一件可朝任意方向转动的旧式节庆机关；玩家是负责给它配光的见习灯匠。

装置由固定的格块外壳承载光片。彩色表示“已装填”，淡色表示“空位”；六面共享棱角，同一角上的颜色会包过相邻面。**没有需要连接的电线、色系锁、入口出口或核心格。**

开局是全部未装填的完整装置，不是破损遗迹、待重建建筑，也不是预先占格的发光核心。底座、灯串、角色都在规则棋盘之外，不增加第 99 个格或内部可用空间。

### 3.2 玩家情绪与目标

- 基础满足：一块光片严丝合缝地装入。
- 策略满足：翻面找到出路；同一共享格同时影响邻面布局。
- 高潮：一次多消或连续消除，让灯会出现短暂、更强的庆祝。
- 长线目标：挑战现有分数与个人纪录，不用未实现的家园升级许诺留存。
- 局终：本轮配光结束，展示真实成绩；不是森林毁灭、角色受伤或扣除生命。

分数可以在叙事中解释为“配光表现”，**界面仍清楚标作 SCORE／得分**。不改成可消费的“光能币”，不新增第二套数值账本。正常落子本来就有分，不能把每一个得分都画成消线或完成点灯。

### 3.3 角色只承担说明，不伪装成玩法系统

可选一位原创“戴叶片围裙的短耳灯匠”，剪影与参考图角色明显区分。首期不是必需资产；优先出现在操作说明或结算边缘，局内不跟随手指、不占拖拽通道、不常驻大气泡。

不做宠物养成、抽卡、好感、助战技能。没有角色也必须完整解释玩法。

## 4. 玩法—世界观—反馈映射

| 当前规则／动作 | 世界观解释 | 可见反馈 | 必须避免的误导 |
| --- | --- | --- | --- |
| 98 唯一格的六面外壳，每面 5×5 | 一件可翻转的灯芯装置 | 完整等大格块；棱角连续包色 | 六个独立盘、125 格填内部、悬空块会掉落 |
| 三槽候选，固定朝向 | 灯匠当前的一盘光片 | 三个清晰浅色托位，保持真实拼块轮廓 | 增加候选旋转按钮、颜色选择或采购 |
| 拖放到合法空位 | 把光片装入格位 | 同色落点预览、短促卡入声 | 预览移到另一处“更合适”的落点 |
| 无效落点／取消 | 形状不合或重叠；收回手中光片 | 明确不可放标识，原件退回 | 扣分、扣道具、损坏模块 |
| 转动整盘、拖块翻面 | 转动机关寻找下一个工作面 | 手势方向沿用现行；侧带与边缘留空 | 顶盖、固定屋顶、烟囱导致只有一面能朝上 |
| 满一整行或一整列，不限颜色 | 一条格带完成释能 | 先确认真实命中线，再彩色退去、空位回归 | 同色匹配、连通电路、对角线消除 |
| 共享棱角及多面同时命中 | 共用格让邻面同时完成格带 | 可见面先说明原因，侧面只做弱呼应 | 一次落子跨面贴块；棱线被画成两份奖励 |
| 一次多消／连续消除 | 配光效率更高、演出更热闹 | 按真实结算提升音程与庆祝量 | 新增倍率、跨面奖金或连击资源 |
| 清除整面 | 当前工作面完成一次清空 | 仅结算事件认可时出现净面表演 | 把共享格带空的邻面也播成净面奖励 |
| 空位不足但道具仍有次数 | 工作台暂时拥挤，可以维护 | 保留原盘、提示现有救场操作 | 灯会熄灭／直接 Game Over／承诺道具必能救活 |
| 最终无法继续且道具耗尽 | 本轮配光结束 | 成绩牌、纪录、再来一局 | 偷加倒计时、失败惩罚或体力 |

**计分门禁：**v2 的独立跨面奖励已取消；物理同一条满棱只计一条线；净面只认可落子前非空、正常结算后清空的落子面，一手最多一个。表现读取结算结果，不从“亮了几个面”自行算奖励。旧存档若采用旧分制，仍按其结算事件表现，不做美术层分制迁移。

## 5. 棋盘与光片：实时 3D、手绘式观感

### 5.1 形体

- 保留现有 98 个唯一实体、规则坐标、共享棱角与同源几何；不做 150 片互相重叠的面贴。
- 空位是**浅暖灰的哑光格块**，不是黑洞、透明玻璃或一个画出来的凹槽。占用状态变为彩色光片表面，但块大小、位置、厚度不改变。
- 主面平整，小倒角提供识别；不做面包鼓包、果冻、宝石切面、悬挂芯片。候选、拖拽与棋盘必须像同一种东西。
- 轮廓比细节重要：整体外轮廓较粗，内部格缝较细。390px 宽概念稿可从外轮廓约 2–3 CSS px、内缝约 1–1.5px 起试，**只是打样值，不是已测参数**；按实际 DPR 与棋盘尺寸验收，不给每块描一圈同样粗的黑边。
- 彩色占用格可用一枚统一的小菱形压印作辅助占用标记；空格没有。符号代表“装填”，不代表元素属性。共享角的标记必须跟随同一格，不添加独立占用状态。

### 5.2 受光与材料

目标是**卡通哑光漆面／陶质感**，不是透明发光水晶。大色块、宽而软的亮部、一档清楚的暗部；方向跟随统一场景光，不能把固定白高光画死在每个 UV 上。

粗描边与少量硬边阴影建立插画气质，保留足够倒角体积使旋转可信。先用低成本材质样块验证，不预先承诺更换整个渲染管线。保留柔和接触影，禁止靠黑 AO 把格缝塞成焦黑。

“灯芯”是题材，不等于全体块常驻自发光。**静止时光片是可读的实体；释能时才短促提亮。** 不用全屏 bloom、透明折射或密集泛光达成主题。

### 5.3 底座与自由翻转

推荐棋盘悬停于低矮圆形灯匠工作台之上；通过稳定的软影与留空间距表达它是一件可自由翻转的机关。工作台不上包边、不用轴架夹住立方体、不压住下沿格子。

悬停是叙事与表现选择，**不是新增物理机制**。第一稿先沿用当前棋盘位置和相机，把工作台画到安全区域内；不得为接触底座挪动棋盘、改变停靠或牺牲向下拖块翻面的余量。旋转扫掠范围与工作台分不开时，先删除工作台装饰，不“顺便修手势”。

## 6. 色板、状态与画面层级

以下为**建议设计色，不是从压缩参考图精确取色，也不是最终材质参数**。

| 角色 | 建议色 | 用法 |
| --- | --- | --- |
| 主轮廓墨 | `#203333` | 深绿灰线条，避免所有对象纯黑描边 |
| 远层森林 | `#123D3B` | 画面外围少量最深色，不铺满中心 |
| 中层树冠 | `#326853` | 大叶团剪影，不画密集叶脉 |
| 中央空地 | `#91B68A` | 明亮、低纹理，为格块提供清晰背景 |
| 空格主色 | `#D8D8C6` | 比草地亮，低饱和；与彩块作状态分离 |
| 空格暗面 | `#A7B0A5` | 维持体积但不读成已装填 |
| 灯会暖黄 | `#FFD56A` | 灯串与确认瞬间，限小面积 |
| UI 奶油纸 | `#FFF0CE` | 数字／说明的干净承托面 |
| UI 深紫蓝 | `#53577D` | 次要控件底色，与深绿环境分离 |
| 光片样块色 | `#CB427D`、`#327FD1`、`#6953BD`、`#198B83`、`#823DA4` | 首轮五类代表样块，不是把 15 种形状合并成五种 |

方块最终色表单独做 **15 形状 × 候选／正面／侧面／预览** 对照；L/J、S/Z 不因方向相近又近色而难分。调色不能影响形状池、权重或存档坐标，也不能为了“单屏五色”更改发牌。现有存档保存 RGB，后续若改候选颜色必须制定已知旧色兼容方案，不能只展示新局就宣称完成。

空／占不只靠色相：空格浅、哑、无压印；占用格较饱和、明度区间受控、有统一小标记。概念稿必须过灰度与色觉模拟，未通过就改配色／标记，不以“灯会本来很花”解释。

合法预览仍用手中拼块自身颜色，加清晰短角标；无效预览使用专门警示色与叉形／斜纹，不只变红。新标记是表现提案，需在实机验证能否减少误读。

层级：**落点与棋盘 > 候选和分数 > 道具与操作提示 > 灯串与角色 > 森林细节。** 热闹在外围，安静在手指要操作的地方。

## 7. 场景、界面与道具

### 7.1 同一场景的屏幕组织

首稿沿用现有交互骨架，尤其竖屏的道具／棋盘／候选顺序和短横屏的左右分区，不照搬参考图的长弹珠跑道。

- 顶部：紧凑的当前分数、最佳纪录与设置；用厚轮廓小木牌或珐琅牌，不加巨型活动横幅。
- 中央：六面灯芯与低细节空地。树冠、彩旗只围外圈，不从棋盘前方穿过。
- 候选区：灯匠配件托盘，三个固定清楚的槽；避免复杂木边吞掉候选面积，尤其 3×3 大件。
- 道具区：同尺寸功能图标、真实余量、明确禁用态。预览、取消区与 3 秒撤销提示不被装饰侵占。
- 桌面／短横屏：重新绘制森林延展与裁切，不把竖屏长图放大裁中间；手机短屏优先移除角色、灯串和台座细节。
- 所有背景与装饰不接收指针事件；前景叶片也不能穿越棋盘的旋转轮廓、候选命中区及边缘翻面提示。

**首屏仍直接进入单局。** 不因为有世界观就强插剧情、营地页或强制开场；刷新续玩不重复播放一场“森林重新点亮”的演出。

### 7.2 四类道具：换外观，不换规则

| 道具 | 建议外观 | 预览必须说明 |
| --- | --- | --- |
| 换批 ×2 | 带循环箭头的光片工具箱 | 更换当前候选批，不是重新开局或免费无限补牌 |
| 锤子 ×1 | 圆头灯匠维修锤 | 只清理选中一格 |
| 火箭 ×1 | 小型纸礼花火箭 | 当前选择的是一行还是一列；保留 Row/Col 控制 |
| 炸弹 ×1 | 方格标签的圆胖彩纸爆竹 | 2×2 方形范围，不画成圆形半径爆炸 |

保留原功能名与一眼可认的工具轮廓，不给按钮只写“萤火”“祝福”等无法判断效果的主题词。清理目标以当前面真实预览为准，不额外扩大到邻面；被删共享格在相邻面同步变空是同一实体的结果，不是跨面溅射。

清理道具是“维护／卸载”，使用后**不飞得分光点、不庆祝满线、不改连击**；保留现有撤销流程、可用次数及卡住判定。不能因世界观好看把维护也包装成获得能量。

### 7.3 文案与界面制作

所有动态文字、分数、剩余次数仍为真实 DOM，走现有 i18n；英文默认、简体中文同步。状态至少有 normal／hover／focus／pressed／disabled／selected；不能让手绘按钮掩盖可用性。

剧情一句话只在合适的说明位置出现：**“转动灯芯，填满一行或一列，让光亮起来。”** 英文草案：*Turn the lantern core. Fill a row or column to release the light.* 不加必须阅读的故事前置。

主页与榜单换的是画框，不增加按钮。全球榜在真数据接入前仍必须标注示例数据，不能改成“森林居民排行榜”来隐去占位事实。

## 8. 动效与音效：先解释成功，再庆祝

以下时长是打样目标，实施时不得改动逻辑结算时机、输入锁或等待时长。

| 状态 | 视觉／声音方向 | 初稿演出长度 |
| --- | --- | --- |
| 普通合法落子 | 边沿短促确认、轻木扣声；数字按真实落子分更新 | 80–120ms |
| 单线消除 | 真实格带短亮 → 彩色褪去恢复空格 → 一小束方形光屑向边缘灯串散开；清脆一声 | 180–260ms |
| 一次多消 | 同批命中一起确认，空间方向可辨；少量彩纸和更饱满和弦 | 250–400ms |
| 连续消除 | 沿用真实链状态，音程与徽标增强；强度设上限 | 不另延长操作等待 |
| 净面 | 只对真实净面奖励播一次工作面描边与灯会呼应 | 350–500ms |
| 道具清理 | 维修／卸载音与范围确认；无得分光束 | 120–240ms |
| 局终 | 外围气氛保持温暖，真实成绩牌出现 | 不以长动画阻止重开 |

灯串呼应只是一闪即回的环境反馈，**不是累计点灯任务或跨局解锁**。正常落子有分但未消线时不触发释能演出。背面命中不自动转相机，不用遮满棋盘的庆祝替代玩家观察。

减动画模式去掉飞行轨迹、晃动与闪烁，保留静态命中轮廓、分数与简短提示。声音和触感沿用现有开关／设备支持判定；音量不靠一手叠加多段庆祝无限增大。

## 10. 最小打样与落地顺序

### A. 方向稿：先证明玩法读得懂

第一批只做以下设计，不直接全量生成资产：

新增图片若使用生成工具，只用于方向探索或经整理的静态布景；运行时不依赖生成服务。最终图标与状态须有可编辑稿，不把整屏截图切成“可交互界面”。相同资产的光向、线宽、圆角与符号含义人工统一；禁随机划痕、伪文字和复杂纹样填空。

### B. 工程分轮：一轮一个主要问题

1. 冻结当前版本、同种子盘面、视口、姿态与截图，记录性能／资源基线。
2. 单块样式：空格与彩块的材料、描边与状态区分；保持相机和规则。
3. 完整棋盘：98 格、共享棱角、候选一致性、旋转中间帧与低端描边降级。
4. UI 分组件更换；接着才做森林背景与工作台。
5. FX 与环境呼应最后接入，读取现有结算事件，不维护第二套玩法状态。
6. 对照方向稿验收；未通过回到对应层，不用更多粒子掩盖造型或构图问题。
