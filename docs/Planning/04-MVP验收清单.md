## v0.9.4 推不动就翻面（通用版）（2026-09-25）

> 制作人在 v0.9.3 之后追加定性："只要块块贴在立方体上，再往某个方向拖超过阈值就触发（等于把上面 A/B 的手势合并成第二段）——按这个方式处理。" 也就是把 v0.9.3 的「整面无位」放宽成**任何面、任何方向**的第二段手势：**块块不再跟手的那些帧**就是触发条件。改动：`src/input/gameInput.js`（`drag.push` + `trackPush()` 逐帧累计被 `clampOrigin()` 丢掉的位移 + `pinnedPush()` 把它投影成面自身轴上的屏幕像素 + `stepTurn()` 一次性翻一面；`updatePreview()` 的跟手分支负责累计，`updateDrag()` 多一条触发分支，`cubeSnapAnim` 分支补上"指针已离开轮廓就回到手上"）、`src/rendering/config.js`（`PIECE_SPIN.pinPx = 26`）、`src/diagnostics.js`（`pushPx` / `pinAxis`）、`tools/drag-feel-probe.mjs`（新增 K 段 9 项；C 段的边界走查按新窗口收口）。规则文字见 [03 §3.1](03-交互与表现需求.md)。

- [x] **触发条件是「块块不跟手」，不是「拖了多远」**：累计的是 `clampOrigin()` 丢掉的位移（面自身轴上的晶格单位），块块还在跟手的帧里这个数恒为 0。K 段实测：把 Dot 一路拖到右边界（`origin 4,3`）期间 `pushPx` 始终 0、姿态不动——**普通拖拽跨面、跨已占用格都不会误触发**（v0.8.27 的滑动手感未受影响）。
- [x] **推满阈值就翻一面，且是第一步就翻**（K 段直接断言）：阈值 26px 前最后一帧读数 25.0px，下一次 6.75px 步进即翻面（`front +z → −x`，轴 `yaw`），全程没有 `mouseReleased`。
- [x] **翻面发生时指针仍在可及范围内**：实测翻面那一刻指针只在立方体轮廓外 **3px**（吸附边距 18px）；从面边界到轮廓的可用空间实测 **36px**，`pinPx` 26px 落在里面。这是本轮**没有**放宽"指针离开轮廓→块块回到手上"的原因（放宽过，被 `probe:interaction` C 段挡回）。
- [x] **翻完即正常落子**：K 段松手后块块落在新面（`used=true`、盘面改变）；不可落点时按普通非法释放退回候选条。
- [x] **探针挡下一个真实缺陷**：加了 K 段后 `npm run probe:interaction` 报 **C 段「块块拖离立方体应留在手上」失败**（`mode=snap`）——原因是翻面动画那 0.22s 里落点标记一直锁在老面上，指针早已离开轮廓，块块会"凭空消失"一段时间。已在 `updateDrag()` 的 `cubeSnapAnim` 分支按指针位置分岔（离轮廓就清标记、回到 carry 幽灵），重跑 **52/52** 全过。
- [x] **代价（制作人明确选择的通用规则，已在 03 §3.1 写明）**：块块停在面边界后**再多推 26px 就翻面，而不是干停在边上**；"把块块放在最边上一格"要在推到边界时停手或直接松手。相应地把 C 段的边界走查收口到 `pinPx × 0.6` 以内（该段断言的是"边界不欠账、反向立刻跟手"，超过窗口的行为由 K 段钉住）。**这不是"改探针凑绿灯"：规则本身变了，窗口跟着变**；`pinPx` 是唯一旋钮（误翻就调大）。
- [x] **回归**：`npm test` **347/347 + 145/145 + 72/72 + 146/146 + 61/61 + 56/56**；`npm run probe:drag` **66 通过 / 1 失败 / 0 跳过**（K 段 9 项全过；唯一失败是既有的 I 段，见 v0.9.3 条目）；`npm run probe:interaction` **52 项全过**；`npm run probe:ui` **67 项全过**；`npm run build` 通过（976.67 kB / gzip 295.00 kB）。
- [ ] **未验证**：物理机手感——**`pinPx` 26px（约半格）是否容易在"想把块块放到边上"时误判成翻面**，是本轮最需要真机确认的一条；微信/QQ 内嵌、低端设备同样未跑；没有真人试玩。

## v0.8.8 方位微调验收（2026-09-17）
