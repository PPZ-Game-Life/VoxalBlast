## v0.8.1 侧带自转方向修复验收（2026-09-16）

用户报告：屏幕中间非六面体区域上下滑，右侧空白区符合预期，左侧与预期相反。

**原因**：竖滑的轴向划分只看手指落点是否在棋盘水平范围内（`isHorizontallyOnCube` → `screenBand`），出界即平面自转；但自转的符号左右两带共用 `ROTATE_STYLE.rollDirection` 一个值。自转是平面内旋转，"跟手"必须按手指所在的那条带定义：右侧带下滑时右边缘向下走（跟手，用户看到的"符合预期"），左侧带下滑时左边缘却向上走（相反）。也就是说两带里同向滑动必然得到方向相反的四分之一转，而代码只对其中一侧成立。

**修复**：`src/rendering/swipe.js` 新增 `bandRollSign()`（左带 -1、右带 +1），`swipeAngle()` 的自转项乘上带符号；`rollDirection` 仍是唯一方向旋钮（配置警告"不要再翻转方向值来追方向报告"依旧成立——这次不是翻旋钮，是补上缺失的带因子）。右侧带行为逐位不变。`main.js` 起手时采样 `screenBand()` 并随手势保存。

- [x] `npm run build` 通过（27 modules，主包 882.58 kB / gzip 261.82 kB、CSS 51.18 kB）。

## v0.8.6 停稳构图与旋转观感验收（2026-09-17）

制作人报告两个问题：停稳后正对玩家的主面面积不足、侧面顶面露得太多；旋转过程发歪，"像带着停稳时的斜角一起旋转"。本轮只改姿态呈现——玩法、输入映射、阈值、存档兼容与美术基线均未改。建议稿是 `docs/Temporary/Cube-Rotation-Interaction-Optimization.md`（临时交接稿，目录已 gitignore，不入库）。

**根因：两个问题同一个源——相机停在 3/4 视角** `[0.52, 0.48, 1.05]`（26.4° 偏航 / 22.3° 俯仰）。

- 停稳时三个可见面几乎平分轮廓：实测 52% / 26% / 23%，主面根本不是视觉主体。
- 世界 X 轴在该俯仰下投影成偏离水平 **10.63°** 的屏幕线，世界 Z 轴偏 **37.43°**——"发歪"来自相机，姿态层修不掉（世界 Y 轴恰好仍投成竖直，所以只有偏航看着是正的）。
- 第二重来源：旧的 `restOffsetYaw/Pitch`（各 ≤8°）存的是上一次手势的溢出量，且被冻结在实时旋转**外面**；只要它非零，主体就一直绕着一根斜轴转，而且每次停稳的斜角都不一样。

**改动**（`src/rendering/config.js`、`src/main.js`）：

- `BOARD_STYLE.cameraDirection` 改为正视 `[0, 0, 1]`，停稳立体观感改由展示偏摆提供。
- `ROTATE_STYLE`：删 `restOffsetYaw/Pitch/Roll` 与 `snapOvershoot`；新增 `presentationYaw/Pitch`、`presentationFadeAngle`（0.35 rad ≈ 20°）、`presentationFadeOutEnd`、`presentationReturnStart`；`snapDuration` 0.26 → 0.22s。
- `main.js` 改为 `renderPose = tilt(weight) ∘ R_axis(angle) ∘ cubeBase`。`cubeLive` 的角度从 0 起算、不再折叠偏摆；新增 `rendered` 记录"实际渲染到的角度"，键盘旋转仍旧从当前可见姿态起动画而不是瞬移（v0.4.1 的老坑）；吸附改 easeOutCubic；存档只写逻辑姿态 `base`，旧存档的 `quat/yaw/pitch` 被忽略但仍可加载。
- 新增只读探针 `__voxalblast.faces()` 与 `__voxalblast.poseAxisScreen(from, to)`；新增 `npm run probe:framing`（`tools/cube-framing-probe.mjs`，24 朝向自动走查）。

**为什么不是建议稿里的 4°/3°**：文档的 4°/3° 与 82–88% 目标建立在正交投影的 `1/(1+tanα+tanβ)` 上。本工程相机很近（D ≈ 14 世界单位、半边长 2.5、FOV 30），一个面只有满足 `D·sin(tilt) > half` 才可见——6.6°/5.3° 实测主面占比 **100%**，侧面和顶面**一个都不显示**，六面体在屏幕上就是一块平面 5×5 板（已用截图确认）。因此偏摆按真实投影反解为 17.5°/15.5°。**注意：探针第一版用 `n·viewDir > 0` 判可见性（正交口径），在这种近距离相机下会把藏在正面背后的侧面的投影面积算进来，得出"86.7% 主面"的假结果；现已改为"相机必须在面平面外侧"。**

**结果**（`npm run probe:framing`，1280×900）：
