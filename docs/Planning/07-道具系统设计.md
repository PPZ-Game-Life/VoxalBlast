# VoxalBlast 道具系统

> **实现事实基线：原 v0.8.16 记录；本轮对照 v0.8.22 工作区的 `src/main.js` 道具定义、瞄准、范围与结算路径复核，未改代码。** §1–§5 保留实现事实，§6 为后续功能项，§7 为原实测待办。
> **本轮新增：§8「道具交互重设计 v1」，为待实施设计，不代表已上线或已通过实机验收。** 保留四种功能、库存与计分规则，只重做预览、生效、取消及输入分工；交互实现以 §8 为目标，不能将其与 §2 旧手势叠加运行。

## 1. 当前已实现：数量、成本与作用

| 道具 | 新局初始次数 | 读档上限 cap | 一次成功使用成本 | 当前作用 |
| --- | ---: | ---: | ---: | --- |
| 换批 Refresh | 2 | 3 | 1 次；点击后立即扣除 | 丢弃当前整批候选（包括已用状态），重抽 3 块 |
| 锤子 Hammer | 1 | 2 | 1 次；实际删到格后扣除 | 删除当前正面目标晶格中的 1 个已占用单元 |
| 火箭 Rocket | 1 | 2 | 1 次；实际删到格后扣除 | 删除当前正面本地行或列中的已占用单元，作用域 5 格 |
| 炸弹 Bomb | 1 | 2 | 1 次；实际删到格后扣除 | 删除当前正面从目标格向 `+u/+v` 延伸的 2×2 作用域，边缘越界部分裁掉 |

四种道具合计新局 **5 次**。当前没有金币、分数或广告成本，也没有局内/局外获取途径；所谓“成本”只有每次消耗 1 个库存次数。

`cap` 只在续玩恢复及撤销返还时钳制，不表示存在补给系统。`session.migrate()` 先读取非负整数，`applySession()` 再按每个道具的 `0..cap` 钳制；新局 `resetItems()` 始终恢复初始次数。

棋盘以共享三维晶格存储棱和角：同一 `(x,y,z)` 只存在一个方块。道具删掉棱角晶格后，相邻面会同步出现空位（`faceLattice()`、`Board.removeCells()`）。

## 2. 当前已实现：使用流程

### 2.1 换批

`activateItem('refresh')` 在有次数且可操作时立即：扣 1 次 → `rerollPieces()` → 保存 → 重新检查卡死。

换批固定生成三块，最多尝试 24 次避开与旧批“同顺序同形”；24 次只是重试上限，不承诺一定不同，也不承诺新批一定可放。

### 2.2 锤子、火箭、炸弹

点击按钮后进入 `itemActive` 瞄准态，按下画布不结算：

1. 记录 `itemTap` 起点；
2. 刷新指针下的预览；
3. 同一个指针手势交给 `beginViewDrag()`。

抬起时位移小于 `ITEM_TAP_SLOP=6px` 才调用 `selectItemAt()`；达到或超过 6px 视为转面手势，不扣次数。触屏因此能在按下时看到预览，抬起确认。

目标必须落在立方体屏幕轮廓内；离开轮廓时保留上一个 hover 预览，但若最终在轮廓外释放，`selectItemAt()` 会提示 `Tap a face cell`，不会结算。格坐标钳制在 `0..4`。

火箭默认 Row，并可按指针在格内的偏移自动选 Row/Col；面板按钮及 PC 的 R/C 可手动纠正。已经锁定为转面手势后不再按格内偏移改方向。

**输入边界：**

- 道具瞄准态可用鼠标/触屏在画布上拖动转面；
- 当前 `handleRotateKey()` 在 `itemActive` 存在时拒绝 W/S/A/D/Q/E，所以键盘不能在瞄准态转面；
- R/C 只负责火箭方向；
- 再点同一道具按钮、火箭面板 `✕`、Esc、右键、打开设置/主页或页面隐藏可退出瞄准态；
- 代码中没有长按计时器或长按取消分支，旧文档“任意端长按取消”并未实现。

### 2.3 成功、失败与冷却

- 作用域内没有已占用格：状态条 + toast + 触感反馈，不扣次数；
- 实际删除至少 1 格：扣 1 次、播放粒子、刷新盘面、保存，并重新检查卡死；
- 成功后 `itemBusyUntil = now + 420ms`，约 450ms 后刷新按钮状态；
- 暂停、局终、候选拖拽中、设置打开或冷却未结束时不执行新道具；
- 道具没有次数时显示 `No <name> left` 并触发触感，而不是静默失败。

## 3. 当前已实现：3 秒撤销

锤子/火箭/炸弹成功后开启 3 秒窗口，toast 为 `Cleared N - Undo`。撤销会：

- 用删除前 `Board.peekCells()` 保存的完整记录恢复晶格与颜色；
- 返还 1 次并按对应 `cap` 封顶；
- 清除道具冷却；
- 重绘、重写续玩存档；
- 再跑 `checkStuckAndPrompt()`。

撤销窗口在落子结算、换批、重新武装任一道具、局终、页面隐藏或 3 秒到期时关闭。换批没有撤销路径。

## 4. 当前已实现：计分与回合边界

清理类道具直接调用 `Board.removeCells()`，不走 `Board.place()` / `settlePlacement()`，因此：

- 不加放置分、消除线分、跨面分、连击分或荣誉分；
- 不增加 `board.totalLines`；
- 不触发落子荣誉；
- 不推进也不打断连击；
- 不消耗候选块，也不算一次落子回合。

换批只替换候选并消耗库存，同样不计分、不改连击。主分保持可复现，不包含道具收益。

## 5. 当前已实现：死亡前救场与死亡边界

`checkStuckAndPrompt()` 只在游戏未结束、未暂停且存在候选时检查三块候选是否在六面任意姿态有合法落点（`hasPlaceablePiece()` → `Board.anyPlacement()`）。无块可放时：

| 剩余库存 | 当前行为 |
| --- | --- |
| `refresh > 0` | 保持局面，提示 `No spot - use/try Refresh` |
| `refresh = 0`，且锤/箭/弹任一 > 0 | 保持局面，提示 `No spot - clear a path` |
| 四项全部为 0 | 立即 `endGame()` |

这是一条**延迟死亡、允许玩家自救**的规则，不是“死亡后复活”：

- 清理类道具只按“还有次数”保活，不穷举这一次是否真的能制造合法落点；
- 玩家可能消耗后仍然无处可放，代码会再次提示或在全部库存耗尽后结束；
- 一旦 `endGame()` 执行，会写本地已结束局纪录、清除续玩槽并显示结算；
- 当前没有死亡后广告续命、免费复活、回退一步或重开前恢复本局的路径。

## 6. 尚未实现/待决策

以下不是当前能力：

1. **荣誉挂钩**：如“道具救场/Second Wind”荣誉；即使新增，也应维持道具不进入主分。
2. **历史数值提案，本轮不采用**：锤子由 `1/2` 调为 `2/3`；本轮保留 `1/2`，四道具初始合计仍为 5。
3. **补给系统**：消除里程碑、连击奖励、广告、每日补给、商店均未实现，本轮不扩展。
4. **专属表现**：方向箭头、作用域完整边框、棱角共享的邻面高亮纳入 §8；每种道具独立音效不作为此次交互交付的前置条件。
5. **瞄准态转面与长按取消的旧设想**：由 §8 取代。新方案瞄准期间统一锁定棋盘，不补瞄准态转面；不用长按/双击等隐藏手势取消。

## 7. 现行实现的实机待办（不是新版验收）

本轮只做静态阅读与文档设计，未构建、未运行游戏测试/探针、未启动浏览器。现行“按下预览 → 轻点结算 / 拖动转面”、火箭自动选向的手感未在本轮实测；它们是 §8 要替换的路径，不再作为新版目标。

保留待回归：3 秒撤销、冷却/无库存反馈、空目标不扣次数、卡死状态逐级消耗道具至 Game Over。新版专项验收见 §8.11，不能用历史 `npm test`、`npm run build` 或 `probe:rescue` 记录代替。

## 8. 道具交互重设计 v1（本轮方案 · 待实施）

### 8.1 目标、参考与不改的边界

**一句话：先拿起来，看清会影响哪里，再松手；不想用了，拖回去。** 取消不该是藏在攻略里的彩蛋，炸弹也不该让玩家猜盲盒。

参考 Block Blast 的**拼块拖放心智**，而不是声称复刻它某个版本的四种道具：选择对象、跟手移动、棋盘承接、明确落点。参考入口：[Hungry Studio《Block Blast!》商店页](https://apps.apple.com/jp/app/block-blast/id1617391485?l=en)。本轮未逐帧实测竞品道具；范围框、取消区和以下多面棋盘规则均是 VoxalBlast 自有设计。

**保持不变：** 换批/锤子/火箭/炸弹四种功能；初始 `2/1/1/1`、cap `3/2/2/2`；成功消耗 1 次；不计分、不改连击、不推进落子回合；清理类保留现有 3 秒撤销及失效边界；无道具补给、无死亡后复活。炸弹仍是当前正面 `+u/+v` 的 2×2、边缘裁切，不改成 3×3、体积爆炸或跨面扩散。

| 当前痛点（交互机制层判断，未量化误触率） | 新版取舍 |
| --- | --- |
| 棋盘上一段手势同时承担瞄准和转面，靠 6px 决定是否花道具 | 道具模式只瞄准，棋盘姿态/缩放锁定；要换面先取消、转好、再拿道具 |
| 点中目标就花次数，玩家未必有时间看清 | 图标起手的拖放可直接释放生效；轻点路径必须先选目标、再按显式“使用” |
| 火箭随格内偏移自动改 Row/Col | 固定方向 + 显式切换，不再自动猜方向 |
| 炸弹只有通用逐格高亮，看不出边界与空格 | 外轮廓 + 格内范围 + 实际清除格强调 + 数量 |
| 取消入口不统一，离开棋盘还残留上个目标 | 候选区/道具区大取消区 + 常驻“× 取消”；移出有效面立即失效 |
| 换批点一下立即扣次数，没有事前反悔机会 | 候选区内嵌确认，确认后才抽取和消耗 |

### 8.2 四道具的主流程总表

| 道具 | 拿起/进入 | 预览 | 生效 | 取消 |
| --- | --- | --- | --- | --- |
| 锤子 | 从图标按住拖出 | 正面单格轮廓，强调该格占用实体；`将清除 1 格` | 在有效目标上松手，清除 1 格、扣 1 次 | 拖回取消区或在无效处松手 |
| 火箭 | 从图标拖出；默认横向，上次本局主动选向可记住 | 正面整行/列 5 格光带 + 两端箭头；`横向/纵向 · 将清除 N 格` | 松手清除预览行/列内占用格，扣 1 次 | 同上 |
| 炸弹 | 从图标按住拖出 | 2×2 范围外框 + 内部分格；已占用格强调；`将清除 N 格` | 松手清除预览范围内占用格，扣 1 次 | 同上 |
| 换批 | 轻点图标，不支持拖到棋盘 | 候选区框出“整批替换”的范围，显示消耗确认；不提前生成新批 | 点 `换一批 · −1`，一次性替换成 3 块、扣 1 次 | 点 `保留当前`、`× 取消` 或再次点换批 |

清理类统一提供轻点备用路径：**点道具 → 点/滑动选择目标 → 松手保留预览 → 点 `使用 · −1`**。这个流程中点棋盘绝不直接消耗；主拖放流程不加二次确认弹窗。持续按住不计时、不蓄力、不自动生效。

### 8.3 公共操作区与取消区

**普通态：** 四个图标始终配名称与次数，不让玩家仅凭 emoji 猜功能。可用态、次数为 0、暂不可操作三个状态明确区分；次数为 0 显示 `0` 和“本局已用完”，不展示虚假的补给入口。

**已选中/预览态：** 在棋盘外的固定道具状态条显示：`[图标 名称] [操作提示/目标数量] [× 取消]`。火箭在这里追加 `↔ 横向 / ↕ 纵向`；轻点备用路径有有效目标后追加 `使用 · −1`。状态条不遮挡棋盘，不跟手四处跑，也不挤掉主分与数量。触控按钮命中区域至少 44×44 CSS px，推荐 48×48；窄屏换行而不是缩成小叉。

**正在拖拽清理道具时：**

- 整个候选区切换为大面积 `× 拖到这里取消`，候选内容弱化、不可选择；道具条也成为取消命中区，与现行拼块取消区域保持一致。只改变内容表现与输入，不隐藏槽位容器、不改变高度或占位。
- 两区域若分居上下或左右，它们是**两个独立矩形的并集**，不是把中间棋盘一起包进去的大矩形；保持原布局占位，不让棋盘/命中区因取消态出现而跳动。
- 命中任何一个取消区就高亮、显示 `松手取消`，道具幽灵回缩；**只有在区内松手才取消，路过不锁死取消意图**。从图标拖出时尚在原道具条内同样可安全放弃；离开后正常瞄准，不能因为起点属于取消区而判整段手势无效。拖过其他道具图标不切换/使用另一道具。
- 只在离开取消区后才可能出现有效落点；原始手指/鼠标命中取消区的优先级高于抬升后的瞄准点，防止手已拖回槽位但炸弹还挂在棋盘上。
- 道具**状态条**与四图标**道具条**是不同区域，状态条不整体充当取消区。拖拽时状态条保留名称、当前方向/数量和 `× 取消`，横/纵切换按钮及“使用”按钮隐藏且不参与命中，但保留布局占位。触屏先选方向再拖或取消后重选；PC 拖拽时仍可用 R/C 切向并刷新预览。
- 常驻 `× 取消` 是已选中/预览态的主要点击退出入口，**不是另造一个小型拖放靶区**；拖拽中移入它并松手同样按取消处理。

**没有持续按住时：** 候选仍可看但不可拖；点另一有库存道具可无成本替换当前选择；再次点当前图标退出。不得在“选着炸弹”的状态下同时允许拖候选块。

冗余退出保留 PC `Esc`、右键。取消和失败释放均只退出道具模式、清理预览，不推进回合、不触发消除、不重新触发卡死结算。

### 8.4 拖放、轻点与转面：互不抢手势

以下阈值是**建议起始值、需真机调优**：图标按下后累计位移达到鼠标 6 / 触屏 10 CSS px，即锁定为拖拽；一旦锁定，即使返回起点也不再降回点击。小于阈值的完整按下/抬起视为轻点选择。只接收主指针/鼠标左键；不要求长按等待。

| 起手上下文 | 移动与释放结果 |
| --- | --- |
| 普通态，从画布起手 | 原有转面手势，不启用道具 |
| 普通态或已选中态，从清理道具图标起手并越过阈值 | 拖动瞄准；有效释放立即使用，无效释放退出；生成的后续 click 必须吞掉 |
| 轻点清理道具图标 | 只进入已选中态，库存不变；点同一图标再次轻点则退出 |
| 已选中态，从棋盘起手 | 按下/滑动只移动目标；抬起只固定预览，显示“使用”，不自动扣次数，不转面 |
| 已固定轻点预览，重新点/滑动棋盘 | 替换预览；若无效则清掉目标、禁用“使用”，仍保持已选中态，可重新选 |
| 已固定轻点预览，点“使用” | 只提交已经锁定的目标，不按按钮所在屏幕坐标重新瞄准 |

**为避免手机上“既想瞄准又想转面”，道具模式期间一律锁定画布转面、W/S/A/D/Q/E 和滚轮缩放**，第二根手指不接管目标也不转面。提示 `需换面？取消后转动棋盘`；转动/吸附动画未停稳时道具暂不可拿起。这个取舍牺牲“拿着道具转面”，换取一次手势只有一种含义。

首次进入清理道具时展示一次轻量引导 `拖到棋盘，松手使用；拖回取消`，不遮屏、不强制耗掉一次。主动轻点后改为 `点选目标，再点使用`，提示与当前路径对应，不能两条规则同时堆给玩家。

### 8.5 共用瞄准与范围语言

1. **只选当前正面。** 用实际正面网格投影的面内区域判定，而非整个立方体轮廓或无限平面；两侧可见面的内部不是合法靶区。棱线归当前正面边界，不自动换面、不在别面“找最近占用格”。
2. **瞄准点可见且跟手。** PC 靶心跟指针；触屏从图标起手的主拖放默认将靶心抬到手指上方 48 CSS px，并显示小连接线。该值是待调参数，本次手势固定；预览与结算必须使用同一个抬升瞄准点，不得预览抬升而落点仍按指腹。**轻点备用路径从棋盘选目标时不抬升，按指腹实际位置命中**，抬手后留出观察时间，再点使用。主动移动目标期间移出有效面立即移除可生效范围，显示 `移到正面棋格`；主拖放另显示灰色手持道具，重新进入可恢复有效预览。轻点目标固定后，单纯移动鼠标或前往“使用”按钮不属于重新瞄准，不清掉固定预览。
3. **连续拖动只吸附格子，不吸附收益。** 目标格按靶心位置确定，不能跳去占用更多的区域，也不能因为空格而跳到邻格。范围不贴近手指时不允许远距离吸到边缘。靠边时以靶心而非道具图标外缘判断面内；原始指针在取消区、页面外或丢失时始终取消。
4. **范围与结果分层。** 细实线/低透明填充表示完整作用域，包括空格；高对比描边与轻脉冲表示将被清除的已占用实体。空格不伪装成待清除块，不只靠红绿区分。数量 N 取唯一三维晶格去重后的实际占用数。
5. **空目标可预览，不可提交。** 整个范围 N=0 时虚线/禁用符号 + `这里没有可清除方块`；不显示可使用状态。拖放释放回弹退出；轻点路径留在选中态，“使用”禁用。半空范围 N>0 可正常使用，不要求填满范围。
6. **邻面只解释共享，不扩大范围。** 若目标含棱/角共享实体，其邻面可见表面同步细描边，提示 `边缘共享格会同步清除`；不高亮邻面的其他格，也不按可见面重复算 N。
7. **所见即所得。** 生效只能提交最后已显示的那份目标快照（道具、面、锚点、方向、范围、占用记录）；“已显示”指 pointerup 之前最后一个已呈现的渲染帧，不是仅在 pointermove 中算好但尚未画出的数据。释放坐标只用于核验当前仍落在相同目标范围、且不在取消/非法区域；像素移动但吸附目标未变不算目标变化。若已移到另一格/方向而新预览未呈现，或棋盘/姿态/库存不再匹配，则退出、不扣次数，提示 `未使用，请重新瞄准`；不得在 pointerup 临时生成另一片范围并直接清除。轻点路径固定目标后，移动鼠标到“使用”不再改目标；点使用仅校验锁定快照仍有效，不将按钮坐标作为目标。

### 8.6 炸弹：把“炸哪儿”画清楚

**主流程示例：** 按住炸弹拖出 → 正面出现 2×2 框 → 移动时整框逐格吸附 → 状态条显示 `将清除 3 格 · 松手使用` → 松手 → 仅这 3 个占用晶格消失，次数减 1。若不满意，继续挪；不想用了，拖回取消。

**范围图形组成：**

- 靶心标出当前锚点格；边框沿棋格画成方形/透视四边形，并保留内部分格，不用圆形爆炸光圈冒充判定区域。
- 炸弹图标可浮在区域几何中心，但**图标中心不是判定锚点**。实际方向沿当前面的 `+u/+v`，用框和锚点直接说明；不硬写成屏幕“右下”，以免转面后误导。
- 已占用目标加粗描边/轻脉冲，空目标格仅保留浅底纹。特效不能抢在松手前爆炸，也不遮盖轮廓、靶心和数量。
- 边缘越界部分按现行规则裁切，不向内偷偷平移来“凑满四格”、不跨面补格。裁切侧画截断短线，提示 `边缘裁切 · 范围 M 格 / 将清除 N 格`；内部位置 M=4，单方向越界 M=2，两方向越界 M=1。

| 面内锚点（u,v 从 0 到 4） | 实际作用格 | 全占用时显示 |
| --- | --- | --- |
| (1,1) | (1,1)、(2,1)、(1,2)、(2,2) | `范围 4 格 / 将清除 4 格` |
| (4,1) | (4,1)、(4,2) | `边缘裁切 · 范围 2 格 / 将清除 2 格` |
| (4,4) | (4,4) | `边缘裁切 · 范围 1 格 / 将清除 1 格` |

完整 4 格中只有 2 格占用，就显示 `将清除 2 格`；4 格全空则禁用。这里保留裁切是为了不改功能/强度；“始终完整 2×2”的吸附方案不在本轮内。

**生效反馈：** 锚点确认闪 → 实际目标短促压缩/碎裂 → 空位显露；范围外不出现“像被炸到”的强闪光。取消只做归槽回弹，不播成功音效/爆炸。

### 8.7 火箭与锤子

**火箭：先定方向，移动只换行/列。**

- 首次默认 `↔ 横向`；方向仅在当前已加载对局的内存中记住最后主动选择，取消、撤销及失焦/隐藏/设置后恢复不重置。新局、页面刷新或重新载入续玩快照均恢复横向，不增加存档字段；界面始终显示当前方向，不把“本局记住”承诺成跨加载持久化。
- 轻点火箭进入选择态即可看到 `↔ 横向 / ↕ 纵向` 两段按钮。手机要竖向：轻点火箭 → 选纵向 → 从已选图标拖到目标松手；也可走点目标、点使用的备用路径。
- 持续拖拽时不要求第二根手指切方向；PC 保留 R/C 显式切向，改变方向须更新预览后才可提交。触屏可取消后重选方向，不增加隐藏双击/扭转手势。
- 横向表示沿当前正面 u 轴、固定 v；纵向沿 v 轴、固定 u。方向箭头贴合当前面投影，转好面重新拿起后按新正面解释。
- 预览完整 5 格条带，空格浅底、占用格强描边，两端箭头显示贯穿方向；行/列交点不自动改向，禁止沿用格内 du/dv 自动判断。
- 成功后光束只沿预览线穿过，删除其中占用格；不是“行列同时消”，也不向立方体深处贯穿。

**锤子：点杀一格，反馈最轻。**

- 方框只圈 1 格，锤头浮在靶心旁，不能遮住该格；空格显示禁用提示。
- 主路径拖放松手清除；备用路径点一格显示 `将清除 1 格`，再点“使用”。不因锤子范围小而恢复“点棋盘立即扣次数”的旧分支。
- 成功只敲击该实体；若是棱/角，同步表现它在邻面上的消失，但仍只算 1 格、消耗 1 次。

### 8.8 换批：不硬套拖炸弹的手势

换批作用于候选，不作用于棋盘；本轮采用**轻量两步确认**，不增加“拖到候选还是取消”的冲突规则。

1. 点换批，图标选中，候选区出现内嵌确认条：`替换当前整批候选，消耗 1 次；新批不保证可放。` 未用候选加淡描边，已用槽保留已用样式；整批容器外框标明 3 槽都将刷新。
2. 显示 `保留当前` 与 `换一批 · −1` 两个明确按钮，后者远离换批图标原点击位置，避免连续点击穿透。此时不抽随机数、不改候选、不扣次数，不提供“预览下批再取消刷答案”。
3. 点确认才替换为新 3 块并扣 1 次；不能偷偷改成“只换未用块”。动画表现旧批淡出、新批进入，完成后回普通态；不承诺一定不同或必定可放。
4. 点保留当前、再点换批、`× 取消`、Esc/右键可退出；点其他有库存道具可取消确认并切换。点棋盘/拖图标不确认，不将棋盘当换批目标。
5. 确认期间锁候选拖放及棋盘转动；按下→抬起一次只生成一次确认，双击/连点在结算锁期间不得抽两批或扣两次。

换批仍无使用后撤销，所以事前确认不能省略；取消确认必须保留原候选形状、颜色、已用标记与库存。

### 8.9 生效、取消、撤销与中断的状态契约

| 状态 | 可发生的转换 | 不变量 |
| --- | --- | --- |
| 普通态 | 轻点选择 / 图标拖拽 / 换批确认 | 没有残留预览，正常候选和转面可用 |
| 已选中态 | 点目标→待确认；图标拖出→拖拽；切道具；取消 | 不扣次数，不清格，锁候选/视角 |
| 拖拽态 | 更新预览；有效释放→提交；无效释放/取消→普通态 | 仅原始 pointerId 可提交，其他指针不接管 |
| 待确认态 | 重新选目标；点使用→提交；切道具；取消 | 目标固定，按钮外移动不改变快照 |
| 换批确认态 | 确认→提交；切道具；取消 | 不提前 reroll、不推进回合 |
| 提交/反馈态 | 一次成功结算→普通态（受现有冷却约束） | 删除/换批与扣次原子完成；禁止重复提交 |

- 清理类实际删到 N>0 才扣 1 次；空目标、非法面、取消区、面外松手均不扣。松手成功后关闭模式，不把剩余库存自动再次拿起。
- 清理类沿用当前约 420ms 冷却；刷新按钮状态不能只靠视觉灰化。换批也必须在一次提交与反馈期间防重复；无需为交互重做库存上限、分数或回合规则。
- `pointercancel`、意外丢失指针捕获、窗口失焦、切标签、页面隐藏、进入设置/主页/结算、重开、视口尺寸或设备方向变化：**未提交动作一律取消**，明确涵盖已选中、拖拽、待确认、换批确认四态，全部退回普通态；恢复后不自动武装、不保留目标、不补发一次松手。取消本身不改棋盘/候选/库存，重开等宿主动作仍按自身规则执行。正常 pointerup 后释放捕获不应再次触发取消或退款。
- 提交后出现上述中断：已完成的棋盘/库存事务保留，只清表现；不得取消已经完成的使用，也不自动返次数。未提交预览不写入续玩快照。
- **取消 ≠ 撤销。** 取消发生在使用前且免费；锤子/火箭/炸弹成功后仍只有 §3 的 3 秒撤销。改为清晰的 `已清除 N 格 [撤销]` 操作条，撤销点击区至少 44px，窗口存在时不被普通提示覆盖；可附倒计时环，但不加新时长、不自动暂停计时。撤销条与道具状态条各自占位、互不遮挡，也不属于拖放取消区。
- 撤销失效条件仍按 §3：落子结算、换批、重新武装清理道具、局终、页面隐藏、到期。**重新武装定义为轻点进入清理道具已选中态，或图标手势首次越阈值进入拖拽态**；此刻就关闭上次撤销，不延后到有效目标或提交，因此保留原“选用下一个清理道具即结束上次撤销”的边界。仅 pointerdown 尚未识别手势不关闭；无库存/不可操作的拿起尝试不关闭。仅打开/取消换批确认不算已经换批，实际确认换批时才关闭撤销；若确认期间点击尚有效的撤销，先退出换批确认再撤销。不要承诺“任意时候都能撤销”。
- 无块可放时仅提示还有库存的自救入口，不替玩家自动选道具/目标、不保证救活。成功后仍按 §5 重查；**最后一次道具用完仍无落点会立即 Game Over，3 秒撤销随局终关闭**，不为新版交互偷偷加死亡后回退。

### 8.10 最小落地顺序与文案
