## 1. 当前实现

### 1.1 配额

| 道具 | 初始 | 上限 cap | 作用 |
| --- | --- | --- | --- |
| 换批 Refresh | 2 | 3 | 丢弃当前整批候选，重抽三块 |
| 锤子 Hammer | 1 | 2 | 删除当前面选中晶格中的一个已占用单元 |
| 火箭 Rocket | 1 | 2 | 删除当前面选中行或列中的已占用格，最多 5 格 |
| 炸弹 Bomb | 1 | 2 | 删除当前面 2×2 区域中的已占用格，最多 4 格，越界侧自动裁掉 |

`ITEM_TOOLS` 定义在 `src/main.js`。配额随未完局存档恢复，新局重置；`cap` 只是存档读取时的钳制上界，**当前没有任何获取途径**——没有商店、里程碑奖励、广告补给或荣誉奖励（`src/game/session.js` 只做读取钳制）。

棱角按共享晶格删除：`faceLattice()` 落到本体 (x,y,z) 上，删掉一个棱上格会让相邻面同步出现空位（`src/game/board.js` 的 `removeCells`）。

### 1.2 目标选择与执行（本轮重做）

- 点道具按钮 → `activateItem(id)`；换批**立即结算**（直接 `rerollPieces()`），其余三个进入瞄准态 `itemActive = { id, face, u, v, orientation }`。
- **按下不结算**：瞄准态下 `canvas` 的 `pointerdown` 只做三件事——记录起点 `itemTap`、按落点刷新一次预览、把同一手势交给 `beginViewDrag()`。结算发生在**抬起**时，且要求位移 < `ITEM_TAP_SLOP`（6px，与候选块拖拽同一阈值）；位移 ≥ 6px 判定为转面，抬起不消耗道具。
- 因此**瞄准态可以转动方块**：想清的面不在正面时，直接拖着转过去再松手，不再需要「退出道具 → 转面 → 再进道具」。PC 的 W/S/A/D/Q/E 与触屏拖拽都可用。
- 触屏在按下瞬间即可看到高亮预览，抬手才确认（触屏没有 hover，这是它唯一的预览窗口）。
- **命中约束**：目标只在指针真的落在方块屏幕轮廓内（复用 `isPointerOnCube`）时更新；离开轮廓保持上一个目标，不再像 v0.5 那样把高亮甩到角落格。`u`/`v` 一并钳制在 `0..SH-1`，越界面外的预览块不会飘到方块外面。
- **火箭方向自动预选**：按指针在格内的偏移决定——落在格的纵中线上（`|du| < |dv|`）读作列，落在横中线上读作行。`#axis-pick` 的 Row/Col 面板保留为手动纠正，并高亮当前方向；PC 的 `R` / `C` 键走同一个入口（`setRocketOrientation`）。转面过程中不重算方向，避免拐动时来回跳。
- 取消路径：**再点同一道具按钮 = toggle 关闭**（激活中的按钮带 `✕` 角标提示这是出口）、火箭面板的 `✕`、PC `Esc`、PC 右键、任意端长按。取消不扣次数、不动盘面。
- 无配额时点击 → toast `No <道具名> left` + 震动，不再静默（v0.5 的静默返回会被读成「按钮坏了」）。
- 空目标（作用域内无已占用格）→ 状态条 + toast + 震动，不扣次数。
- 成功后 `itemBusyUntil = now + 420ms`，450ms 后重绘道具条（防连点）。
- 拖拽候选块、暂停、局终、设置打开、无配额时不响应。

### 1.3 撤销（本轮新增）

- 清场成功后开启 **3 秒撤销窗口**：toast 变为可点的 `Cleared N - Undo`。
- 撤销恢复晶格**与原色**（`board.peekCells` / `board.addCells`，颜色存在格记录里，`removeCells` 只返回坐标所以不足以还原）、按 `cap` 返还道具次数、清零冷却、重写存档，并重跑 `checkStuckAndPrompt()`——撤销回一个仍然卡死的盘面时，该结束就照常结束。
- 窗口在下列时点立即关闭：落子结算（`settlePlacement`）、换批、重新武装任一道具、局终、页面隐藏。
- **未采用触屏两段式确认**（原提案里「第一次轻点锁定、第二次才执行」）：既然结算已经改到抬起、且位移超过 6px 就等于取消并转为转面，再叠一层二次点击会变成三次操作，收益不抵摩擦。

### 1.4 计分、结束与存档

- 道具**不计分、不增加消除线数、不触发落子荣誉、不推进/打断连击**（`src/game/scoring.js` 与 08 §5.4 一致）。清理类不消耗候选块；换批替换整批，含已用状态。
- 成功操作后 `saveSession()` 并 `checkStuckAndPrompt()`。
- `checkStuckAndPrompt()`（v0.8.16 起）：无块可放时按剩余次数逐级降级——`refresh > 0` → 提示换批；否则 `hammer|rocket|bomb > 0` → 提示「清理挡路格」并**保持局面、不判死**（B1，见 §1.5）；四项全部为 0 → `endGame()`。
- 换批最多重试 24 次避开与旧批「同序同形」，不构成不重复保证。

### 1.5 救局判定 / 卡住时的道具出口（v0.8.16 落地 B1）

无块可放时 `checkStuckAndPrompt()` 按剩余次数逐级降级：

| 剩余 | 行为 | 状态条 / toast |
| --- | --- | --- |
| `refresh > 0` | 提示换批，保持局面 | `No spot - use Refresh` / `No spot - try Refresh` |
| `refresh = 0`，锤/箭/弹任一 > 0 | 提示清理挡路格，**保持局面、不判死** | `No spot - clear a path` / 同上 |
| 四项全为 0 | `endGame()` | — |

- 为什么这样定：卡手在现行池里是常态（典型打法 99.7% 的对局会走到无块可放，见 [难度曲线](../Technical/DIFFICULTY_CURVE_POOL14.md) §4/§9），而三个清理类道具本来就**能在拥挤的面上开出空位**——在它们还有次数时判死，等于把道具做成装饰。
- 判定故意不做可行性检查：不扫描「这次清理是否真能开出合法落点」，也不做穷举。每次提示都指向一个可消耗的次数，所以既不会死循环，也不会出现"提示了但真的救不回来"之外的承诺。
- 这条规则对标 Block Blast 的续命/兜底（[竞品拆解](../Planning/竞品拆解-Block-Blast.md)、[难度曲线](../Technical/DIFFICULTY_CURVE_POOL14.md) §8.1）：**先给出口，再谈难度**。它与「道具没有获取途径」（§1.1）是两件事，后者仍未解决。
- 回归门：`npm run probe:rescue`（`tools/rescue-probe.mjs`）用 DEV 句柄造死局，断言三个分支 + 死局中锤子仍可武装；关掉 B1 分支后该探针必须失败（负对照已实测）。

## 3. 尚未实现的提案

### 3.1 B 规则

**B1 救局判定扩展 —— ✅ v0.8.16 已落地，见 §1.4 与 §1.5。** 原提案文本保留如下（实现与提案一致，仅补了两条实现口径）：

```
无块可放时：
  refresh > 0                 → 提示换批（现值，不变）
  否则 hammer|rocket|bomb > 0  → 提示「清理挡路格」，保持局面，不判死
  否则                         → endGame()
```

- 不承诺「一定能救」——是否真能开出合法落点由玩家判断；不做可行性穷举（3 面 × 25 目标 × 3 道具 × 3 候选块的正放姿态，成本远高于收益）。
- 不会死循环：每次提示都对应玩家可消耗的道具，耗尽后自然进入 `endGame()`。
- 实现口径（v0.8.16 补充）：①`hasBlockingClearTool()` 只看锤/箭/弹次数，不看它们是否真的能救，也不做盘面扫描；②提示沿用状态条 + toast 双通道，文案 `No spot - clear a path`，与换批的 `No spot - try Refresh` 区分；③`tools/rescue-probe.mjs`（`npm run probe:rescue`）用 DEV 句柄造一个死局，断言上面三个分支与「死局中锤子仍可武装」，并在**关闭 B1 分支的负对照下失败**——所以这条规则有回归门，不是靠人眼。

**B2 荣誉挂钩（需 08 同步）**：新增一枚「道具救场」类荣誉（如 `Second Wind`），并明确它**不计分**，维持 08 §5.4 的「主分不含道具」。

### 3.2 C 数值

| 道具 | 现值（初始/上限） | 提案（初始/上限） | 理由 |
| --- | --- | --- | --- |
| 换批 | 2 / 3 | 2 / 3 | 不变 |
| 锤子 | 1 / 2 | **2 / 3** | 单次只清 1 格，价值最低但最对症「差一格」，靠数量补足 |
| 火箭 | 1 / 2 | 1 / 2 | 清整条面线（≤5 格）为最强，保持稀缺 |
| 炸弹 | 1 / 2 | 1 / 2 | 4 格但跨 2 行 2 列，棱角共享带来邻面收益 |
| 合计 | 5 | **6** | — |

**纸面推导，未跑模拟**。落地前建议按 `tools/reachability.mjs` / `tools/rule-tests.mjs` 的既有方式实测道具使用率与救局成功率。`tools/rule-tests.mjs` 当前只校验存档钳制，不锁定初始配额，改 `ITEM_TOOLS` 不会直接破测。

### 3.3 局内获取途径（需与 08 联合定稿）

1. **消除里程碑**：每累计消除 N 条线（或每 X 分）随机补 1 个道具，按 `cap` 封顶。与现有消除链路同源，最容易实现。
2. **连击奖励**：单次落子消 ≥3 条线时补 1 个锤子，强化「连爆」正反馈。
3. **广告/每日补给**：CrazyGames 侧需要真实广告流程（当前未接入，见 [KNOWN_GAPS](../Technical/KNOWN_GAPS.md)），排在最后。

任何一条落地都必须同步 08：道具仍**不进入主分**。

### 3.4 D 表现

- 道具专属准星：锤子 = 单格描边、火箭 = 整行/列光带 + 方向箭头、炸弹 = 2×2 边框；
- 棱角共享可视化：作用域命中棱上格时，给相邻面叠加弱高亮，表达「这个面也会开洞」；
- 音效：三类道具各一套短音效（现仅有通用粒子与震动）。
- 镜头上暂不加推近，避免与消除反馈抢焦点。
