# VoxalBlast 核心规则与数值

> 版本：MVP v0.2.25

## 1. 棋盘模型

- 棋盘为**一个六面体（立方体）**，6 个面均参与放置。
- 每个面是一张 `5×5` 网格，坐标为 `u=0..4`、`v=0..4`。
- 方块**只能放在六个面的表面**；立方体**内部/中心不可放置**。
- 每格最多容纳一个方块单元；方块整体放置，不允许越过面边界或压到已占用格。
- 放置完成后方块固定在对应面上，并向外凸起一个单元厚度（BlockBlast 观感）。
- 玩家通过**旋转立方体**把目标面转到朝向自己后再放置。
- 一次手势只绕**一个**轴旋转立方体（v0.2.25 起，见 03 交互文档 §3）：水平滑动绕屏幕纵轴（Y）偏航、在六面体范围内上下滑动绕屏幕横轴（X）俯仰、在六面体范围外上下滑动绕屏幕法线（Z）自转。
- 旋转停稳后立方体**必定有一个面正对玩家**（允许每轴 8° 以内的轻微偏摆以保留立体感），因此"当前面"始终是唯一且可判定的放置面。自转（绕 Z）不改变正面朝向，只改变面在屏幕内的方位。

## 2. 消除判定

> **v0.3 修订（2026-09-11）：由「只检查当前面」改为「六面全检」。** 决策依据见 `08-荣誉与排行榜系统.md` §1/§3。

每次放置结束后，**扫描全部 6 个面**做行/列检查：

- 行线：固定 `v`，`u` 从 0 到 4 全部占用。
- 列线：固定 `u`，`v` 从 0 到 4 全部占用。

所有被填满的行/列在同一结算批次中消除。被多条线共同穿过的格子只删除一次，但每条完整线都计入本次消除数量。

**为什么必须六面全检**：六面体是 `5×5×5` 立方体的外壳，格子按立方体晶格坐标存储（见 `src/game/board.js`），因此**棱上的 1 格被 2 个面共享、角上的 1 格被 3 个面共享**。在棱/角上落子会同时推进相邻面的进度——若只检查放置面，会在别的面留下**已经填满却不会消失的线**，玩家必须再放一块才结算，规则不自洽。全检同时带来 VoxalBlast 相对 Block Blast 的独占维度：**一次落子可跨 2~3 个面同时连爆**。

## 3. 计分

基础分如下，实际手感测试时允许整体缩放：

| 同次落子消除线数 | 倍率 | 基础得分 |
| --- | ---: | ---: |
| 1 | ×1 | 100 |
| 2 | ×3 | 300 |
| 3 | ×6 | 600 |
| 4 及以上 | ×10 | 1000 起 |

> ⚠️ **本节已由 `08-荣誉与排行榜系统.md` §4 取代（v0.1 待拍板）。** 原表保留仅供当前 MVP 版本回查，新版本按 08 文档的四层计分（放置分 / 线分倍率 / 跨面倍率 / 连消链）执行。
>
> 核对时确认的两处问题：
> ① **上表与下方公式自相矛盾**——3 线按公式应为 `100 × 3 × 6 = 1800`，表中却写 600。代码 `board.js:72` 用的是公式口径（`100 * lines * multiplier`），即**代码对、表错**。
> ② **表格无上限**。单面 5×5 且拼块 ≤4 格且连通时，**单面一次消除线数的数学上限是 5**（4 格连通块不可能同时覆盖 3 行又 3 列）。写成"4 及以上"会让玩家误以为可以无限增长，破顶失去意义。

现行公式（与代码一致）：`本次得分 = 100 × 消除线数 × 对应倍率`。  
若同一次落子穿过多条线，优先展示“消除线数”，再展示倍率和累计分数。首版不做爆炸式多阶段连锁，专注于一次落子多线消除。

## 4. 方块池

方块为**平面 2D 拼块**（BlockBlast 式），系统给定固定朝向、玩家不可旋转。首版共 10 类（v0.2.31 起；`src/game/shapes.js`）：

- 单点 / 直线 2 / 直线 3（**v0.2.31 起最长直线为 3**：5 格直线在 v0.2.24 移除——面缩到 5×5 后只能落在完全空白的行/列上并立即成线，等于白送分数且几乎废掉 Game Over 判定；4 格直线由制作人拍板于 v0.2.31 移除——它是唯一占掉面内一行 80% 的拼块，只要能放下就读成"白送一条线"而不是选择）。
- 平面田字（2×2）。
- 平面 L / J / T / S / Z（四格）。
- 小型 L 转角（三格）。

## 4.1 开局局面（v0.2.31）

开局**不是空壳**：`Board.seedOpening()` 按 `OPENING_LAYOUT` 在**初始可见的三个面**预置方块——正面 +z **7 格**、顶面 +y **3 格**、右侧面 +x **3 格**（实测合计 15~18 格 ≈ 外壳 98 格的 15%~18%），方块**取自同一候选池**（同形状、同颜色），因此开局画面就是"已经开打"的棋盘。

- 目标是**每面的格子数**而不是"几块"：拼块 1~4 格不等，按块数预置会让同一份配置在"正面只有 2 格"和"正面 8 格"之间摇摆，开局因此忽空忽满。
- 正面承载主要密度、顶面与右侧面各放一点：3/4 视角下顶面的方块贴在天际线上，密度堆在顶面会读成"屋顶堆东西、正面空着"（v0.2.31 首版实测即如此）。

两条硬规则（在代码里强制，不靠调参）：

- **不重叠**：走 `canPlace()`，落在外壳合法格上；
- **任何面上都不得预置出已满线**：预置不结算，而 `place()` 只结算落子面，若在别的面留下满线会"满着不消"，玩家必须恰好又落那块面才结算。

预置**不计分、不消除、不改变回合**，HUD 仍从 0000 开始；开局候选方块至少有一个可放置（因为至少 3 个面完全空着）。

形状生成原则：

- 前期保证存在可放置位置，避免随机开局即死。
- 中后期提高填补缺口的机会，让玩家频繁遇到差 1～2 格成线。
- 不要求每一回合都能消除，保留空间规划压力。

## 5. 供给与 Game Over

- 每回合展示 3 个方块。
- 方块以系统给定的固定朝向供给，玩家不可旋转；只能通过**旋转立方体选面**后放置。
- 当三个方块在**任意面上都不存在任何合法放置位置**（立方体可自由旋转，因此需扫描全部 6 面）时，触发 Game Over。
- Game Over 面板显示最终分数和重新开始按钮。

## 6. 目标手感

- 开局节奏宽松，让玩家理解“选面 + 平面放置”。
- 中后期平均每 2～3 步出现一次差 1～2 格的候选线。
- 玩家应能通过在六个面之间切换与规划解决大部分局面，而不是依赖随机运气。
- 允许出现无解局，但无解应来自空间管理失误或可理解的供给结果。
