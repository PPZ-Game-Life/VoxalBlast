## 1. 当前已实现：页面、布局与状态

**启动入口（v0.8.22 改变）**：加载/刷新**直接进入单局**——有可玩快照就走 `continueRun()` 续玩，没有就 `beginRun()` 开新局，两者都以 `leaveHome()` 落地；**不再停在主页**。主页只从局内设置「回到主页」（`#home-setting` → `openHome()`）进入，它仍是"新游戏/继续游戏 + 最高分 + 排行榜 + 设置"那一屏，也是唯一会给未完局做快照的出口。`openHome()` 仍会把局内 `.topbar/.game-layout` 设为不可见且 `inert` 并保留布局尺寸，`refreshHome()` 的缩影仍由当前场景几何克隆生成，不是续玩存档截图。

局内 HUD 包含 SCORE、BEST、连击、操作说明和设置；中央为 3D 棋盘，候选区固定三槽，道具区四槽。版本徽标 `#app-version` **在任何构建下都显示**（`src/main.js` 只写文本，不再按 `import.meta.env.DEV` 隐藏）：它在旧版曾是 dev-only，手机上的正式产物因此看不到自己跑的是哪一版；窄屏只缩字号（≤460px `font-size: .5rem`），不设 `display:none`。主页覆盖时它随 `.topbar` 一起 `visibility: hidden`。

## 2. 当前已实现：翻面、方位与缩放

### 2.1 指针手势

从候选槽 `pointerdown` 开始的是拼块拖放；从画布开始的是视角手势，两者互斥（`beginDrag()`、`beginViewDrag()`）。

一次画布手势只锁定一个世界轴：

- 横向拖动：绕世界 Y 轴偏航；
- 在棋盘水平投影范围内纵向拖动：绕世界 X 轴俯仰；
- 从棋盘左右侧带开始纵向拖动：绕世界 Z 轴平面自转。

轴锁定不是首个像素立即决定：领先方向至少达到 `axisLockPx=16`，通常还需达到 1.2 倍方向优势；到 `axisHardLockPx=44` 仍接近对角时由较大方向接管（`gestureAxisReady()`、`pickGestureAxis()`）。右侧带下滑为顺时针，左侧带下滑为逆时针（`bandRollSign()`）。

逻辑姿态 `cubeBase` 只累计 90° 世界轴步进；偏航/俯仰方位 `bearingYaw`、`bearingPitch` 是玩家保留的微调层。释放规则由 `src/rendering/boardView.js` 的 `planAxisRelease()` 决定，v0.8.24 起拆成三条互不耦合的规则：

- **默认停靠角度 = 正对镜头（v0.8.26 定稿；v0.9.2 起改为「由相机派生」）**：`bearingYaw` = `ROTATE_STYLE` 里的 `CAMERA_BEARING_YAW` = `atan2(BOARD_STYLE.cameraDirection.x, cameraDirection.z)`——**当前相机方向 `[0.429, 0.208, 0.879]` → +26.0°**（`bearingPitch` = 0°），即正面**正对**相机的那一档。主面 **85.8%**、顶面 **14.2%**，两个侧面边缘朝向相机所以都看不到（0% / 0%）。它同时是微调区间的**中心**。
  - 为什么是正对：制作人两轮手机实测把它收敛到了这一句——"停下来的时候，我可以看到右侧面一部分……我想在停止的时候，能够看到右侧面和左侧面的面积应该一致"。**只要停靠偏离相机轴，两侧面就不可互换**：v0.8.25 的停靠（偏轴 8°）实测能拨出右侧面 20.4%，左侧面最多只有 0.3%；只有中心落在相机轴上的停靠，区间两端才互为镜像。
  - **v0.9.2 的教训（为什么现在不再手写这个角度）**：v0.8.26 把角度手写死成 `0.2793`（= 当时相机的偏航 16°），不变量藏在数字里；2026-09-24 的美术提交把相机方向改到 26° 却没动它，停靠就悄悄偏轴 10°——制作人 2026-09-25 复测报"往左微调看到的侧面比往右大很多"，`npm run probe:framing` 的 bearing 段同时报"停靠偏离相机轴"与"区间两端不是镜像"（静止 0.0% vs 10.0%、两端 0% vs 21.1%）。改成派生后这一类回归整体退役：**调相机，停靠自己跟着走**。
  - 实测（`npm run probe:framing` 的 bearing 段，v0.9.2）：**静止时两侧面 0.000% / 0.000%（差 0.000）**；拨到区间一端侧面 **10.0%** 落在画面中心**左**侧（x = −0.186），拨到另一端侧面 **10.0%** 落在**右**侧（x = +0.194），两端主面同为 **77.0%**——即"往任一侧拨多少，就露出多少，两侧完全对称"。
  - 附带好处：正对时正面与屏幕轴逐轴对齐，v0.8.6 以来那族"网格在屏幕面内旋转"的数字归零——24 朝向面内滚转离散 **2.27° → 0.01°**、正面网格线屏幕斜切 **−0.34…2.95° → −0.48…0.50°**。
  - 代价（说清楚）：静止时看不到任何侧面，深度感只剩顶面那条 **14.2%** 的檐（比 v0.8.26 相机俯仰 8° 时的 9.1% 更厚）。换来的是操作面最大（占轮廓 **85.8%**，而偏轴 10° 的停靠只有 77.0%）、正面网格完全不吃斜切（最好瞄准）、以及左右真的对称。注意这与 v0.8.6 被否的"正视停稳"不是同一件事：那次相机**俯仰也是 0**，连顶面都没有，才退化成平面网格。制作人 2026-09-23 看过实机后确认可以接受，2026-09-25 的复测再次确认这个取舍（要求本身就是左右对称）。
- **微调区间（左右对称）**：`ROTATE_STYLE.bearingMargin` = 偏航 **±10°**、俯仰 **±3°**，以停靠角度为中心、两侧同宽，所以偏航实际区间是 **+16.0°～+36.0°**（相对相机轴 ±10°）。两端主面 77.0%、侧面 10.0%、顶面 13.0%，互为镜像。±10° 不能再小：轴锁定在 `axisLockPx=16`（PC 上约 6.4°、390px 手机上约 9.4°），区间再窄就会被轴锁定吞掉，微调退化成一跳到位（该区间值 ±16.9° 手指行程）。±10° 不能再小：轴锁定在 `axisLockPx=16`（PC 上约 6.4°、390px 手机上约 9.4°），区间再窄就会被轴锁定吞掉，微调退化成一跳到位（该区间值 ±16.9° 手指行程）。
- **微调区内松手即保持**：区间内的释放保留玩家眼前的姿态，不回弹、没有第二段动画。
- **接近边界的阻力**：区间外沿不是硬墙。`ROTATE_STYLE.bearingResistance`（`free=0.4` / `wall=0.2`）让区间内侧 40% 1:1 跟手，之后响应逐渐变缓，越过边界后仍以 20% 的手指速度继续跟随——**是斜率、不是饱和**：饱和曲线会让立方体从约 40° 拖动起完全不动（实测姿态增量归零，探针 trajectory 段直接报"轴偏 90°"），翻面手势变成"卡住再跳"。由此"区间值多少手指行程"= **操作余量 1.69 × 角度余量**（偏航 ±16.9° 行程换 ±10° 角度，俯仰 ±5.1° 换 ±3°），左右同值——对称是**操作上的对称**，不是把参数改成 ±14°。
- **需要归位时的收敛**：拖动确实停在边界之外时，用 `bearingSettleDuration=0.16s` 的 `easeOutCubic` 收敛到边界、无过冲；不会像 v0.8.23 那样在松手的那一帧里把玩家拨出的角度直接截断。
- **换面门槛与微调偏移分开**：翻面由**本次手势自身的拖动量**决定（`|angle| ≥ stepThreshold=0.52rad` ≈30°），与当前方位无关，因此左右换面的操作距离一致，且在任意方位都翻得动（v0.8.23 以前判定用的是 `|方位 + 本次拖动|`：从正视边界翻面只要 24.8°，从 3/4 边界要 44.8°，正视边界到阈值之间还有一段"拖了不动"）。
- **换面后保留方位**：翻面只翻转 `cubeBase`，玩家调好的方位原样带到下一个面。
- Z 轴不保留残余方位，只会翻 90°或回到网格姿态；
- 非微调释放（翻面）使用 `easeOutCubic`、0.22 秒球面插值，无过冲。

相机当前为弱透视参数：桌面 FOV 6°、移动端 7°，方向 `[0.429, 0.208, 0.879]`（偏航 26°、俯仰 12°）；竖屏另乘 `portraitCubeScale=0.86`。滚轮按 0.92/1.08 倍缩放并钳制在 `cameraZoom=0.7..1.7`；当前没有独立镜头复位按钮。

### 2.2 键盘

`W/S` 绕 X，`A/D` 绕 Y，`Q/E` 绕 Z；映射来自 `axisForKey()`。按住不连发（`event.repeat` 被吞掉），一次按键触发一次四分之一转。

操作说明卡打开时，六个键只驱动说明行里的迷你方块，真实棋盘保持暂停。正常局内按键成功后会短暂显示“键帽 + 轴 + X/Y/Z”提示。

**边界：道具瞄准态下 `handleRotateKey()`（`src/input/gameInput.js`）会因 `itemActive` 返回，故 W/S/A/D/Q/E 当前不能转面；此时只能在画布上拖动转面。** R/C 仍可在火箭瞄准态切换 Row/Col。旧文档中“瞄准态键盘也可转面”不是当前实现。

## 3. 当前已实现：候选拖放与取消

候选槽按下后，移动不足 6px 仍按点击选择处理；越过阈值才进入实际拖拽。拖动时：

- 画布外/棋盘外显示随指针移动的手持拼块；鼠标固定抬升 10px，触摸抬升为 12px + 拼块屏幕高度一半，上限 120px（`DRAG_GHOST`，抬升算法唯一真源 `dragGhostLiftPx()`）；
- 指针进入棋盘轮廓（+`snapMarginPx` 18px）内即吸附：手持拼块隐藏，改在**目标面**上显示落点预览；一个回合里画面上只存在一个方块；
- **吸附 = 直接映射**（v0.8.27）：把手中拼块的**包围盒中心**（= 指针位置 + 上面的抬升）投到该面上，得到连续的形状原点；**不做"面内最近合法位"搜索**。大拼块因此落在手上那个位置（最多被面边界截断到最近一格），不会凭空跳到面内别处；指针离开轮廓再回来时重新按当前位置吸附；
- **目标位置与合法性分离**（v0.8.27）：预览始终停在指针当前对应的格子，位置由 `ndcToCell()` 的浮点 `fu/fv` 逐帧累加、每帧立即截断到面内；压到已占用格只把预览染成非法色 `RENDER_PALETTE.invalid`，**位置照常跟手**，离开占用区立刻恢复拼块自身颜色。旧实现"非法即沿用上一个合法格"（粘滞）已废除；
- 只有面边界限制移动：越界位移当场丢弃、不累积（反向拖动只保留正常的半格换格阈值，没有要还的"空行程"）；已占用格不阻挡移动；
- 吸附后目标面与拼块在该面上的朝向在本次拖拽内锁定；`beginDrag()` 会先 `settleCubeSnap()` 结算未完成的旋转归位动画，避免坐标基准中途变化；
- 松手只提交当前预览对应的合法落点（`pointerup` 的最终坐标走同一套规则再算一遍），不会在释放时重新搜索其他合法位；当前非法（或不在面上）则消耗 0、退回候选条，且**不会回落到之前的合法位置**；
- 合法预览使用候选拼块自身颜色，非法态使用 `RENDER_PALETTE.invalid`；
- 候选条与道具条共同构成取消区，拖回后释放不消耗拼块、不计分；
- `Esc`、右键、`pointercancel` 和打开设置可取消候选拖拽。

### 3.1 块块推不动时，立方体跟着拖的方向翻面（v0.9.3 起；v0.9.4 泛化）

**手指不换手、不松手**：块块贴在立方体上时，同一个手势可以从「移动块块」转成「转立方体」，转完继续拖/松手就是正常落子。两个触发条件、同一个动作：

1. **这个面整面都放不下这块**（v0.9.3）：`Board.anyPlacementOn(face, cells)` 在该面上以拼块当前朝向枚举所有原点，没有任何合法落点时，本次拖拽立即进入待转态（状态文案 `No room — drag to turn`）。判断依据是「整面无位」，**不是**「手指当前这一格被占」——后者仍走 v0.8.27 的"预览跟手 + 变红"，不会触发翻面。
2. **块块被推到面边界、手指还在往外推**（v0.9.4）：这一条**不限面、不限方向，也不需要这个面没位**。块块一旦停止跟手（`clampOrigin()` 正在丢弃手指位移，也就是 `drag.push` 有了非零值），继续推满 `PIECE_SPIN.pinPx`（26px，按**面自身轴**的屏幕投影计算，`src/rendering/config.js`）就翻一面。

共同点与差异：

- 条件 1 会在吸附瞬间进入待转态但**姿态不动**：还要拖满 `PIECE_SPIN.startPx`（26px）才允许认轴，再叠加旋转原有的 16px 轴锁，最后拖满 30°（`ROTATE_STYLE.stepThreshold`）才真正翻面。所以「把块块推上一个满面」这个动作本身不会把立方体翻掉；翻面在手势进行中提交，落点标记锁在原面、跟随该面一起转过去，姿态落定后才在新正面重新吸附。
- 条件 2 是**一次性**的：块块本来就没跟手，所以推满 `pinPx` 就直接翻一面（一次手势一面，和键盘一次按键一面同规），不存在"边推边慢慢转"的半个姿态。
- 两条都**只认水平（yaw）/垂直（pitch）**，不含左右侧带的内平面自转（自转既打不开位置、也移不动块块）。
- **普通拖拽永远不触发**：块块还在跟手的那些帧里，`drag.push` 恒为 0（v0.8.27 的"滑过已占用格"照旧成立，跨面横拖也不会翻）。这是本功能唯一不能踩的底线，由 `probe:drag` 的 K 段直接断言。
- 条件 2 的推力必须**在立方体轮廓内（+18px 吸附边距）完成**：从面边界到轮廓只剩约 36px（430×900 实测），`pinPx` 26px 落在里面。这段越界是「把块块拖离立方体」的既有语义，`指针离开轮廓 → 块块回到手上` 没有为了本功能放宽——真放不下这个约束，宁可让阈值变小。
- **代价（制作人明确选择的通用规则带来）**：块块停在面边界后**再多推 26px 就会翻面，而不是干停在边上**。因此「把块块放在最边上一格」这件事要在推到边界时停手或直接松手；超推半个格子会被判成翻面。`PIECE_SPIN.pinPx` 是唯一的调参旋钮（觉得容易误翻就调大）。对应地，C 段的"边界无空行程"回归**只在 `pinPx` 以内成立**，探针的边界走查已按这个窗口收口，超过窗口的行为由 K 段钉住。
- 转完若新正面放得下，继续拖动/松手即为正常落子；若仍放不下，继续拖可再翻。松手时若归位动画仍在飞，会**先结算到位再按同一套规则判一次落点**，避免"刚好在动画里松手"吞掉这一回合。
- 松手时若指针已在立方体轮廓之外，按普通非法释放处理（消耗 0、退回候选条）；`Esc`、右键、`cancelActiveDrag`、`resetDrag` 都会把未提交的旋转姿态交还给 `boardView`，不会留下 `getLive()` 非空的死姿态（那会让之后的 W/S/A/D/Q/E 全部失效）。

落点使用当前画面朝向推导出的拼块格形；结算使用预览阶段已经确定的 `currentDrag.cells`，避免释放时重新计算造成所见与落点不一致（`finishDrag()`，`src/input/gameInput.js`）。

上述行为的回归门是 `npm run probe:drag`（`tools/drag-feel-probe.mjs`，A–K 共 67 项，v0.9.4 实测 66 通过 / 1 失败 / 0 跳过）：吸附映射与 1:1 跟手、跨占用区移动+变红+恢复、两条面边界的"无空行程反向"（在 `pinPx` 窗口内）、非法松手不消耗/不回落、释放坐标判定、触屏与转面后的方向一致性，以及 §3.1 的两条翻面路径（J 段：整面无位；K 段：块块推不动）。反向断言有两条——"到达满面不会自己翻/能放下的面不会被翻"（J）与"还在跟手的块块永远不会触发翻面"（K）。唯一失败项是既有的 I 段「部分溢出停在请求的边上并变灰」，已在**改动前的基线**上原样复现，与 §3.1 无关；结论与待裁决口径见 [04 v0.9.3 条目](04-MVP验收清单.md)。

## 4. 当前已实现：暂停、续玩与局终

`syncPause()` 的暂停来源为主页、页面隐藏、局终、设置、操作说明，以及**开场创建波次进行中**（见 §6）。打开主页/设置会清理候选拖拽和道具瞄准；页面隐藏还会清理候选拖拽、道具瞄准、道具撤销窗口及旋转手势，保存未完局，并让进行中的开场波次直接结算到位。

窗口 `blur` 当前只调用 `cancelViewDrag()`（`src/input/gameInput.js`），不等同于完整的候选拖拽/道具状态清理；不要把它写成所有输入都已覆盖的失焦暂停流程。

未完局快照键为 `voxalblast.session.v1`（读写经 `src/game/session.js`，已结束局纪录经 `src/game/records.js`，两者的底层存储边界都在 `src/platform/storage.js`），保存：

- 棋盘晶格、分数、总消除线；
- 三个候选及已用状态；
- 四种道具次数；
- 连击、局内最佳、荣誉及点亮面等运行统计；
- 逻辑姿态与玩家方位。

快照在落子、道具成功、换批、撤销、回主页、页面隐藏等状态变化后写入。`localStorage` 不可用时退化为当前页面会话内存续玩；刷新/关闭后的持久化不作保证。Game Over 先写已结束局纪录，再清除续玩槽；重新开始会创建新局、重置道具、荣誉运行态及方位。

## 5. 当前已实现：反馈

落子结算顺序为：全六面满线判定 → 连击 → 荣誉 → 分数 → 反馈（`settlePlacement()`）。

- 无消除 L0；单线 L1；双线 L2；三线 L3；四线或三面 L4；五线以上，或四线且三面，为 L5；
- L5 的 0.6 倍/400ms 只影响动画时钟，输入逻辑不读取慢放状态；
- 分数跳字、连击提示、荣誉横幅/徽章、音效、触感、线光束、星星和粒子由现有事件调用；
- 声音和触感可分别关闭，但触感是否发生仍取决于浏览器/设备能力；
- 画布由 `ResizeObserver` 跟踪容器尺寸并重算投影与缓冲区。

荣誉、分数和排行榜边界见 [08](08-荣誉与排行榜系统.md)，道具瞄准与死亡前救场见 [07](07-道具系统设计.md)。

## 6. 当前已实现：进入单局的开场动画（v0.8.22 两阶段版）

进入一局时六面体不是瞬间完整出现，而是**先被造出来、再被上色**：一道按屏幕空间“左下 → 右上”的斜向波次先把 98 个表面格块建出来并刷上**底漆**，停一拍，然后同一道波次再走一遍，把每块刷成**它在这局里真正的颜色**。参数集中在 `src/rendering/config.js` 的 `INTRO_STYLE`，实现集中在 `src/rendering/boardView.js` 的 intro 区块（`armIntro()`、`updateIntro()`、`settleIntro()`）。

- **触发**：`leaveHome()`（启动/刷新直接进局、主页开新游戏或继续游戏）与 `beginRun()`（设置里的重新开始、结算面板的再来一局）。启动时不再有主页覆盖，所以**刷新一次就播一次**；`armIntro()` 每次都先 `settleIntro()`，任何时刻只有一轮（`__voxalblast.intro().plays` 记录本次加载播放过几轮）。
- **排序**：在**第一帧真正可见时**把每个格块的世界坐标投影到屏幕，取 `(x + y) + depthBias·z` 排序，`x`、`y` 为 NDC（`+y` 向上）。深度项让远面比近面晚约一个节拍，波次因而**一次横扫当前可见的多个面**，不是六个面各自播放。两阶段共用同一顺序与同一波带划分：第二节是"同一道波又走了一圈"。
- **第一阶段「上底漆」**：格块从各自格子里沿**该块面的法线**（棱/角块是相邻面法线的合成，即立方体径向）从内缩 `inset=0.42` 飞出，`opacity 0→1`、`scale 0.72 → 1.04 → 1`（0.62 处达峰后只回落，不振荡），单块 `build.duration=0.30s`，相邻波次 `build.bandStagger=0.042s`，共 26 个波次。这一阶段**画面上不允许出现任何游戏色**（木色与候选池漆色都不行）：底漆是**同一族三档冷灰蓝** `#7d8b9c / #93a1b2 / #a9b6c5`，按格块在立方体上的**高度分档**（底档最暗、顶档最亮），从上色、粗糙度、清漆都统一成一"遍漆"，读起来是一整块被打了底的木玩具，而不是"把颜色关掉的正式棋盘"。改成单色只要把 `primer.colors` 留一项。
- **停一拍**：`hold=0.22s`，底漆状态的立方体完整、静止地站住，让两阶段在观感上分开。
- **第二阶段「上色」**：同一波次再走一遍，每块用 `build` 期的同一顺序、`paint.bandStagger=0.038s` 错峰，单块 `paint.duration=0.26s`：`color` 从自己的底漆色**线性插值到它自己的正式色**，`roughness/clearcoat/bumpScale` 同步回到该材质原本的值，并有一次 `scalePulse=1.05` 的"盖印"脉动。已占用（彩色）格块晚 `occupiedDelay=0.05s` 上色，并且是**唯一**会获得 `shine=0.22` 亮度提升的格块（低于 bloom 阈值 1.35，不产生辉光），落地前归零。**正式色不是算出来的**：每块的终点取它进场时那件材质自己的 `color`，所以续玩/旧存档的颜色就是保存里的颜色。
- **整段时长**：`total ≈ 2.83s`（第一版 v0.8.21 的单阶段是 1.05s；按"太快、看不清"的反馈拉长并拆成两阶段）。
- **结束**：`settleIntro()` 从 arm 时保存的副本显式恢复 transform 与**共享材质实例**（不是动画用的逐块 clone），`color/roughness/clearcoat/bumpScale/opacity/emissive` 一并回位，再走一次 `applyTileMaterials()`；结束后格块的位置、尺寸、颜色、材质与齐平状态与动画前完全一致。
- **输入**：播放期间由 `syncPause()` 统一上锁（旋转、拖拽、放置、道具、键盘同一把锁），播完统一解锁。
- **取消**：回主页（`openHome()`）与页面隐藏会直接结算到位；连续重开时先 `settleIntro()` 再开始。实现只用 rAF 循环驱动，没有 timer 或 tween，不会残留。
- **减少动态效果**：`prefers-reduced-motion: reduce` 时为 0.18s 的**整盘淡入直接落到正式颜色**——不播底漆、不做逐格弹性、不移动也不缩放任何格块（arm 时读取该偏好）。
- **不写入规则层**：动画只读棋盘已经生成的 `occupiedColors`、格块自身变换与相机，不复制第二套棋盘状态、不逐格改游戏数据，也不改判定棋盘颜色的那份材质；`__voxalblast.intro()` 提供只读回读（阶段、每个格块的底漆/正式标记、位置/缩放/材质完整性计数）供自动化核对。

## 8. 道具交互重设计 v1（待实施，不覆盖上文实现事实）

完整规则与边界以 [07 道具系统](07-道具系统设计.md) §8 为唯一详细口径；本节同步全局输入约束，验收见 [04](04-MVP验收清单.md) 新版道具交互段。只改交互，不改四道具功能、次数、计分或救场规则。

- **锤子/火箭/炸弹主路径：图标按住拖出 → 范围预览 → 有效处松手使用。** 不是“先点道具，再在棋盘随便轻点就结算”。持续按住不自动生效、不蓄力；空目标/非法处释放回弹退出且无消耗。
- **轻点备用路径：点图标 → 点/滑动选目标 → 松手固定预览 → 点 `使用 · −1`。** 重新点棋盘只换目标；移动到确认按钮不改已锁定范围。两条路径按手势起点区分，拖完吞掉合成 click，防止自动再选中。
- **取消统一：** 拖拽时整个候选区与道具条分别成为大取消区，显示 `拖到这里取消 / 松手取消`；分离布局按两个矩形的并集，不能覆盖中间棋盘。常驻状态条有 `× 取消`，非拖拽时可再点同一道具退出；保留 Esc/右键。拖经其他道具不切换。候选槽只弱化/隐藏内容、不改占位。
- **瞄准时不转面：** 进入道具模式后锁候选拖放、画布转面、W/S/A/D/Q/E 和缩放；要换面先取消、转好、再选。第二指不接管，转面动画未停稳不允许拿道具。普通态的转面和候选操作仍按上文，不修改普通棋盘手势。
- **预览可解释：** 只选当前正面网格；范围边框含空格，实际清除实体强描边，数量按共享晶格去重。主动瞄准时移出正面立即去掉有效预览，不能沿用旧 hover；轻点路径固定目标后去点“使用”不清预览。提交只用已显示且仍有效的快照。触屏主拖放的靶心抬升与落点用同一坐标，轻点备用路径按实际点下位置命中、不抬升；原始手指命中取消区优先。
- **道具差异：** 锤子显示 1 格；火箭显示 5 格行/列，方向由横/纵按钮或 R/C 明确切换，不再随格内偏移自动跳；炸弹显示实际 2×2 范围、锚点、清除数及边缘裁切，棱角仅提示共享实体，不扩散到邻面。
- **换批是两步点击：** 候选区内嵌 `换一批 · −1 / 保留当前` 确认；不支持拖到棋盘，确认前不扣次数、不抽随机数，确认后仍整批换成 3 块，不承诺可放。
- **中断安全：** 未提交时 pointercancel、意外丢捕获、失焦/隐藏、设置/主页/结算、重开、尺寸变化统一取消；恢复不补发、不自动选中。提交后的中断不退款。现行窗口 blur 只取消转面的事实仍见 §4，不能把该目标写成已经补齐。
- **界面底线：** 状态条不遮棋盘，取消/确认/方向按钮至少 44×44 CSS px，推荐 48×48；窄屏换行，不缩成难点的小叉。清理成功保留 3 秒撤销及现有失效条件，换批仍无撤销，不新增死亡后回退。

此方案替换的是道具模式里的旧手势，不与 [07](07-道具系统设计.md) §2 的“轻点结算/拖动转面”同时保留。所有新交互与触屏手感均待实现后验证。
