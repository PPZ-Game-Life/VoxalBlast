# VoxalBlast 交互与表现需求

> 版本：MVP v0.4.2
> 平台优先级：PC 优先，竖屏移动端完整兼容

## 1. 平台与响应式布局

- PC 是首要交互平台，优先保证鼠标拖拽、镜头视角观察与精确吸附的手感。
- 竖屏手机必须提供完整可玩的触摸方案，不能仅将 PC 布局等比缩小。
- PC 端棋盘、方块供给区、分数和重开入口不得互相遮挡。
- 竖屏端建议将棋盘置于上方或中部，方块供给区置于下方，分数和重开入口固定在顶部。
- 触摸控件要有足够点击面积，核心流程不能依赖悬停提示或键盘快捷键。
- 屏幕旋转、窗口缩放和浏览器安全区变化时，棋盘仍需完整可见并保持可操作。

## 2. 页面布局基线

### PC 横屏布局

采用顶部信息条 + 大棋盘 + 底部候选条的 Block Blast 式结构：

- 顶部一行紧凑排布：左侧 SCORE 积分胶囊、右上单一设置图标；开发版版本号以正中小徽标悬浮（脱离布局流，正式版移除时不影响其他元素位置）；不显示游戏名。
- 中央：主 3D 棋盘占据绝大部分可视高度，保证完整可见且不留大片空白。
- 棋盘下方自上而下两行：先横向排列 3 个固定朝向的候选方块，再排列 4 个道具图标（参照 Block Blast 的自下而上视觉层级）；候选与道具区合并作为统一取消放置区。
- 底部操作区不得覆盖棋盘，也不得压缩棋盘到无法辨认。
- 设置面板包含 Sound、Haptics、Restart Game（不提供镜头复位）。

### 竖屏手机布局

- 顶部平台栏：游戏内顶部与桌面一致，只保留版本徽标（窄屏隐藏）、居中 SCORE 积分胶囊与右侧单一设置入口。
- 顶部平台栏下方自上而下：候选方块一行、道具图标一行；候选区即主要触摸拖拽起点与取消放置区。**（v0.2.25 起按现状写入：窄屏下候选与道具行位于棋盘上方，取消卡片也出现在屏幕上部；桌面端仍是棋盘在上、候选在下的 Block Blast 层级。）**
- 中央：完整 3D 棋盘（六面体）铺满剩余可视区域，优先保证棋盘可操作和落点可读；取景按"充满但不裁切"收口，六面体是主要的触摸操作区。
- 方块供给区与棋盘保持明确间距，拖拽时不能被其他 UI 截断。
- 声音与触感开关统一收纳在设置面板，避开系统安全区。
- 手机版只使用局内配额型道具，不加入参考图中的金币、商店、弓箭、炮台等商业化道具系统。

### 参考范围说明

参考图仅作为布局和信息层级参考：保留“左侧状态、中央棋盘、右侧操作区、右上角设置”的结构；不照搬其中的金币、免费道具栏、8×8 平面棋盘或其他与 VoxalBlast MVP 冲突的系统。

## 3. 视野与镜头

- 默认展示完整立方体，棋盘（六个面的网格）不得被 UI 遮挡。**六面体是主要操作区**：取景按"尽量充满中央操作区"放大（目标：PC 竖向占中央画布约 8 成、移动端横向占约 8 成），只在左右两侧保留可触达的自转手势带。
- 中间 3D 操作区拖动用于**旋转立方体**（而非相机）；桌面端鼠标和移动端触摸均可使用。旋转不改变棋盘、方块或放置规则。
- **手势轴固定在世界（屏幕）坐标上，绝不跟随六面体（v0.2.27 起，核心规则）**：三个轴分别是**世界 Y（偏航）/ 世界 X（俯仰）/ 世界 Z（自转）**，每次手势都是"先把六面体停稳，再以当前姿态为基准、绕这个固定轴转 90°"。也就是说：先偏航到某个侧面再上下滑，仍然是"绕屏幕横轴把当前这个面翻上去/翻下来"，而不是变成绕 Z 自转；先自转 90° 再左右滑，仍然是把左右面转过来。
  - ⚠️ v0.2.25~v0.2.26 用三个欧拉角分量（pitch/yaw/roll）分别累加，一个手势的**实际转轴会随另外两个角变化**（例：偏航 90° 后，上下滑动变成绕 Z 的平面内自转，正对的面根本不变），玩家会读成"XY 轴跟着六面体一起转了"。**这是缺陷，回归时按下面两条断言复核。**
  - 回归断言（见 04 验收清单）：任意姿态下，一次手势产生的姿态差 `ΔQ = base_after · base_before⁻¹` 必须**精确**等于绕对应世界轴的 90° 旋转（探针实测 `angle=90.0000°`、`axis=[0,0,±1]` 等，误差 < 1e-9）。
- **单次手势只认一个轴（v0.2.25 起）**：手势起手后取位移较大的那个屏幕方向定轴，整段手势只驱动该轴、**不做斜向合成**，另一轴的角度保持起手时的姿态。
  - **定轴判定（v0.2.29 修正，`src/rendering/swipe.js`）**：不能只看起手最初那几像素——手指起手常带几像素侧向抖动，若按 6px 处的位移定轴，一次正常的上下滑会被判成"偏航"，而"已定轴的手势忽略另一轴"，于是整段下滑被丢弃、六面体完全不动（玩家报"有些时候转不动，像锁住了"）。现在必须等**领先方向明确领先**（`axisDominance` ≈1.2 倍）且位移过 `axisLockPx`（≈16px）才定轴；一直不明确的滑到 `axisHardLockPx`（≈44px）后按"谁大谁定"兜底。**定轴前的每一帧都重新判定**，所以起手慢不影响手感（角度始终从按下点起算），定轴后不再切换。
  - **左右滑动 → 绕屏幕纵轴（Y）偏航**。
  - **上下滑动 → 按起手落点分区**：起手 x 落在六面体**水平范围以内** → **绕屏幕横轴（X）俯仰**；落在六面体**水平范围以外**（左右两条窄带）→ **绕屏幕法线（Z）自转**（屏幕平面内旋转）。分区在按下时采样一次，手势中途不切换含义。
- **旋转方向**：立方体朝**手指滑动的方向**转，即"手指往前推、当前正对玩家的那个面就跟着往那个方向走"。右滑 → 正面往右走（左面转到前面）；下滑（六面体范围内）→ 正面往下走、顶面转入视野；下滑（左右窄带）→ 屏幕平面内顺时针自转。方向值集中在 `ROTATE_STYLE.yawDirection / pitchDirection / rollDirection`，要改方向只改这三个符号。
  - ⚠️ v0.2.26 曾把三轴方向整体取反（当时误判为"方向反了"），v0.2.27 已改回。**以后再报"方向反了"，先查"手势轴是否跟着六面体转"，不要直接翻符号。**
- **松手判定（v0.2.24 起，取代旧的"吸附到最近 90°"）**：一次手势在该轴上**最多翻一个面**。拖动角度超过阈值（约 30°）→ 直接转到**下一个面**；未超过阈值 → 弹回起手时的面。**角度的换算标尺（v0.2.29）**：`角度 = 位移 / 六面体自身在屏幕上的投影尺寸 × π`（定轴时采样一次），即"滑约 1/6 个六面体 = 翻一面"；旧的画布标尺（`位移 / 画布尺寸 × π`）让同一次翻面在 390px 手机上只要 65px、在 1120px 桌面画布上要 185px，桌面端正常一滑常常直接弹回（"有时候转不动"）。定轴前不产生任何角度。
  - **拖动中看到的旋转量 = 松手后兑现的量（v0.2.30，核心）**：手势进行中渲染的角度被限制在"起手姿态 ± 一个面"之内（`setLiveAngle()` clamp 到 `ROT_STEP`），而松手判定同样最多一个面——两条路径从此一致。**唯一会弹回的只有未过阈值的短滑**（角度 < 30°，即"轻点不翻面"），不存在"手指划出一整面、松手又转回去"的情况。
- **手势状态不会因丢失 pointerup 而卡死（v0.2.29）**：页面隐藏、窗口失焦、触摸被浏览器手势抢走时浏览器不再补发 `pointerup`，若 `viewDrag` 残留会永久拒绝新手势（旋转彻底失效、放置仍正常，观感就是"锁住了"）。现在 `visibilitychange`（隐藏）、窗口 `blur`、Reset 以及"按下时发现捕获已丢失"都会结束手势并把中途姿态停稳。
- **俯仰不再限位（v0.2.30 撤销 v0.2.25 的 ±90° 限位）**：三个轴一律"一次手势翻一个面"，俯仰可以连续把六面体翻过极点、把背面转到前面（`+z → +y → −z → −y → +z`）。旧限位在"固定世界轴 + 四元数网格姿态"下已没有保护对象（它原本只是旧欧拉模型的 ±90° 夹取），实际效果却是**手指已经转出来的一整面在松手时被拒并弹回**——玩家报"中心区域上下滑动，松手前转动了、松手后弹回去"（探针实测：重复下滑拖动 105.5° → 弹回 89.5°，且该方向此后永远无效）。**任何轴、任何姿态下都不存在"滑了不生效"的方向。**
- 停稳姿态固定为"某个面正对玩家"，并保留拖动溢出量形成的**轻微偏摆**：**偏航与俯仰每轴上限约 8°**（让立方体仍读得出立体感，而不是一张摊平的平面）；**Z 自转是显式归正动作，不允许任何残留偏摆——必须清除此前 X/Y 手势留下的展示偏摆，并精确落回 90° 网格**（v0.2.28）。否则即使本次 `restOffsetRoll = 0`，组合手势后仍会看到"歪着的面"。自转的弹性手感由停稳动画的轻微回弹（`snapOvershoot`，约 4%）提供，而不是靠留偏摆。Z 自转不改变"哪个面朝前"，只改变该面在屏幕内的方位。
  - 实现要点（v0.2.27）：**网格姿态用四元数 `cubeBase` 累乘整 90° 台阶**（永远待在 90° 网格上、永不漂移），8° 以内偏摆单独放在 `cubeRest*`，渲染姿态 = 偏摆 ∘ base；停稳动画用**四元数 slerp**（而不是三个角度插值），因此"手势停在任意姿态 → 落到网格姿态"这条路径总能平滑走完，且终点按位精确。v0.2.28 起 Z 停稳终点直接为 `cubeBase`，`cubeRestYaw/cubeRestPitch` 同时清零。
- 手势若在吸附动画播放中重新按下，动画立即结算到目标姿态再开始新拖动，避免两套角度互相覆盖。
- 支持滚轮拉近/拉远缩放（作用于相机）；不提供方块旋转入口（X/Y/Z 按钮与 WASD 方块旋转已移除），也不提供镜头复位（VIEW RESET / RESET VIEW / R 键已删除）。
- 视角/立方体旋转与候选方块拖拽必须互斥：从方块槽开始的手势用于放置，从中间 3D 区域开始的拖动用于旋转立方体选面。
- 立方体旋转应平滑，放置过程中不能突然改变落点解释。
- 被遮挡的已放置方块位于立方体背面，可降低不透明度或允许按面淡出。
- 棋盘边界、每个面的格线和格隙应足够清楚，不能只依赖颜色区分；当前朝向前面的面网格可作高亮以提示放置面。

## 4. 方块拖拽

- 鼠标按下方块后进入拖拽态，方块跟随光标移动。
- 只有**当前朝向玩家的那一个面**（立方体旋转选中的面）是有效放置面；方块吸附到该面的最近网格坐标，并向外凸起一个单元厚度。
- 光标接近合法位置时自动吸附到最近网格坐标。
- 合法落点显示半透明预览；非法落点显示明确的红色或警示态。
- 松开鼠标或结束触摸时才确认放置，拖拽取消不得改变棋盘。
- 预览状态要能显示完整方块轮廓，不能只显示接触面的单个格子。
- 开始拖拽任意候选方块后，整个候选方块区切换为统一的“取消放置区”，其他候选方块暂时隐藏或弱化且不可选择。
- 取消放置区使用清晰的 `×`、回退图标或 `Cancel` 状态提示，并保留覆盖整个原候选区的大尺寸命中范围。
- 拖动中的方块进入取消区时，取消区增强高亮并显示吸附反馈；在该区域松开即取消，方块平滑回到原槽位。
- 主动取消、在棋盘非法位置松开或拖拽中断都不消耗方块、不计分、不推进回合，也不触发消除或 Game Over 判定。
- PC 端可用 `Esc` 或右键作为备用取消入口；PC 与手机版的主要取消方式均为将方块拖回整个候选方块区。

## 5. 方块朝向与候选预览

- 备选方块由系统以固定朝向提供，玩家不可旋转；X/Y/Z 方块旋转按钮与 WASD 方块旋转均不提供。
- 候选槽位显示**平面正视**的小型方块组合：方块以 2D 拼块形态、正面朝向玩家展示（复用棋盘圆角几何与统一光照），与在放置面上的朝向一致，且不随立方体旋转而改变角度。
- **放置朝向以"当前正对玩家的那个面"为基准（v0.2.28 修正坐标语义）**：候选形状使用左上原点，`+u` 指向候选卡片右侧、`+v` 指向候选卡片下方；拖拽时必须把这两个方向重新表达为当前面上的**屏幕右 / 屏幕下**（`faceOrientedCells()`），而不是把 `+v` 错映射到屏幕上。
  - 不管立方体绕 Z 转了多少，方块落到正面上的**视觉轮廓与候选区显示完全一致**，L/J/S/Z/T 等非对称块不得上下翻转或镜像；
  - 中立姿态下也按"右 / 下"这一屏幕语义映射，不能用面自身 (u,v) 是否恒等代替视觉验收；
  - 立方体转动时方块**不会跟着一起转**——转的是面，方块始终按玩家在候选卡片看到的方向落。
  - 反面要求：按面的固定 (u,v) 放置会在 Z 自转后跟着面转；把 `+v` 当作屏幕上则会让候选轮廓上下颠倒，两者都属于缺陷。
- 拖拽中候选线与落点预览按方块当前朝向判定；由于不提供旋转操作，不存在"旋转后越界"的额外分支。
- 因为立方体可自由旋转（6 面 × 4 个平面内朝向都可达），"还有没有位置可放"必须按**4 个平面内朝向**判定（`Board.anyPlacement()`，v0.2.26 起），否则只差一个侧向朝向能放时会误判 Game Over。
- 观察维持恒定比例：旋转立方体时棋盘大小不随朝向变化，仅通过滚轮缩放调节远近。

## 6. 候选线提示

- （当前版本暂未实现）对差 1 格或差 2 格的完整线显示高亮候选点，作为未来增强保留。
- 候选提示采用呼吸或轻微闪烁，不得持续强亮造成视觉噪音。
- 候选线只作为辅助，不替玩家自动选择方块或落点。
- 当当前拖拽方块能补齐候选线时，可提高该线的高亮优先级。

## 7. 消除反馈（v0.3.0：五档反馈 + 荣誉播报 + 连消链）

一次落子完成后按以下顺序反馈：

1. 方块固定并短暂强调落点。
2. 完整线高亮，区分方向（当前为行线/列线）。
3. 线和方块格子同时消失。
4. 播放粒子、短促镜头震动和分数跳字。
5. 显示"几线消除"与倍率；跨面时补一行 `M FACES`；命中荣誉时补一行名号。
6. 棋盘恢复可操作状态，进入下一回合。

### 7.1 五档强度（档位由规则判定，数值集中在 `src/game/config.js#FEEDBACK_STYLE`）

| 档 | 触发 | 时长 | 震屏 | 粒子 | 音效 | 播报 |
| --- | --- | ---: | --- | --- | --- | --- |
| **L1** | 1 线 | 0.35s | 轻 | 基线 | 单音 | 仅 `+分` |
| **L2** | 2 线 | 0.6s | 中 | ×1.6 | 双音 | 小字 |
| **L3** | 3 线（`TRIPLE`） | 0.9s | 强 | ×2.4 | 和弦 | **名号横幅** |
| **L4** | 4 线（`QUAD`）或 3 面（`TRIFACE`） | 1.4s | 强+ | ×3.5 | 和弦 + 上行音阶 | 大横幅 + 徽章 |
| **L5** | ≥5 线（`PENTA`/`HEXA`）或 `QUAD`+`TRIFACE` 同爆 | 2.2s | 最长 | ×5 | 专属短旋律 | 全屏级名号 |

- 档位判定在 `src/game/honors.js#feedbackLevel()`，是**规则**（决定是否该给横幅）；秒数/震屏/粒子倍率在 `FEEDBACK_STYLE`，是**视觉数值**。
- 实测梯度：L3 约每局 2 次、L4 约每 3 局 1 次、L5 约每 50 局 1 次——保证"日常有反馈、稀有才隆重"。
- **L5 硬约束**：横幅必须落在**不遮挡棋盘**的区域（棋盘上方信息带，与状态条同带），允许约 0.6× 的时间流速下调（≤400ms）制造顿帧，但**不得阻断输入**，结束后棋盘状态完好可读。禁止白色过曝、全屏泛白、火焰烟雾。
- **未消除的落子也有反馈**（v0.3.0 新增）：`放置分` 每格 10 分，跳字以小号"安静版"出现（`+分` 单行），抑制"放歪了 = 白玩"的挫败。

### 7.2 荣誉播报（`src/game/honors.js`）

- 一次落子只弹**一个主横幅**：稀有度最高者优先，同为顶级时取加分最高者；其余荣誉以一行小徽章依次浮入（每个 ≤200ms）。
- 全部荣誉加分**累加**，不互相吞。
- 播报层 `#honor-layer` 位于棋盘上方信息带，`pointer-events:none`——任何奖励时刻都不得吃掉一次手势。

### 7.3 连消链（`CHAIN`）

- 顶部信息条常驻链指示器（`×N` + 进度条），**链长 ≥2 才出现**（链长 0/1 时不可见：永远在屏上的链断了也不心疼）。
- 链越长越亮（≥5 时转为暖色），进度条以 20 链为满格。
- **断链必须给"断裂"反馈**：胶囊灰闪约 0.6s + 下沉音，且只在"屏上曾有链"时才播。

### 7.4 分数跳字

`showScorePop()` 最多四行：`+分数` / `N LINES` / `M FACES`（跨面时）/ 荣誉名号。

## 9. 平台生命周期与发行体验

- 首屏优先展示实际游戏画面；加载阶段显示可理解的进度或状态反馈。
- 页面失去焦点、切换标签页或进入广告时，游戏进入暂停态并屏蔽放置输入。
- 页面恢复焦点或广告结束后，恢复前的棋盘、方块、分数和回合状态必须保持一致。
- 广告或外部平台回调不得触发重复放置、重复消除或重复计分。
- 低端移动设备允许关闭或降低粒子、阴影和后处理，但不能影响规则判定和落点可读性。
- 初始化失败、资源加载失败或异常状态应提供可恢复的重试或重新开始入口，不能停留在无反馈画面。

## 10. 程序化渲染与高品质 VFX

- 运行时视觉必须由代码程序化生成，不加载图片贴图、视频背景、预制粒子图集或外部 3D 模型；棋盘与方块使用参数化几何，UI 使用 HTML/CSS，特效使用代码参数和 Shader/材质。
- Three.js 负责场景、几何、材质、灯光与阴影；`postprocessing` 负责组合式后处理，至少接入抗锯齿与阈值受控的 Bloom；`three.quarks` 负责同批次的规则碎片/小立方体粒子。
- 消除粒子严格沿完成线的 x/y/z 方向发射，单线与多线采用固定数量、寿命、速度和尺寸曲线；禁止烟雾、火焰、满屏随机粒子与强烈全屏泛光。
- 光影采用统一主光、柔和环境补光和轮廓光，方块使用统一圆角、粗糙度、接触阴影和高光逻辑；后处理不能抹掉网格边界或预览轮廓。
- 高性能档允许更高阴影贴图、MSAA/SMAA、Bloom 层级和粒子数；低性能档降低这些参数但保留消除方向、合法/非法和候选线信息。
- 所有 VFX 参数集中在代码配置中，不在组件或事件回调内散落魔法数字。
- v0.3.0 起新增 `FEEDBACK_STYLE`（五档时长/震屏/粒子倍率/播报形态/顿帧）与 `HUD_STYLE`（链指示器可见阈值、差值文案比例），与 `BOARD_STYLE`/`ROTATE_STYLE`/`VFX_CONFIG` 并列，同属 `src/rendering/config.js` 单点配置。

## 11. 音频建议

MVP 使用代码程序化 Web Audio 生成短促、无侵入的放置与消除反馈音，不加载外部音频素材。设置面板提供 Sound 开关；移动设备另提供 Haptics 开关，两项状态均写入本地存储。重复落子音不得形成疲劳。

## 12. 主页与断点续玩（v0.4.0）

进入游戏后**先落在主页**，不再直接开一局（Block Blast 的入口结构）。

### 12.1 主页内容与层级

```
                    [V]
                VoxalBlast
           立体消除 · 六面连爆
              最高分 18,400

        ▶  继续游戏  /  ▶  新游戏

     未完成的一局：1,895 分 · 10 格        ← 仅当有未完成的一局

        [🏆 排行榜]      [⚙ 设置]
```

- **主页是覆盖层（`#home`，`position: fixed` 的不透明封面），不是第二个页面**：3D 棋盘、棋子预览、候选槽在封面之下原样保留，从主页返回棋盘**不重载、不重新取景**。
- **主按钮只有一个**（同尺寸、同位置，不因状态换位）：`继续游戏` / `新游戏` 由**存档**决定，不由按钮标签决定（标签只做显示）。
- **`继续游戏` 与 `新游戏` 用配色区分**：继续 = 蓝色渐变（`#8ecbff → #3f7ce0`），新游戏 = 琥珀渐变（`#ffd85e → #ff9f34`）。玩家不必读完文字就能分辨当前按下去会发生什么。
- 有未完成的一局时，主按钮下方显示**进度摘要**（分数 + 已占格数），让"继续"是可预期的，而不是盲盒。
- 次级两个入口：`排行榜`（打开 08 §7.5 的排行榜弹层，主榜指标＝**单局最高分**）与 `设置`。
- 顶部信息条（SCORE / BEST / CHAIN / 版本徽标）**在主页不出现**——主页是封面，这些东西属于局内（05「版本号退出主界面」由此落实）。

### 12.2 未完成的一局（存档槽）

- **"未完成"的定义**：玩家已经进入棋盘（新开或继续）且该局尚未结算（未 Game Over）。**开机不写存档**——没人动过的棋盘不是"未完成的一局"。
- 存储键：`localStorage["voxalblast.session.v1"]`，独立于`voxalblast.records.v1`（`records` 是**已结束对局**的纪录簿，`session` 是**未结束对局**的存档槽；生命周期相反，共用一个键会互相覆盖）。
- 存档内容：棋盘占用格（只存**外壳晶格坐标**，读回时逐格复核，内核/越界/重复一律丢弃）、分数与累计线数、3 个候选（**存形状名**，不存副本，避免复活已下架的形状）、道具余量、本局 run 状态（链、各维度最佳、点亮面、荣誉计数）、立方体姿态（四元数 + 停摆偏航/俯仰）。
- 写入时机：每次落子结算后、道具生效后、候选重洗后、进入主页时、页面转入后台时。一次普通对局的写入频率 ≈ 每回合一次（约 1~2 秒），不涉及每帧写盘。
- **对局结束（Game Over）必须清空存档**：已结算的局不得再以"继续游戏"回到棋盘。
- 降级：隐私模式/存储被禁时静默转为内存态（本次会话内仍可"继续"），读取失败或存档不可玩（例：候选全为已使用、形状全部不在当前形状池）一律**当作"没有存档"显示"新游戏"**，绝不抛错、绝不半途恢复一个坏棋盘。

### 12.3 回到主页（随时）

- 设置面板新增第三个动作行 **`回到主页`**（位于 `RESTART GAME` 之上，避免误触销毁存档）：局内、主页上、以及 **Game Over 结算面板之上**都可打开设置并回到主页。
- 因此**设置入口在一局结束后依然可用**（v0.3 之前 `gameEnded` 会直接拒绝打开设置）——"随时回到主页"是硬要求。
- 回主页时先写存档，再覆盖棋盘：玩家不会因为回主页而损失进度；主按钮随即变为 `继续游戏`。

### 12.4 暂停态收口

`isPaused` 由单一函数 `syncPause()` 计算：`homeOpen || document.hidden || gameEnded || settingsOpen || controlsOpen`（最后一项由 v0.4.1 的操作说明卡加入）。主页或任一弹层打开期间棋盘不接受手势、道具按钮禁用、`animate()` 不再绘制封面之下的画面（省电且防姿态漂移）。

### 12.5 回归断言（详见 04）

1. 首次进入落在主页，主按钮为"新游戏"，无进度摘要。
2. 从主页开新局 → 落子 → 设置 → 回到主页：主按钮变"继续游戏"，摘要显示该局分数与格数。
3. **跨页面刷新**：关掉页面重新打开（同一浏览器档案），主页仍为"继续游戏"；点进去后**分数、棋盘格数、候选、道具、链全部与离开时一致**，再回主页写回的存档与读入的存档逐字段相同。
4. Game Over 结算后回到主页：主按钮回到"新游戏"。
5. 主页封面之下不可触达顶部信息条与棋盘（命中测试必须落在封面上）。

## 13. 键盘操作（PC，v0.4.1）

PC 端提供一套与手势**同轴同向**的键盘旋转，并把键位做成可视的操作说明。

### 13.1 键位

| 键 | 轴 | 等同的手势 | 方向 |
| --- | --- | --- | --- |
| `W` / `S` | **X 轴（屏幕横轴）** | 上下滑（六面体范围内） | W = 上滑（正面往上翻），S = 下滑 |
| `A` / `D` | **Y 轴（屏幕纵轴）** | 左右滑 | A = 左滑，D = 右滑 |
| `Q` / `E` | **Z 轴（屏幕法线）** | 左右窄带内上下滑 | Q = 逆时针，E = 顺时针（跟手） |

- **键位不新增一套方向模型**：每个键的语义就是"它等价的那次滑动"。`src/rendering/keyboard.js` 只回答"这个键转哪根世界轴、往哪边一圈"，方向值是与 `ROTATE_STYLE.yawDirection / pitchDirection / rollDirection` 相乘的同一个旋钮——改方向配置时键位跟着一起变，两套输入永远不可能互相矛盾。
- 走的是与手势完全相同的落地路径（`beginAxisGesture → setLiveAngle → startCubeSnap`），因此**同一次翻面，键按出来的姿态与滑出来的姿态逐位相同**。
- **按键的旋转必须有动画（v0.4.2）**：从**当前姿态** slerp 到目标姿态，时长与过冲同手势停稳（`ROTATE_STYLE.snapDuration` 0.26s + `easeOutBack` ≈4% 回弹），**不允许瞬移**。
  - ⚠️ 实现陷阱：手势松手时姿态已经被手指拖到位，停稳动画只是"收尾"；按键没有手指，若用 `setLiveAngle()` 先把角度写进渲染姿态，停稳动画就会在"零距离"上播放 → **立方体直接跳过去**（v0.4.1 首版实测就是这样）。正确做法是把角度写进手势对象而**不渲染**，再由 `startCubeSnap()` 从立方体当前所在的姿态开始动画。
  - 断言（04）：按键后取样渲染姿态，必须存在**中间帧**（首帧距起点与终点都 > 5°）、姿态朝目标单调推进、结束时精确落在 90°（误差 < 0.05°）且停稳动画已结束。
- **一次按键 = 一次翻面**，与"一次手势只翻一个面"一致。
- **不启用按住连发**：`event.repeat` 的事件只做拦截，不转动。理由是这是全场唯一可能"跑在玩家所见之前"的输入，按住连发会转出玩家没准备好的角度。（快速连按是允许的：进行中的停稳动画会被立即结算，然后开始下一个面。）
- **按键在棋盘不live时必须无效**：主页、设置/操作说明/排行榜/Game Over 面板打开期间、以及正在拖拽放置或道具待选期间，键盘旋转一律不响应。
- 带 `Ctrl / Cmd / Alt` 的组合同样不响应（避免抢浏览器快捷键）。

### 13.2 操作说明（可视化，不是一段文字）

- **入口**：顶部信息条新增 `⌨` 图标按钮（**≥641px 才显示**：更窄的窗口是拇指环境，键位仍在，但入口让位）；也可从设置面板的 `操作说明` 行打开（该行右侧直接印着 `W A S D Q E` 六个键）。
- **卡片内容**：每个轴一行，行内三件东西——**键帽对**（`W/S` 竖排读作上/下，`A D`、`Q E` 横排读作左右）、**一颗 CSS 3D 迷你方块**、**绕对应世界轴的箭头环**；右侧两字标注（上下翻面 / 左右翻转 / 平面自转）+ 轴名小字。
- **箭头环用同一套世界轴语言**：平放（不旋转）＝ Z 轴（屏幕法线）、前后翻倒＝ X 轴、左右翻倒＝ Y 轴。环的倾角固定 **46°**——更平（60°+）会把环压到迷你方块的轮廓上，看上去像"脸上划了一道线"。
- **卡片是活的**：卡片打开期间按键不会碰棋盘（棋盘本来就是暂停的），而是让**该行自己的迷你方块转一个 90°**、对应键帽下沉一下。所以这套说明可以"当场试出来"，不用先关掉它。
- 卡片的 `z-index`（13）高于设置面板（12）：它是从设置面板里点开的，不能开在点它的那个面板后面。
- **棋盘区瞬时提示（`#axis-hint`）**：局内按方向键时，立方体下方浮出"键帽 + 该轴的箭头环 + 轴名（X/Y/Z）"小胶囊，700ms 后自动淡出；不接收任何指针事件，不遮挡棋盘。窄屏（≤700px）不显示。

### 13.3 回归断言（详见 04）

1. 六个键各自产生**精确 90°**、绕**对应世界轴**的姿态差（`ΔQ = base_after · base_before⁻¹`，误差 < 0.01°），且符号与等价手势一致。
2. 按住不连发；面板打开时按键不生效、关闭后立即恢复。
3. 操作说明卡片里印出的键帽集合 == 引擎真正响应的绑定集合（`src/rendering/keyboard.js` 的 `KEY_BINDINGS`），不得出现"说明里有个无效键"或"有效键没写进说明"。
4. 卡片打开时按键只转说明里的迷你方块，棋盘姿态不变。
