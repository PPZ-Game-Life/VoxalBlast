## 1. 页面与布局

启动进入主页，提供新游戏/继续游戏、最高分、排行榜、设置。主页是覆盖层，背后的游戏画布保留尺寸；静态棋盘缩影复用当前场景几何。首次启动缩影来自初始化盘面，不承诺是续玩存档的截图。

- 常规桌面：顶部分数、BEST、连击和操作入口；中央棋盘；底部候选与道具。
- 顶部不显示游戏名（占位样式仍留在 styles.css）。版本号仅开发构建显示；设置已中文化，局内状态提示、部分统计与荣誉标题仍含英文，并非全量中文化。

## 2. 翻面与缩放

从棋盘区域开始拖动用于旋转，从候选开始拖动用于放置，两者互斥。一次手势只认一个固定世界轴：横向绕 Y；起点在棋盘水平范围内的纵向绕 X；左右侧带纵向绕 Z（平面自转）。

侧带的平面自转按「手指抓住哪条边，哪条边就跟着走」定向：右侧带下滑 = 顺时针，左侧带下滑 = 逆时针，因此两带里同向的一次滑动得到方向相反的四分之一转。v0.8.1 修复：此前左右侧带共用一个方向符号，只有右侧带跟手，左侧带与手指相反（用户报告"右侧符合预期、左侧反了"）。方向符号仍是 `ROTATE_STYLE.rollDirection` 一个旋钮，侧带只决定 ±。

超过约 30° 阈值转向下一面，否则弹回。每次最多 90°，用四元数维持网格姿态，不因之前转向改变手势轴。滑动标尺按棋盘投影大小计算，起手需满足方向优势与距离门槛。

### 2.1 停稳姿态与方位微调（v0.8.6 引入，v0.8.7 修构图，v0.8.8 改成玩家可控）

姿态拆成互不干扰的两层，各自只有一个归属：

- **逻辑姿态** `cubeBase`：只由整数个 90° 世界轴步进相乘而成，永远落在六面体 24 种标准朝向上。面判定、翻面判定、吸附目标、道具作用面与存档读取**只认它**。
- **方位** `bearing`：**玩家可微调**的一层屏幕空间倾斜（偏航 + 俯仰两个分量），与逻辑姿态相乘渲染：`renderPose = Rx(bearingPitch) ∘ Ry(bearingYaw) ∘ (R_axis(live) ∘ cubeBase)`。它不参与面判定、不参与姿态累计，也不回写成下一次旋转的起点。

停稳的立体观感由**相机**提供 3/4 视角：`BOARD_STYLE.cameraDirection = [0.34, 0.33, 1.0]`（约 18.8° 偏航 / 17.6° 俯仰）；`bearing` 只是它之上的额外一点转角，出厂默认偏航 −5°。

**方位是玩家的，不是常量（v0.8.8）**。此前它是一层固定倾斜，每次松手都回到同一个角度——制作人反馈"每次转完，都是到达同一个角度"。现在：

- **微调被保留**：拖动中的偏航/俯仰**直接移动方位本身**（不是在它外面再叠一层旋转），所以松手时画面上的姿态就是被保留的姿态——**不回弹、不二次动画**。
- **微调被记住**：翻面时方位**原样保留**，新的一面按玩家调好的方位停下来。
- **超出区间就翻面**：只有当"方位 + 本次拖动"的总偏移落在 `±stepThreshold`（≈30°）之内才判为微调；一旦越出这个区间，就按拖动方向**恰好翻一个面**，本次偏移作废、方位回到玩家之前调好的值。也就是说"离整面超过约三分之一面"这件事，对刚拖过去和早就调在那儿是一样的判定。
- **平面自转不参与**：侧带/Q/E 的 Z 旋转不留任何残角（Z 是"摆正"手势），要么精确 90°，要么精确弹回。
- **复位**：重新开始游戏把方位恢复到出厂默认；方位随续玩存档一起保存（它现在是玩家状态，不再是纯观感），读档时按 `±stepThreshold` 夹一次，手改过的存档也进不了非法角度。

由此得到的行为：

- **停稳构图**（出厂方位，`npm run probe:framing`，1280×900）：主面占三个可见面投影面积的 **71.4%**，右面 18.1%、顶面 10.5%；24 种标准朝向的占比与离轴角完全一致（实测离轴 29.14°，逐朝向零离散）。v0.8.5 的 26.4°/22.3° 视角约为 65% / 19% / 16%，主面因此比上一版更主导，而三个面仍然都是"面"而不是薄片。
- **可调出来的范围**（同视口实测，供参考）：偏航方位 −25° → 主面 46.4%（侧面 43.3%），−5° → 71.4%，+25° → **89.0% 且顶面 0.0%**。**往"更正视"方向调过头会退化成平面网格**，这是玩家自己的选择，但默认值刻意留在 71.4%。
- **六面体永远竖直**：相机 up = +Y，网格姿态是坐标轴的带符号置换，方位按**俯仰在前、偏航在后**（`Rx(pitch)·Ry(yaw)`）复合——绕世界 Y 的旋转不改变世界 Y 方向，而世界 Y 方向就是竖直棱的方向，因此**任何**玩家可调的方位都不会把棋盘压歪（实测倾斜 0.00°）。顺序反过来会（v0.8.6 实测 −4.77°）。
- **相机带来的轴偏斜是 3/4 视角的代价**：世界轴不等于屏幕轴，实测偏航轴 0°、俯仰轴 5.98°、平面自转轴约 12°（`alongView` 0.87）。三者都**不随手势变化**（拖动全程漂移 0°）。
- **松手吸附**用 easeOutCubic、**无过冲、无弹簧式二次摆动**；微调路径根本不播动画（姿态就是松手那一刻的姿态）。

> **v0.8.6 → v0.8.7 更正记录**：v0.8.6 曾把整个 3/4 视角搬进六面体（相机正视 `[0,0,1]` + 17.5°/15.5° 双轴倾斜），把主面推到 82.8% 以贴合当轮建议稿的 82–88%。制作人实测否决："整个就是一格一格的，然后视觉上还比较歪"。两个原因都是结构性的：正面接近正视时每一格都是近正方形，读起来就是平面网格；而双轴倾斜把棋盘压歪 −4.77°。**结论：主面占比不是越高越好，3/4 视角也不能靠把六面体斜过来实现。** 现行断言区间为 66–78%（出厂方位下），另有两条硬门：任一非主面不得低于 6%、竖直棱偏斜 ≤0.5°。均由 `npm run probe:framing` 在出厂方位下强制。

标尺数值（1280×900，六面体投影 458.5×456.1px）：翻一面约需拖动 229.3px（偏航）/ 228.1px（俯仰），判定阈值对应 75.9px / 75.5px；v0.8.5 同视口为 227px / 232.4px 与 75.1px / 77.0px，即偏航 +1.0%、俯仰 −1.9%。规则（半屏投影 = 一面）与 `stepThreshold` 0.52 rad 均未变；阈值现在同时用于"方位区间"（见上），方位为出厂值时两者等价。

W/S 对应俯仰，A/D 对应偏航，Q/E 对应平面自转：Q 等价于左侧带下滑（逆时针），E 等价于右侧带下滑（顺时针）；按住不连续触发。按键时棋盘附近浮出「键帽 + 轴环 + X/Y/Z」小胶囊，约 0.7 秒自动淡出，不接收指针事件，≤700px 隐藏。说明卡片打开时按键只驱动该行迷你方块并让键帽下沉，棋盘姿态不变。滚轮缩放相机，无镜头复位入口。候选始终保持固定的屏幕形状朝向；槽内使用固定斜视 3D 预览，并非纯正视平面图。

## 3. 拖放与取消

越过拖拽阈值后显示手上拼块；进入立方体轮廓附近且有合法位置时隐藏手上幽灵，显示面上预览。不能同时显示两个正在拖动的拼块。轮廓内无合法位置时幽灵转红。

鼠标抬升固定 10px；触摸抬升为 12px + 拼块屏幕高度的一半，上限 120px。吸附后按相对位移步进，每约半格触发一次取整；目标非法时停在前一合法位置，退回后继续跟随。

候选条和道具条共同构成取消区。拖回后松开取消；Esc、右键和输入中断也结束拖拽。取消不消耗拼块、不计分。打开主页/设置、失焦、页面隐藏等路径清理拖拽与旋转手势。

## 4. 暂停、续玩与结算

主页、设置/操作说明、页面不可见和局终等状态共同控制暂停。页面隐藏/失焦会结束当前手势；不要把“失焦清理手势”等同于所有环境都已有完整广告暂停流程。

运行状态变化后保存棋盘、候选已用状态、道具、荣誉/连击及姿态（逻辑姿态 + 玩家调好的方位）。回到主页保留未完局；继续读取存档。Game Over 写入本地纪录并删除续玩存档。重新开始直接开新局，并把方位复位到出厂默认。

声音和触感可单独开关；触感是否实际发生取决于浏览器/设备。操作说明中可用键盘驱动示意小立方体。
