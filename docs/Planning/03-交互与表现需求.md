# VoxalBlast 交互与界面

> v0.8.7 实现基线 / 2026-09-17；依据 main.js、swipe.js、keyboard.js、config.js、styles.css、toy.css。v0.8.7 修正 v0.8.6 的停稳构图（3/4 视角回到相机、展示偏摆改为纯偏航），玩法、输入映射、阈值与其余画面与 v0.8.1 一致；v0.8.1 只修侧带平面自转的方向，与 v0.8.0 一致。

## 1. 页面与布局

启动进入主页，提供新游戏/继续游戏、最高分、排行榜、设置。主页是覆盖层，背后的游戏画布保留尺寸；静态棋盘缩影复用当前场景几何。首次启动缩影来自初始化盘面，不承诺是续玩存档的截图。

- 常规桌面：顶部分数、BEST、连击和操作入口；中央棋盘；底部候选与道具。
- 顶部不显示游戏名（占位样式仍留在 styles.css）。版本号仅开发构建显示；设置已中文化，局内状态提示、部分统计与荣誉标题仍含英文，并非全量中文化。

styles.css / toy.css 中实际生效的断点：

| 条件 | 效果 |
| --- | --- |
| ≥641px | 顶部显示 ⌨ 操作说明入口；更窄只隐藏入口，键位仍生效，卡片仍可从设置进入 |
| >900px | 桌面列序：棋盘 → 候选 → 道具 |

HUD 使用奶油纸芯与暖木边，入口/道具为深棕图标，候选选中态为浅绿描边；背景插画是独立装饰层，不参与命中测试。主棋盘、候选和手中拼块共用几何与漆面参数；布景、材质与色调映射约束见 [05](05-美术方向与视觉规范.md)。

## 2. 翻面与缩放

从棋盘区域开始拖动用于旋转，从候选开始拖动用于放置，两者互斥。一次手势只认一个固定世界轴：横向绕 Y；起点在棋盘水平范围内的纵向绕 X；左右侧带纵向绕 Z（平面自转）。

侧带的平面自转按「手指抓住哪条边，哪条边就跟着走」定向：右侧带下滑 = 顺时针，左侧带下滑 = 逆时针，因此两带里同向的一次滑动得到方向相反的四分之一转。v0.8.1 修复：此前左右侧带共用一个方向符号，只有右侧带跟手，左侧带与手指相反（用户报告"右侧符合预期、左侧反了"）。方向符号仍是 `ROTATE_STYLE.rollDirection` 一个旋钮，侧带只决定 ±。

超过约 30° 阈值转向下一面，否则弹回。每次最多 90°，用四元数维持网格姿态，不因之前转向改变手势轴。滑动标尺按棋盘投影大小计算，起手需满足方向优势与距离门槛。

### 2.1 停稳姿态与展示偏摆（v0.8.6 引入，v0.8.7 修正口径）

姿态拆成互不干扰的两层，各自只有一个归属：

- **逻辑姿态** `cubeBase`：只由整数个 90° 世界轴步进相乘而成，永远落在六面体 24 种标准朝向上。面判定、阈值判定、吸附目标、道具作用面与存档读取**只认它**。
- **展示偏摆**：固定在**屏幕/镜头空间**的一层小倾斜，按权重与逻辑姿态相乘渲染：`renderPose = tilt(weight) ∘ R_axis(angle) ∘ cubeBase`。它不参与面判定、不参与姿态累计，也**不回写**成下一次旋转的起点。当前它只有**偏航约 5°**（`ROTATE_STYLE.presentationYaw`），`presentationPitch` 必须为 0。

停稳的立体观感由**相机**提供 3/4 视角：`BOARD_STYLE.cameraDirection = [0.34, 0.33, 1.0]`（约 18.8° 偏航 / 17.6° 俯仰）。由此得到的行为：

- **停稳构图**：主面占三个可见面投影面积的 **71.4%**，右面 18.1%、顶面 10.5%；24 种标准朝向的占比与离轴角完全一致（实测离轴 29.14°，逐朝向零离散）。v0.8.5 的 26.4°/22.3° 视角约为 65% / 19% / 16%，主面因此比上一版更主导，而三个面仍然都是"面"而不是薄片。
- **六面体永远竖直**：相机 up = +Y，网格姿态是坐标轴的带符号置换，因此竖直棱在屏幕上恒为铅直（实测倾斜 0.00°）。**这是"不要歪"的硬口径。**
- **为什么展示偏摆只能是偏航**：绕世界 Y 的旋转不改变世界 Y 的方向，所以最后施加偏航时棋盘永远不会被压歪；带俯仰的展示偏摆会。同理，两层倾斜复合成 `Rx(pitch) · Ry(yaw)`（俯仰在前、偏航在后）——最后施加的那个轴以外的那一个会把棋盘带歪。
- **起转即归正**：拖动开始后，展示偏摆在约 20° 旋转量内**连续**衰减到 0（不在 pointerdown 上清零，避免起手跳正）；偏摆退净后按键与手势都严格绕单一世界轴运动，实测偏摆退净后的轴漂移为 0°（三条轴）。偏摆在约 30° 判定阈值之前已退净，因此松手要兑现的那个姿态从来不是斜的。
- **相机带来的轴偏斜是 3/4 视角的代价**：世界轴不等于屏幕轴，实测偏航轴 0°、俯仰轴 5.98°、平面自转轴 8.98°（`alongView` 0.90）。三者都**不随手势变化**（漂移 0°）——这是本轮真正修掉的东西（旧版还有 ≤8°+8° 的偏摆冻结在实时旋转外面）。
- **停稳恢复**：吸附用 easeOutCubic，**无过冲、无弹簧式二次摆动**；逻辑姿态在动画前段落到精确网格，展示偏摆在动画后段再淡回。
- **Q/E 与侧带自转**仍是精确 90°（逻辑姿态校验通过），不再各自留下残余偏摆。
- **存档**只保存逻辑姿态 `base`。旧存档里的 `quat/yaw/pitch` 被忽略但仍可正常加载。

> **v0.8.6 → v0.8.7 更正记录**：v0.8.6 曾把整个 3/4 视角搬进六面体（相机正视 `[0,0,1]` + 17.5°/15.5° 双轴展示偏摆），把主面推到 82.8% 以贴合当轮建议稿的 82–88%。制作人实测否决："整个就是一格一格的，然后视觉上还比较歪"。两个原因都是结构性的：正面接近正视时每一格都是近正方形，读起来就是平面网格；而双轴偏摆把棋盘压歪 −4.77°。**结论：主面占比不是越高越好，3/4 视角也不能靠把六面体斜过来实现。** 现行断言区间为 66–78%，另有两条硬门：任一非主面不得低于 6%（防止退回平面板）、竖直棱偏斜 ≤0.5°（防止再歪）。三条都由 `npm run probe:framing` 强制。

标尺数值（1280×900，六面体投影 458.5×456.1px）：翻一面约需拖动 229.3px（偏航）/ 228.1px（俯仰），判定阈值对应 75.9px / 75.5px；v0.8.5 同视口为 227px / 232.4px 与 75.1px / 77.0px，即偏航 +1.0%、俯仰 −1.9%，回到与上一版基本一致的手感（v0.8.6 的 +5.6% 漂移随之消失）。规则（半屏投影 = 一面）与 `stepThreshold` 0.52 rad 均未变。

W/S 对应俯仰，A/D 对应偏航，Q/E 对应平面自转：Q 等价于左侧带下滑（逆时针），E 等价于右侧带下滑（顺时针）；按住不连续触发。按键时棋盘附近浮出「键帽 + 轴环 + X/Y/Z」小胶囊，约 0.7 秒自动淡出，不接收指针事件，≤700px 隐藏。说明卡片打开时按键只驱动该行迷你方块并让键帽下沉，棋盘姿态不变。滚轮缩放相机，无镜头复位入口。候选始终保持固定的屏幕形状朝向；槽内使用固定斜视 3D 预览，并非纯正视平面图。

## 3. 拖放与取消

越过拖拽阈值后显示手上拼块；进入立方体轮廓附近且有合法位置时隐藏手上幽灵，显示面上预览。不能同时显示两个正在拖动的拼块。轮廓内无合法位置时幽灵转红。

鼠标抬升固定 10px；触摸抬升为 12px + 拼块屏幕高度的一半，上限 120px。吸附后按相对位移步进，每约半格触发一次取整；目标非法时停在前一合法位置，退回后继续跟随。

候选条和道具条共同构成取消区。拖回后松开取消；Esc、右键和输入中断也结束拖拽。取消不消耗拼块、不计分。打开主页/设置、失焦、页面隐藏等路径清理拖拽与旋转手势。

## 4. 暂停、续玩与结算

主页、设置/操作说明、页面不可见和局终等状态共同控制暂停。页面隐藏/失焦会结束当前手势；不要把“失焦清理手势”等同于所有环境都已有完整广告暂停流程。

运行状态变化后保存棋盘、候选已用状态、道具、荣誉/连击及姿态。回到主页保留未完局；继续读取存档。Game Over 写入本地纪录并删除续玩存档。重新开始直接开新局。

声音和触感可单独开关；触感是否实际发生取决于浏览器/设备。操作说明中可用键盘驱动示意小立方体。
