# VoxalBlast 交互与表现需求

> 版本：MVP v0.2  
> 平台优先级：PC 优先，竖屏移动端完整兼容

## 1. 平台与响应式布局

- PC 是首要交互平台，优先保证鼠标拖拽、键盘旋转和精确吸附的手感。
- 竖屏手机必须提供完整可玩的触摸方案，不能仅将 PC 布局等比缩小。
- PC 端棋盘、方块供给区、分数和重开入口不得互相遮挡。
- 竖屏端建议将棋盘置于上方或中部，方块供给区置于下方，分数和重开入口固定在顶部。
- 触摸控件要有足够点击面积，核心流程不能依赖悬停提示或键盘快捷键。
- 屏幕旋转、窗口缩放和浏览器安全区变化时，棋盘仍需完整可见并保持可操作。

## 2. 页面布局基线

### PC 横屏布局

采用参考图的三栏信息结构：

- 左侧：当前分数、最高分和简洁状态信息。
- 中央：主 3D 棋盘，占据首要视觉面积并保持完整可见。
- 右侧：3 个当前方块、旋转/操作入口和设置入口，按纵向排列。
- 右侧操作区不得覆盖棋盘，也不得压缩棋盘到无法辨认。
- 设置入口放置在右上角，使用图标按钮并提供悬停说明。

### 竖屏手机布局

- 顶部平台栏：保留退出、音量和平台状态入口，并适配手机安全区。
- 游戏顶部状态区：当前分数、最高分和设置入口。
- 中央：完整 3D 棋盘，优先保证棋盘可操作和落点可读。
- 棋盘下方：横向展示 3 个当前方块，作为主要触摸拖拽起点。
- 底部：触摸旋转、视角控制和声音等基础操作区，避开系统安全区。
- 方块供给区与棋盘保持明确间距，拖拽时不能被底部 UI 截断。
- 横屏 PC 的右侧纵向栏在竖屏端不得原样缩放，应改为底部横向或分段布局。
- 手机版游戏内不加入参考图中的金币、商店、炸弹、弓箭、炮台等道具系统。

### 参考范围说明

参考图仅作为布局和信息层级参考：保留“左侧状态、中央棋盘、右侧操作区、右上角设置”的结构；不照搬其中的金币、免费道具栏、8×8 平面棋盘或其他与 VoxalBlast MVP 冲突的系统。

## 3. 视野与镜头

- 默认展示完整棋盘，棋盘不得被 UI 遮挡。
- 支持鼠标拖拽旋转视角和滚轮拉近/拉远。
- 支持 WASD 旋转观察方向，R 键快速切换朝向。
- 镜头旋转应平滑，放置过程中不能突然改变落点解释。
- 被遮挡的已放置方块降低不透明度，必要时允许按层级淡出。
- 棋盘边界、坐标轴和格子间隙应足够清楚，不能只依赖颜色区分。

## 4. 方块拖拽

- 鼠标按下方块后进入拖拽态，方块跟随光标移动。
- 光标接近合法位置时自动吸附到最近网格坐标。
- 合法落点显示半透明预览；非法落点显示明确的红色或警示态。
- 松开鼠标才确认放置，拖拽取消不得改变棋盘。
- 预览状态要能显示完整方块轮廓，不能只显示接触面的单个格子。

## 5. 旋转

- 旋转操作实时更新预览，不必等待确认动画结束。
- 滚轮或 WASD 提供连续、可预测的旋转步进。
- R 键用于切换观察方向，不应与方块自转产生歧义。
- 旋转后若越界或与已占用格冲突，继续显示非法态但不允许落子。

## 6. 候选线提示

- 对差 1 格或差 2 格的完整线显示高亮候选点。
- 候选提示采用呼吸或轻微闪烁，不得持续强亮造成视觉噪音。
- 候选线只作为辅助，不替玩家自动选择方块或落点。
- 当当前拖拽方块能补齐候选线时，可提高该线的高亮优先级。

## 7. 消除反馈

一次落子完成后按以下顺序反馈：

1. 方块固定并短暂强调落点。
2. 完整线高亮，区分 x、y、z 方向。
3. 线和方块格子同时消失。
4. 播放粒子、短促镜头震动和分数跳字。
5. 显示“几线消除”和倍率。
6. 棋盘恢复可操作状态，进入下一回合。

多线消除必须比单线消除更强：持续时间更长、粒子密度更高、分数跳字更醒目，但不能遮挡棋盘导致玩家丢失局面。

## 8. UI 信息

首屏持续显示：

- 当前分数。
- 历史最高分（若已实现本地存储）。
- 当前可用的 3 个方块。
- 重新开始入口。

Game Over 状态显示：

- `GAME OVER`。
- 本局分数。
- 最高分。
- 重新开始按钮。

按钮需支持鼠标点击和键盘焦点，图标与文字含义清晰，避免小屏溢出。

## 9. 平台生命周期与发行体验

- 首屏优先展示实际游戏画面；加载阶段显示可理解的进度或状态反馈。
- 页面失去焦点、切换标签页或进入广告时，游戏进入暂停态并屏蔽放置输入。
- 页面恢复焦点或广告结束后，恢复前的棋盘、方块、分数和回合状态必须保持一致。
- 广告或外部平台回调不得触发重复放置、重复消除或重复计分。
- 低端移动设备允许关闭或降低粒子、阴影和后处理，但不能影响规则判定和落点可读性。
- 初始化失败、资源加载失败或异常状态应提供可恢复的重试或重新开始入口，不能停留在无反馈画面。

## 10. 程序化渲染与高品质 VFX

- 运行时视觉必须由代码程序化生成，不加载图片贴图、视频背景、预制粒子图集或外部 3D 模型；棋盘与方块使用参数化几何，UI 使用 HTML/CSS，特效使用代码参数和 Shader/材质。
- Three.js 负责场景、几何、材质、灯光与阴影；`postprocessing` 负责组合式后处理，至少接入抗锯齿与阈值受控的 Bloom；`three.quarks` 负责同批次的规则碎片/小立方体粒子。
- 消除粒子严格沿完成线的 x/y/z 方向发射，单线与多线采用固定数量、寿命、速度和尺寸曲线；禁止烟雾、火焰、满屏随机粒子与强烈全屏泛光。
- 光影采用统一主光、柔和环境补光和轮廓光，方块使用统一圆角、粗糙度、接触阴影和高光逻辑；后处理不能抹掉网格边界或预览轮廓。
- 高性能档允许更高阴影贴图、MSAA/SMAA、Bloom 层级和粒子数；低性能档降低这些参数但保留消除方向、合法/非法和候选线信息。
- 所有 VFX 参数集中在代码配置中，不在组件或事件回调内散落魔法数字。

## 11. 音频建议

MVP 可使用短促、无侵入的反馈音：放置、非法放置、单线消除、多线消除、Game Over 各一类。音量应提供静音开关，不能让重复落子音形成疲劳。
