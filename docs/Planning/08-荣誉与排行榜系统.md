## 1. 当前职责与结算顺序

- `Board.place()`：把拼块写入共享外壳晶格，扫描并一次性结算六个面的所有满行/列；
- `settlePlacement()`：更新连击与局内统计，调用荣誉判定和计分；
- `scoring.js`：唯一的主分公式来源；
- `honors.js`：单次落子的荣誉集合、主横幅和反馈等级；
- `session.js`：未结束局快照；
- `records.js`：已结束局的本地纪录；
- `crazygames.js`：可选平台提交/打开全球榜的降级适配层。

当前落子顺序为：六面满线结算 → 连击 → 荣誉 → 分数 → 表现反馈 → 保存未完局 → 卡死检查。

## 2. 当前计分公式

> **v0.11.0 计分改版（2026-10-01，[SCORE_REWARD_SIMPLIFICATION_HANDOFF](../Technical/SCORE_REWARD_SIMPLIFICATION_HANDOFF.md)）：**
> §2–§4 描述的是**旧分制（score rules v1）**，现在只用于「改版前开始、尚未结束的旧局」
> （存档缺 `scoreRulesVersion` 字段即视为 v1）。新局使用 v2：
>
> ```text
> 总分 = 10 × 落子格数 + 100 × 满线数
>      + 一次多消 100 × (L-1)      （L≥2，每多一条线 +100）
>      + 连续消除 50 × min(C-1, 4) （C≥2，第 5 次起封顶 +200，次数仍显示真实值）
>      + 清除整面 300 × 净面数      （**只算落子面**：落子前非空、结算后为空）
> ```
>
> v2 **没有**倍率曲线、跨面奖励、连击里程碑和荣誉奖金；单线首次消除且未净面时只有基础分。
> **满线数 `L` 按格子集合去重（制作人口径 2026-10-01「棱上的消除会被计算多次」）**：沿棱的一整行
> 是同一个物理行，棋盘在两个面上各报一次（六面全检需要），计分只算一条 —— 原先它值 310 分，
> 而面内同样的 5 格只值 110 分。收窄实现在 `scoring.js:countScoringLines()`。
> **净面只算方块放置的那一面（制作人口径 2026-10-01）**：共享棱/角上的格子被邻面的线带走时，
> 邻面也会跟着空掉，但那些侧面不发奖 —— 一手最多一个净面。收窄实现在 `scoring.js:wipedFacesFor()`。
> 实现在 `src/game/scoring.js`：`SCORING_V2` / `settleScore()` / `resolveRewards()` /
> `rewardLevel()`；旧表 `SCORING` / `moveScore()` 与 `honors.js` 只为 v1 旧局保留。
> BEST / 周最佳 / NEW BEST **只比较相同规则版本**（records 里 v1 与 v2 是两个池，v1 池只读展示）。

一次落子总分（**旧分制 v1**）：

```text
总分 = 放置分 + 消除线分 + 跨面奖励 + 连击奖励 + 连击里程碑 + 荣誉奖金
```

| 分项 | 当前实现 |
| --- | --- |
| 放置分 | 拼块格数 × 10；即使没有消除也计分 |
| 消除线分 | `100 × 本次线数 × multiplier(本次线数)` |
| 线倍率 | 0..12 线依次为 `[0, 1, 2.5, 5, 10, 18, 30, 45, 65, 90, 120, 155, 195]`；超过 12 按 12 的倍率钳制，但仍用实际线数乘 |
| 跨面奖励 | 本次 2 面 +200，3 面 +600；其他面数 +0 |
| 连击 | 有消除时先把 chain +1，再计 `25 × 当前 chain`；无消除时 chain 归 0 |
| 连击里程碑 | chain 恰好达到 5/10/15/20 时额外 +200/+500/+1000/+2000 |
| 荣誉奖金 | 本次触发的所有荣誉奖金累加 |

`Board.addScore()` 只累计 `moveScore().total` 和本次消除线数。道具清理及换批不调用这条链路，因此不计分、不改总消除线、不推进或打断连击。

## 3. 当前荣誉与累计规则

> **v0.11.0：** 下表六个荣誉**只为 v1 旧局**继续结算与展示；v2 新局不再累计荣誉、不发荣誉奖金，
> 结算卡改列三类奖励次数（`reward.<TYPE>.name ×N`）。荣誉收集墙在 v2 局下标注为「旧分制」只读区。

| ID | 条件 | 奖金 | `priority` | `broadcast` |
| --- | --- | ---: | ---: | --- |
| TRIPLE | 单次 ≥3 线 | 150 | 10 | true |
| TRIFACE | 单次 ≥3 面 | 600 | 25 | true |
| QUAD | 单次 ≥4 线 | 500 | 30 | true |
| PENTA | 单次 ≥5 线 | 1500 | 40 | true |
| HEXA | 单次 ≥6 线 | 4000 | 50 | true |
| PERFECT_TWELVE | 单次 ≥12 线 | 20000 | 90 | false |

`priority` 是 baseline v0.9.17 从 `src/game/honors.js` 补录的现行值：本文正文一直写「按 `priority` 降序取一个」，此前表里却没有这一列，读文档的人查不到值。

阈值为累计触发，不是只取最高档。例如 6 线会同时触发 TRIPLE、QUAD、PENTA、HEXA，四项奖金全部相加；若同时达到三面，再叠加 TRIFACE。

`resolveHonors()` 的实际返回边界：

- `primary`：`broadcast=true` 的触发项按 `priority` 降序、再按奖金降序取一个；
- `secondary`：其他可播报荣誉；
- `records`：`broadcast=false` 的触发项；
- `ids`：本次所有触发 ID；
- `bonus`：所有触发奖金总和。

`PERFECT_TWELVE` 不会成为主横幅，但当前 `showHonorBanner()` 把 `secondary.concat(records)` 一起绘制为小徽章；因此实际行为是“**不做主横幅，但仍可能显示小徽章，并计分、计数**”。旧文档将其写为“仅记录、完全不播报”并不完全符合当前渲染代码。

本局每次触发都会把 ID 追加到 `run.honors`，并增加 `run.honorCounts[id]`。同一荣誉在一局中可重复计数；Game Over 时将整个 ID 列表交给 `recordRun()`，历史荣誉总数按列表中的每一次出现累加。

### 4.1 加分反馈：分数滚动与音效（v0.9.29）

分数不再直接跳到新值，也不再只靠 `+N` 浮字报账：`#score` 从旧值**滚**到新值，滚完在数字上落一次弹跳，并配一条「计数咔哒 → 落定和弦」。

| 项 | 现行值 | 出处 |
| --- | --- | --- |
| 滚动时长 | `min(900, 260 + 点数 × 1.5)` ms | `SCORE_ROLL`（定义在 `ui/hud.js`，与消费它的 `stepRoll()` 同处一文件；这是 HUD 自己的表现时长，没有别的模块读它，因此没进 `config.js`） |
| 缓动 | easeOutCubic（起步快、落定软） | `ui/hud.js stepRoll()` |
| 计数咔哒 | 间隔 ≥48ms、最多 14 次，音高 660 → 1180Hz | `SCORE_ROLL.tickMs / tickMax` → `effects.playScoreTick()` |
| 落定和弦 | 990Hz + 1480Hz；音量按本次点数 0.032 / 0.042 / 0.05 | `effects.playScoreSettle()` |
| 落定弹跳 | 数字缩放 1 → 1.16 → 1，420ms | `styles.css` 的 `#score.settled`、`SCORE_ROLL.settleMs` |

边界（这几条是设计决定，不是实现细节）：

- **只往上滚**：分数变小一律直接落值（重开、续玩恢复）。倒着数会被当成 bug。
- **续玩不滚**：`applySession()` 走 `renderBoard(true)`，直接在存档分数上落值，不为没发生过的操作报账。
- 滚动只是**画法**：`board.score` 仍是唯一真源，被画出来的 `shownScore` 只活在 `ui/hud.js` 内部，规则层与存档都读不到它。
- 音效照旧走 `getSoundOn()` 实时开关；**声音关掉时数字照滚**——滚动是表现，不是音效的附属。
- `prefers-reduced-motion` 下只去掉两处缩放，计数与咔哒保留（09 §8.2：这是独立维度）。
- 数字同时改 `tabular-nums`：比例数字会让滚动中的数字左右抖。

验收：`npm run probe:score`（headless Edge + 真实指针拖放）——数字被画出 ≥3 个中间值、从不超调、落定值 == 棋盘分数、`.rolling` / `.settled` 依序出现，且滚动期页面 AudioContext 真的建了振荡器（≥4）；再把声音开关关掉复跑，要求 0 个振荡器而数字照滚。冷页面第一块放置会有一次 >300ms 卡帧（软件渲染下编译着色器），探针先热身再计数，卡帧事实按 `rollGap` 打进每条 check 的证据里。

## 5. 当前未完局保存边界

未结束局使用独立键 `voxalblast.session.v1`，与历史纪录分离。快照包含棋盘分数/总线数、候选、道具、连击、局内最佳、点亮面、净面、荣誉 ID 列表/次数和逻辑姿态/方位。

- 落子及道具状态变化后写快照；
- 续玩时恢复上述运行态；
- Game Over 后 `clearSession()`，不允许已结束局再次显示为“继续游戏”；
- 快照迁移会过滤非法晶格、退役形状和非法统计；无可用候选的快照视为不可续玩；
- `localStorage` 不可用时，仅退化为当前页面会话的内存槽，不能承诺刷新后仍在。

## 6. 当前本地纪录边界

本地纪录键为 `voxalblast.records.v1`，只在 `endGame()` 中调用 `recordStore.recordRun()` 写入。正在进行中的分数不会实时更新历史最高分，因此 SCORE 暂时高于 BEST 是正常的。

当前保存内容：

- 历史最高分与达成时间；
- 当前记录桶中的周最佳；
- 个人最佳：最长链、单次最多线、单次最多面、点亮面数；
- 累计维度：净面、净体字段当前通过“单局数值与历史值取最大”更新，UI 位于“个人最佳”区，不是全生涯求和；
- 已结束局数；
- 各荣誉历史触发次数；
- 最近 10 局：分数、总线、最长链、点亮面、荣誉 ID 列表、时间。

关键口径：

- `faceWipes` 是本局被落子结算清空的面次数，Game Over 时作为该局值参与“历史最大值”比较；
- `pureCubes` 当前只在 Game Over 时检查棋盘是否完全空，空则本局传 1，否则 0，所以纪录值实际只有 0/1；
- 最近 10 局按结束时间“最新在前”保存，排行榜面板按该顺序画条形图，**不是按分数排序的 Top 10**；
- 面板名为“排行榜”，但本地层本质是个人纪录墙：没有多玩家名次、账号、好友榜或服务器查询。

存储读取、解析和写入均有 try/catch。没有可用 `localStorage` 时，纪录仍可在当前页面进程内更新，但重载后的持久化不保证；`recordRun()` 返回的 `persistent` 表示本次是否实际写入存储。

## 7. 当前周边界

`weekKey()` 先将时间减去 9 小时，再按 UTC ISO 周计算，因此代码边界是 **周一 09:00 UTC**：

- 周一 08:59:59 UTC 仍属于上一周；
- 周一 09:00:00 UTC 起属于新周。

读取排行榜时，如果保存的 `weekly.key` 不是当前 `weekKey()`，UI 显示本周最佳 0；下一局结束后 `recordRun()` 才会把周桶换成当前周并写入该局分数。

这是仓库算法边界，不等于已得到 CrazyGames 当前赛季规则确认；本轮未联网或平台验收。

## 9. 当前 CrazyGames 全球榜边界

平台榜只有可选适配，不是已交付在线排行榜。

可用条件必须同时满足：

1. 构建变量 `VITE_CRAZYGAMES_LEADERBOARD === 'on'`；
2. 运行时存在 `globalThis.CrazyGames.SDK`；
3. SDK 提供 `user.submitScore`。

结束局先无条件写本地纪录，再异步 `platform.submitScore(finalScore, runId)`。适配层：

- 每个 `runId` 最多提交一次；
- 不可用、重复或异常都静默返回失败状态，不阻断结算；
- 有 `VITE_CRAZYGAMES_SCORE_KEY` 且 Web Crypto 可用时尝试 AES-GCM 加密；否则只传明文 `score`；
- 全球榜展示由 SDK 的 `showLeaderboard()` 负责，客户端没有全球榜读取与渲染；
- 未满足邀请/开关/SDK 条件时，入口灰置并显示“即将开放”。

加密消息格式、平台授权、SDK 方法签名、真实提交、周赛边界均未平台验收；也没有自建排行后端、账号同步、反作弊服务端校验或云端续玩。

### 12.1 诊断：不是"荣誉太多"，是一把尺子量了四次

`src/game/honors.js` 的注释自己写着 *"Honors are SIZE MILESTONES, not event types."* —— 里程碑本该是一条阶梯，现在却是四张奖状：≥3/4/5/6 线各给一个名字（TRIPLE / QUAD / PENTA / HEXA），且**同为累计触发**，一次 6 线落子四枚全中、四笔奖金相加、局内一次性全部弹出（§3）。

这是"荣誉数量难理解"的直接来源，**不是数量问题**——删掉任何一枚都治不了，因为问题在"四条独立名册被当成四个事件"。

### 12.2 D3（待拍板）：PERFECT_TWELVE 局内彻底静默

| 项 | 内容 |
| --- | --- |
| 现状 | `broadcast=false`，但 `showHonorBanner()` 把 `secondary.concat(records)` 一起画成小徽章 → **不做主横幅，仍会露面**（§3） |

### 12.3 分阶轮的规则层门禁

本轮**不改**：`src/game/honors.js`（名册 / 奖金 / `priority`）、`src/game/scoring.js`、`feedbackLevel()` 判定条件、存档协议与结算流程、平台层。

现有 `tools/rule-tests.mjs` 覆盖荣誉规则层，本轮预期**零变化**——这是主要的安全性证据，也是第一道门禁（见 [09 §11.4](09-特效设计与庆祝感升级.md)）。

## 13. 等级即荣誉（目标态，未排期）

> 同属原 doc 10（编号已撤销）的"B 路"。此处只记方向与代价，**不是排期承诺**。

**主张：把 L0–L5 升格为唯一语言，废弃与它并行的独立荣誉名册。**

每档一个名字、一种视觉签名、一笔挂在档上的奖金；跨面不再单独发徽章，只作为档位内的加成记号。

- **收益**：玩家只需要背 5 个词，而不是 6 个 ID + 5 个内部等级。§12.1 的"四张奖状"问题从结构上消失。
- **代价**：`honors.js` 结构改写；本文旧版按 6 枚实测的 share 频率表，以及 `tools/reachability-baseline.json` 的 `honorOccurrencesPerGame` / `honorGamesPct`，**全部需要重测**。
- **时机判断**：`TIER_CUTS` 至今全为 `null`（§8），一次都没标定。荣誉改动会改奖金总和 → 改分数分布 → 改阶位切点。**趁未标定动手最便宜**，再拖就要连标定一起返工。
- **与分阶轮的关系**：09 §4.3 的刻度 pip 与档位词条就是这一方向需要的 UI 载体，先做分阶轮不会白费——落地时表现层不必再改第二次。
