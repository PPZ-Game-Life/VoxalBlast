# VoxalBlast 立项 PRD

> 版本：MVP v0.2  
> 项目：VoxalBlast  
> 平台：CrazyGames Web 端  
> 文档状态：首版策划基线  
> 发行基线：CrazyGames Quality / Gameplay / Technical Requirements

## 1. 一句话卖点

在 六面体(每面 5×5) 的立体空间里把平面拼块贴到六个面上，某个面铺满一行或一列即可消除；每次落子都可能触发多线连爆，玩家手持 3 个朝向固定的可观察方块，持续挑战“差一格就清屏”的心跳感。

## 2. 产品定位

VoxalBlast 是一款单人、短局、无重力的 3D 拼块消除游戏。它保留 Block Blast 的手动放置和“没有合适位置就结束”的紧张感，同时把平面棋盘折成一颗可转动选面的六面体。

目标玩家：喜欢轻量益智、碎片化游玩和高分挑战的网页玩家。  
单局时长：目标 2～5 分钟。  
首发原则：先把放置、视角观察和消除反馈做顺，再扩展道具、成长或社交系统。

## 3. 核心体验支柱

1. **看得懂**：玩家始终能理解方块占据哪些格子、还能补成哪些线。
2. **放得准**：鼠标拖拽、吸附和预览让落子结果可预期。
3. **看得清**：可转动立方体选面并滚轮缩放，方块在候选槽与棋盘上的朝向始终一致，落点关系一眼可判。
4. **爆得值**：一次落子消除多条线时，镜头、粒子和分数反馈必须形成明显奖励。
5. **输得服**：Game Over 只在确实没有可放位置时触发，并展示本局分数与重开入口。

## 4. 核心循环

1. 生成或展示 3 个朝向固定的方块。
2. 玩家先转动立方体把目标面转到朝前，再把方块拖到该面的合法格位（方块朝向固定，不可旋转）。
3. 方块固定，无重力，不会自动下落。
4. 检查当前面是否出现铺满的行线或列线。
5. 消除所有满足条件的线，结算连击和分数，播放反馈。
6. 补充新的方块，继续下一回合。
7. 当前方块均无法放置时进入 Game Over。

## 5. MVP 范围

### 必须包含

- 六面体(每面 5×5) 立体棋盘。
- 3D 方块渲染、选中态、落点预览和合法性提示。
- 3 个固定朝向方块的回合制供给。
- 局内四道具：换批 ×2 / 锤子 ×1 / 火箭 ×1 / 炸弹 ×1（单局配额，不跨局保留）。
- 鼠标拖拽放置与自动吸附。
- 立方体旋转选面（水平偏航 + 垂直俯仰）与滚轮缩放；不提供镜头复位功能。
- 在单个面上检测并消除完整的行线与列线。
- 多线同时消除、连击倍率和基础分数。
- 立方体转动选面、滚轮缩放、被遮挡方块半透明。
- 差 1～2 格的候选线高亮或呼吸提示。
- 消除粒子、镜头轻微震动、分数跳字。
- Game Over、最终分数和重新开始。

### 明确不包含

- 技能、付费、广告奖励和成长系统（局内仅提供配额型四道具，不引入商店/金币）。
- 重力、自动落下、层面整体消除。
- 联机、排行榜、账号和长期成长。
- 首版复杂教程或强制操作教学。

## 6. 关键约束

- 棋盘尺寸固定为 六面体(每面 5×5)，首版不要扩大为 8×8×8。
- 消除单位是单个面上的完整一行/一列（5 格），不是整层消除、也不是跨面的三维直线。
- 方块放置后保持原位，不受重力影响。
- 每回合只提供 3 个方块，降低三维信息负担。
- 不能放置新方块时才 Game Over，不因棋盘看起来拥挤直接结束。

## 7. 成功标准

- 新玩家无需文字教程即可在 30 秒内完成首次放置。
- 玩家能从预览看出方块落点，不因镜头遮挡产生误操作。
- 中后期平均每 2～3 步出现一次差 1～2 格的候选线状态。
- 消除一条线和同时消除多条线的反馈层级明显不同。
- 一局能稳定完成 2～5 分钟的连续决策，不出现无意义等待。
- 首屏尽快进入实际可玩棋盘，不使用独立宣传型 Landing Page 阻塞游戏。
- 在 CrazyGames Web 环境中，加载、失焦、广告返回和重开流程均保持稳定。
- 单局采用 Block Blast 式布局：顶部紧凑信息条（左侧 SCORE 积分胶囊 + 右上设置，开发版版本号居中悬浮、正式版移除不改变布局），中间为大面积 3D 棋盘，底部为道具与候选方块条；顶部不显示游戏名。

## 8. CrazyGames 发行约束

- 首屏优先加载棋盘、基础方块和核心交互，非必要资源延迟加载。
- Loading 必须有明确状态，不能出现长时间无反馈、白屏或黑屏。
- 页面失去焦点、切换标签页或广告展示时暂停游戏并停止接受放置输入。
- 恢复后不得重复放置、重复计分或跳过当前回合。
- 运行时画面必须全量程序化生成：方块、棋盘、背景、UI、材质、纹理、光影、粒子和过场不得依赖外部图片、贴图、视频或预制 3D 模型；允许使用由代码生成的几何、CSS、Canvas、Shader 与运行时数据。
- 在 Three.js 基础上引入业界成熟组件增强品质：`postprocessing` 承担抗锯齿、泛光和后处理链，`three.quarks` 承担批量程序化粒子；禁止引入不可解释的素材包或仅作装饰的重型框架。
- 3D 资源、粒子、阴影和后处理应支持移动端或低性能设备降级；降级只减少粒子数量、阴影采样和后处理质量，不改变核心规则与反馈语义。
- 桌面端和竖屏移动端都必须能完成一局，不能只适配缩小后的桌面布局。
- 上线前必须检查控制台持续报错、资源加载失败、无法重开和异常卡死。
