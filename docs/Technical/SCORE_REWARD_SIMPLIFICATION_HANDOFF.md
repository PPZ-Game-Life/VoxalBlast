## 0. 一句话目标与范围

**平时安静，精彩时说清楚“你做对了什么”；三类奖励、一次结账、一场庆祝。**

## 2. 新计分：基础分 + 三类额外奖励

### 2.1 唯一公式（首轮推荐值）

定义：

- `P`：本次成功放置的格数。
- `L`：同一次正常落子结算的满线总数；沿用现有六面计线口径。
- `C`：本次结算后的连续消除次数，有消除时旧值 +1，无消除时归 0。
- `W`：本次 `faceWiped` 去重后的面数，范围 0–6；不是 `facesHit`。

```text
基础放置分 = 10 × P
基础消线分 = 100 × L

一次多消奖 = L >= 2 ? 100 × (L - 1) : 0
连续消除奖 = L > 0 且 C >= 2 ? 50 × min(C - 1, 4) : 0
清除整面奖 = L > 0 ? 300 × W : 0

本次总分 = 基础放置分 + 基础消线分
         + 一次多消奖 + 连续消除奖 + 清除整面奖
```

| 类别 | 起奖 | 递增与封顶 | 奖励意图 |
| --- | --- | --- | --- |
| 一次多消 | 同手 2 线 +100 | 3 线 +200、4 线 +300、5 线 +400；每多一条线额外 +100 | 做大一手，公式易懂，不再叠旧倍率 |
| 连续消除 | 连续第 2 消 +50 | 第 3/4/5 消 +100/+150/+200；第 6 消及以后每次仍 +200 | 保持节奏，但不靠无限链长滚出爆炸分数 |
| 清除整面 | 1 个面 +300 | ~~2 面 +600，依此类推~~ **不可达**（只算落子面，W ∈ {0,1}） | 空间释放有明确回报，不要求先铺满整面 |

三个奖金均为**加法**，可以同手并存，且各结算一次。没有全局乘分、奖金再乘连消、荣誉返奖或同类阶梯逐项累加。

注意：新规则下单线首次消除、未净面时是 `基础放置分 +100`，没有额外奖励；仍保留普通消除声音和局部线反馈，不等于静音。

### 2.2 一次多消：只看这一手

- 只合并本次正常落子同时形成的满线，不把连续两手的线数凑成多消。
- 一条共享满棱在现行规则中属于两个面、计两条线：仍可触发 2 线多消。**不借本次简化改掉共享计线。**
- 相交线、共享格只删除一次；实体退场与粒子去重，不因计两线而爆两遍同一格。
- 文案为「一次消除 3 线」/ `3-LINE CLEAR`，不用“3 连击”混淆链长。

### 2.3 连续消除：第二次才算奖励

- 正常成功落子有消除：`C += 1`；无消除：`C = 0`。
- 连续第一消只建立链，不发连消奖、不出现连消提示。
- 换一批候选不打断；道具删除、道具撤销、换批道具、取消拖拽、非法释放、转面、暂停均不推进也不打断。
- 同规则版本的续玩恢复真实链长，但不补发奖金、不补播提示。
- 第 5 消及之后保持 +200，**显示真实次数**（如连续消除 12 次），不把次数也截成 5。
- 不设时间倒计时，不因思考慢而断链。无消除落子静默断链，不震屏、不播失败惩罚音。

### 2.4 清除整面：落子前非空 → 正常结算后为空，且**只算落子面**

> **制作人修订（2026-10-01，本稿实现后）：清空一面只算方块放置的那一面，侧面不算。**
> 因此 `W` 的取值范围从 0–6 收窄为 **0–1**：共享棱/角上的格子被邻面的线带走时，邻面也会跟着
> 变空，但那不是玩家这一手的目标面，不发奖。`wipedFacesFor()`（`src/game/scoring.js`）是这条
> 收窄的唯一实现，奖励、短签、面扫亮与 `run.faceWipes` 全部消费它的输出。
> 本节下方描述的是收窄**之前**的口径，保留作对照。

使用现有 `faceWiped`，不要另写一个“看起来空了”的表现层判断：

1. 在**本次拼块写入棋盘前**，记录六面的占用数；该面必须大于 0。
2. 本次正常落子至少消掉一条线。
3. 所有满线同批删除后，该面占用数为 0，便计 1 个净面。

这不是“某面铺满 25 格再消掉”，也不是“本次在某面消过线”。具体边界：

- 落子前已经空的面不奖励，开局六面空不发奖。
- 落子前空、本手短暂写入再被清空，仍不奖励该面（与当前 `faceWiped` 一致）。
- **（已修订）** 即使该面只剩 1 个共享格，被邻面正常消线带走后变空，**只在它就是落子面时才计净面**；
  侧面被带走不计、不发奖。
- 同一面一手只算一次；以后重新占用，再由正常落子清空，可以再次领奖。没有整局“一面只能一次”的隐藏限制。
- 锤子/火箭/炸弹直接清空面不发该奖；撤销不发奖；后续正常落子以当时真实盘面判定，不追补道具清空的面。
- 全棋盘清空只按实际 `W` 计净面奖，**不另加全清/净体第四类奖励**。

这是沿用已有净面语义、降低实现歧义的推荐方案，不是对“整面”一词唯一可能的解释。净面可能较常见，不能默认等同稀有大奖；若试玩过密，先调该类分值与演出强度，不暗加最低占用阈值。

### 3.2 三类视听签名（首轮参数，需实机调校）

采用现有木作/纸彩庆祝资源，不要求重做素材。颜色只是辅助，必须同时有文字和不同节奏。

| 类别 | 短暂文案 | 视觉签名 | 激励音效 | 默认轻震 |
| --- | --- | --- | --- | --- |
| 一次多消 | `一次消除 {L} 线` / `{L}-LINE CLEAR` | 真实消线同步亮边，向外一次展开的小纸彩；线数越多构图更完整 | 短上行木琴，2 线两音、3 线及以上加收束音；4+ 线用封顶增强版，不无限升调 | 2 线约 1.5 CSS px/80ms；3 线约 2px/100ms；4+ 线约 3px/120ms |
| 连续消除 | `连续消除 {C} 次` / `STREAK {C}` | 紧凑纸签一次双拍弹出，短星点接力；不是大礼花 | 辨识度明确的两次短木敲/木琴“接上了”；C=2–4 渐进，C>=5 音型封顶 | 约 1 CSS px/60ms 的短双脉冲，合计在窗口内结束 |
| 清除整面 | `清空 {W} 面` / `{W} FACE(S) CLEARED` | 清空面的可见边框扫亮一次，面形小印章收束；背面只用文字/图标说明，不强转镜头 | 柔和扫纸 + 明亮短和弦，与多消上行旋律区分 | 1 面约 2px/100ms（**没有 2+ 档**：只算落子面） |

- 震动幅度指棋盘画面在屏幕上的最大偏移量，不是直接把数值填入现有世界单位 `shake`。
- 只允许受控的表现偏移，HUD、候选、按钮、拖拽命中与逻辑相机不抖；新拖拽开始立即收敛。若现有实现无法保证投影/落点一致，先用局部纸签弹动代替，不为震屏牺牲手感。
- `prefers-reduced-motion` 下震屏为 0，取消位移弹跳/慢放，保留静态文字和温和短亮边；声音由独立音效开关控制。
- 普通放置、单线且无额外奖励、断链、道具清理不触发这套奖励震屏。道具保留各自原有成功反馈。
- 三类触发均有视觉提示；开启并成功解锁音频时均有激励声音。声音关闭/浏览器拒绝音频时照常结算，不积压待播。

### 3.3 同手多类命中：账可以叠，演出不能叠

**一个主标题、一条合并明细、一个总分跳字、一个主声音、一次震动。**

- 主标题优先级固定为：**清除整面 > 一次多消 > 连续消除**。这是说明顺序，不声称净面一定最稀有。
- 同手其他奖励放到同一张短签明细里，不顺次弹三张奖状、不另起附属荣誉徽章行。
- 示例：标题「清空 1 面」；明细「3 线 +200 · 连消 4 次 +150 · 清面 +300」；另一个总分跳字 `+990`，含基础分 340。
- 明细中的 `+N` 是该类**额外奖金**，总分跳字才是本手全部得分，不能让两个数字都叫“总加分”。零奖金的类别不展示。
- 窄屏允许同一张短签分成两行，不遮挡棋盘/候选/道具，不缩小棋盘腾地方；基础分不再额外播一张奖状。
- 主声音按主类别选音型，次类别用纸签明细表达；允许在同一 cue 内加入一个连消收束音，不同时播放三段曲子。
- 震动强度取本手各类建议值的**最大值**，不相加；粒子使用整次事件预算，不乘类别数、面数或共享格数。沿用现有已验收预算，不因本轮增加上限。
- 保持 v0.10.1 已有的单主音机制，普通消线触感并入奖励 cue 起音；新增三类奖励不能各自再起一条旋律。分数 tick 继续降低或让位。

### 3.4 时序和抢占

`t=0` 是成功规则结算完成：分数、链、候选消耗立即按逻辑更新，不等待演出。**保存与卡住检查保持现有调度**：本手用掉最后一个候选时，必须等 `nextPieces()` 补齐新批后再保存和检查（`src/main.js:1052–1065`），不能为配合演出改成在空候选窗口立即保存。

| 时间 | 表现 |
| --- | --- |
| 0–120ms | 消线位置确认；一次短震与奖励主音起音 |
| 100–240ms | 合并奖励短签出现，不重复旧荣誉横幅 |
| 160–450ms | 本手一个总分跳字；HUD 数字按现有滚动汇入 |
| 700–1000ms | 短签退场；多类并发可到 1200ms，不能常驻 |

单次主 cue 建议不超过 800ms。新落子到来时，旧短签/尾声可淡出替换，**不排队等庆祝播完**；未结完的分数滚动必须追向最新真实总分，不能丢增量。暂停、隐藏、回主页、重开、读档清理短命事件；不重播、不重复入账。局终取消局内尾声后，才播放独立的新纪录反馈。

旧 L0–L5 可作为基础消线资源强度映射保留，但不能继续按 `facesHit>=3` 自行升级奖励，也不能触发旧荣誉奖金/横幅。新奖励展示必须直接消费本次统一奖励结果；没有旧 `honors.primary` 的 2 线多消、连消、净面也必须正常出现。

## 4. Jeffy 的实现契约与改动范围

### 4.1 结算输出与单一事实源

推荐结算输出（字段可依项目风格调整，含义不能丢）：

```text
score = {
  placement, linePoints,
  multiBonus, streakBonus, faceClearBonus,
  total
}
rewardEvent = {
  eventId, scoreRulesVersion,
  lines, chain, wipedFaces,
  rewards: [{ type, count, bonus }],
  primaryType
}
```

- 三类类型固定 `MULTI_CLEAR / CLEAR_STREAK / FACE_CLEAR`；零奖金不生成奖励条目。
- `wipedFaces` 必须保留面 ID，不只有面数，供局部轮廓与去重消费。
- 数值常量集中在 `scoring.js`；结算一次产出三类结果。HUD/音频/VFX 不重算分数、不分别判定是否应该发奖。
- `eventId` 绑定一次成功落子，表现层渲染、resize、语言切换、恢复页面不得当作新事件；逻辑入账也不能依赖动画回调。
- 正常逻辑顺序仍是：落子与消线 → 更新链 → 计算分项 → 入账与统计 → 发布表现事件 → 保存/后续现有流程。

## 5. 旧分数与存档：本轮不能忽略的兼容风险

本稿会显著降低高线数单次得分，**不是与旧分制等价的公式整理**。新旧 BEST、周最佳、最近局不能直接混用，也不能猜一个比例换算旧分数。

推荐采用明确规则版本，实施时一并交付：

1. 新局写入 `scoreRulesVersion = 2`，缺字段的旧档视为版本 1；注意它与已有 `SESSION_VERSION = 2` 是两回事，不能共用这个数字字段。
2. 已开始的旧局继续使用旧计分直到结束，不中途改价；给予“旧规则续局”的一次性说明。该局也不恢复常驻 Combo，旧特殊奖励无需新增专属演出，沿用基本消除反馈即可。**“只有三类额外奖励”适用于版本 2 新局。**
3. 旧局结束写入旧规则纪录区；新局写版本 2 纪录区，BEST/周最佳/NEW BEST 只比较相同规则版本。保留旧记录只读查看，不清空旧 localStorage。
4. 版本 2 局结算显示三类奖励口径；历史荣誉、分数不重算、不自动转成新奖励次数。个人统计如需汇总须标明口径，默认按版本展示。
5. 平台在线榜若实际启用，发布前确认新分制独立榜/赛季路由；平台不支持隔离时暂停版本 2 向旧榜提交，明确展示不可用状态。不得以客户端多传一个版本字段就宣称完成分榜。
6. 不能实现旧局双版本计分时，先反馈给制作人确认替代迁移方案，**不得静默丢档或让同一局前后混用两套分数**。

若确认当前构建从未面向用户发行、无需兼容，也只能经制作人明确同意后简化此节，不由 Jeffy 自行清库。

## 7. 实施顺序与调参原则

1. **先跑通新公式与版本兼容**：分项可复算，净面判定有真实盘面测试，无隐藏旧奖金。
2. **再移除常驻 Combo 并合并奖励短签**：先把玩家读到的信息收敛，不用大特效遮掩规则问题。
3. **接三类视听签名与仲裁**：复用已有资源，优先保证输入稳定、单次声音与减少动态效果。
4. **试玩后只调集中参数**：观察三类触发频率、分数占比、最长连消与提示密度。当前没有真人样本，不能承诺平衡已成立。

本轮推荐的多消奖励是易懂的线性增量，会削弱旧版极稀有高线数的超额收益；这是简化的代价。若试玩认为高线规划不值得，先调同一多消公式/表，不把旧荣誉奖金、跨面奖和里程碑叠奖请回来。

**交付完成标准：玩家无需背荣誉名单，就能说清楚“这一手多消了、我连着消了、这一面清干净了”，分数与声音都对得上。**
