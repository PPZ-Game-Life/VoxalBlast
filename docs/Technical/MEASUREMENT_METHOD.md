# 难度与形状测量的方法说明（可复核版）

> v0.8.16 / 2026-09-21。**目的**：任何一位评估者（策划、外援、后来的维护者）照着本文就能复跑、能判断口径是否合理、能定位每一个结论数字的出处。
> 适用文档：[现行池难度曲线](DIFFICULTY_CURVE_POOL14.md)、[方块清单对照](SHAPE_POOL_VS_BLOCKBLAST.md)、[紧张度测量](DIFFICULTY_TENSION.md)（历史）、[KNOWN_GAPS](KNOWN_GAPS.md) 的「验证边界」段。
> **一句话**：所有难度数字都来自 `tools/` 里的模拟器，它直接 import 游戏的规则层（棋盘、形状、权重、开局），但**不含道具、不含渲染、不含真人**。

## 1. 测量系统总览

| 工具 | 回答什么问题 | 是否 import 玩法代码 | 产物 | 命令 |
| --- | --- | --- | --- | --- |
| `tools/difficulty-model.mjs` | 规则镜像：位棋盘、放置枚举、发牌、开局、四种打法 | **是**（`src/game/board.js`、`shapes.js`、`SHAPE_WEIGHTS`） | 无（被下面两个调用） | — |
| `tools/difficulty-abcd.mjs` | 跑臂、出紧张度面板 / 生存曲线 / 12 步分桶 / 逐件压力 / 死亡手牌 | 是（经 model） | `<out>.json`（全量，数十 MB，**不入库**）、`<out>.summary.json` + `<out>.html`（入库） | `npm` 无脚本，直接 `node` |
| `tools/difficulty-tests.mjs` | 口径自检：池定义、随机流、面板计数、测量池＝游戏权重表、不变量 | 是 | 终端 26/26 | `node tools/difficulty-tests.mjs` |
| `tools/reachability.mjs` | 历史可达性测量（早期"能不能结束"那一轮） | 是 | `tools/reachability-*.json` | `npm run reachability` |
| `tools/shape-geometry.mjs` | 纯几何：每种形状的落位数 / 占盘面 / 占行长 / 能否自清 | **否**（只读形状定义） | 终端表格 | `npm run probe:shapes` |
| `tools/face-fragility.mjs` | 纯几何蒙特卡洛：N×N 盘面上"没有空 3×3 窗口"的概率 | **否** | 终端表格 | `npm run probe:fragility` |
| `tools/rescue-probe.mjs` | 实机（无头 Edge）：卡住时三分支救局判定 + 死局中道具可否武装 | 是（跑真实构建的 dev 页面） | 终端断言 | `npm run probe:rescue`（需先 `npm run dev`） |
| `tools/screenshot.mjs` | 实机截图与 DOM 硬门（含结算面板两张） | 是 | `artifacts/visual/*.png` | `npm run shot`（需先 `npm run dev`） |
| `tools/rule-tests.mjs` | 规则层单元测试（棋盘/形状/计分/荣誉/存档） | 是 | 终端 255/255 | `npm test` |

**为什么模拟器要 import 玩法代码**：形状池与权重必须"测的就是发的那一套"。`soft75` 池的权重表直接来自 `src/game/shapes.js` 的 `SHAPE_WEIGHTS`，`difficulty-tests` 会断言两者相等——这样游戏侧改权重而测量没跟上时会直接报错，而不是悄悄测旧池。

## 2. 模型层：棋盘、放置与结算

| 项 | 实现 |
| --- | --- |
| 棋盘 | 5×5×5 外壳的**共享晶格**，6 面 × 25 − 共享棱角 = **98 个唯一格**；状态是 4×`Uint32` 位图 |
| 面 | `+x −x +y −y +z −z`，每面是独立的 5×5 平面 |
| 放置合法性 | 形状的**四个平面内朝向** × 六面 × 合法原点，全部枚举成 `PLACEMENTS`；`canPlace` 要求目标格全空 |
| 消除 | 面内**满行/满列**（5 格）即清；一次落子可以同时清**多个面**的多条线（`settle` 返回 `lines`、`faceBits`、`cellsCleared`） |
| 结算顺序 | 落子 → 找满线 → 清除 →（模拟**不计分**） |
| 开局 | `OPENING_LAYOUT`（+z 7 / +y 3 / +x 3 为目标占面数），由 `Board.seedOpening` 生成，且断言不产生满线 |
| 局终 | 手上（尚未使用的）候选**全部无处可放**。**模拟里没有道具**，所以不存在 B1 那类豁免 |

⚠️ 模拟与正式游戏的三处差异，读数字时必须记住：**①无道具**（游戏里卡住可用换批/锤/箭/弹救，模拟不能用）；**②不计分**（分数相关结论只能从计分公式推）；**③无渲染**（掉帧、动画时序都不在测量范围内）。

## 3. 指标定义

| 指标 | 定义 | 读法 |
| --- | --- | --- |
| `mobility` | 手上**仍然存在的不同形状**的合法物理落点总数（同一形状在多个槽位不重复计） | 会被小件放大：一个 Dot 单件就有约 70 个落点 |
| `tight` | 该步 `mobility ≤ 8` | 极紧步的"密度"指标，事故密度而非严重度 |
| `zeroPct`（逐件） | 该形状在**在手**的步数里，**一个合法落点都没有**的比例 | 逐件的"瓶颈度"；Block 9 = 21.4%，其余 ≤1.8% |
| 平均合法落点（逐件） | 该形状在手时的 `shapeOptions` 均值 | 与 `zeroPct` 一起读；Block 9 = 4.9，Line 5 = 13.8 |
| 一局最紧时刻（中位） | 每局 `mobility` 的最小值，再取各局的中位数 | **抗小件膨胀**的余量指标 |
| 可选≤19 格占比 / 80+ 格占比 | `mobility` 落在粗桶里的步数占比 | 桶是粗的，只作占比报告，不做插值分位 |
| 三块全可放 / 三选一唯一 | 手上 3 个**不同**形状是否都有落点的步数占比；"唯一" = 只有 1 个可放 | 按"手上仍有几种不同形状"分层统计，否则最后一块会稳定报出 ~33% 的假信号 |
| 生存曲线 `S(n)` | `P(成功落子数 ≥ n)`，阈值 12/30/60/120/300/600 | **没有通关条件**，所以不报"胜率" |
| Wilson 95% | 结束率的二项置信区间 | 只表达抽样不确定性，不含真人差异与模型误差 |
| 12 步分桶 | 每 12 步一个进度桶，桶内统计仍在场对局的占用格 / mobility / 极紧步 / 消除步 / 净增格 | **幸存者偏差**：越靠后的桶只剩活得久的局 |
| `endHand` / `deathHand` | 终局时手里的形状名；因为局终时每一块必然零落点，它本身就是死因归因 | 无需靠臂对照反推 |
| `dealsPerGame` | 每局发牌批次数（一批 3 块） | 局长与"清线次数"的代理 |
| `restrictedMeanSteps` | `E[min(T, 600)]` | **不是**无限时长的期望；超过上限属右删失 |

## 4. 臂（测什么）与打法（谁来玩）

**臂 = 池 × 发牌模式 × 开局**（`--arms=<pool>/<dealer>`，开局用 `--groups=A..D` 那套）。

| 池 id | 含义 | 备注 |
| --- | --- | --- |
| `soft75` | **正式池**：`SHAPE_WEIGHTS` 原样（现行 14 类，四格件×2、其余×1） | 唯一"跟着游戏走"的池 |
| `current` | v0.8.4 之前的十类等权池 | 历史对照 |
| `b9w04` / `no9` | 正式池把 Block 9 权重改 0.4 / 删掉 | Block 9 归因臂 |
| `bb4` / `bb5` / `bb` | 正式池 + `Line 4` / + `Line 5` / + 两者 | **测量专用**：这两个形状只存在于 `tools/` 的 `EXTRA_SHAPES`，**不在 `src/`** |
| `c` `d` `w90` `e` `e5` `soft82` | 早期压缩池候选 | 冻结在测量时点，不随游戏变化 |

**发牌模式**：`uniform` = 按池权重等概率；`staged` = 按局内阶段加权（实验项，未上线）。

**打法**（机器人，不是真人分层）：

| 策略 | 行为 | 代表谁 |
| --- | --- | --- |
| `random` | 在所有合法落点里**等概率乱选** | 下限/最差玩家；现行池下中位 23 步 |
| `greedy` | **按手牌槽位顺序取第一个放得下的形状**，在该形状内选**立即消除线数最多**的落点（并列取枚举序第一个） | "会消除就行"的玩家；**注意它是逐槽位的贪心，不是全局最优** |
| `noise` | 同 `greedy`，但 25% 的概率在该形状的合法落点里**随机**选一个 | 典型玩家（本项目的"典型"代理） |
| `space` | 一步前瞻启发式：**先看能否消除 → 再保空位 → 再紧凑度** | 熟练玩家上限（现行池下 0% 结束） |

**这四种都不是真人**：槽位优先级、无长期规划、无道具使用。结论只能读成"在这一族策略下会怎样"。

## 5. 随机数与可复现性

- 随机源：**FNV-1a 哈希流身份 + mulberry32**，每条流独立：`deal`（发牌）与 `policy`（决策）分开，`(seed, gameIndex, stream)` 三元组决定整条序列 → 同一命令逐值可复现。旧版 LCG 会按种子聚簇（单种子结束率可偏差约 14pp），v0.8.3 起已换掉。
- **配对比较**：同一 `seed/gameIndex` 的两个臂共享发牌流，所以"谁先死"的差异不是运气；`difficulty-abcd` 会输出逐阈值配对的百分点差与 `leftOnlySurvived/rightOnlySurvived`。
- 采样量：报告里的每组数字都是**每臂每打法 600 局（3 种子 × 200 局）**；`space` 因耗时按 150 局（3 × 50）。逐种子结束率单列在表里，避免"只看合计"。
- 结果带**源码指纹**：`summary.json` 里记录了命令、选项与规则层源码的 SHA256，可核对"这份数字是不是这份代码跑出来的"。

## 6. 产物与入库约定

- **入库**：`tools/results/<name>.html`（图）+ `<name>.summary.json`（聚合值、逐种子统计、配对比较、源码指纹）。
- **不入库**：`tools/results/<name>.json` 全量文件（逐局记录、每种子第 0 局的轨迹、逐步骤生存曲线、12 步分桶）。因此**报告里"曲线"一类的细粒度数值来自本机全量文件**，复跑同名命令即可重建。
- 逐件压力（`shapePressure`）、死亡手牌（`deathHand`）、逐形状发牌占比随 `.summary.json` 一起入库。

**实测耗时**（本机同规格）：2 臂 × 3 打法 × 600 局（3600 局）≈ 39 秒；4 臂 × 3 打法 × 3 种子 × 200 局（7200 局）≈ 37 秒；`space` 300 局 ≈ 91 秒。`greedy` 最慢（长局多，逐局可到 600 步）。

## 7. 已知偏差与不可外推项（评估者必读）

1. **无道具**：游戏里卡住时有换批/锤/箭/弹（B1 起清理类也参与救局），模拟一律直接结束 → **真实结束率必然低于全部模拟数字**。
2. **机器人不是真人**：`greedy` 是逐槽位贪心、不保留空间、不用道具，比会玩的真人保守也差；`noise` 只是"典型"的粗糙代理。任何"真人会怎样"都需要真机试玩。
3. **六面通算**：`mobility` 是六面合并计数，不区分"某个面不行但另一个面行"；`faceFragility` 那类单面概率是几何代理，不是对局结果。
4. **幸存者偏差**：12 步分桶曲线只统计仍在场的对局，越后越偏乐观。
5. **右删失**：>600 步记为删失，**不是**"600 步通关"；`p50 = >600` 表示"观察不到中位"。
6. **池的冻结**：只有 `soft75` 跟随游戏权重；其余池（含 `b9w04`/`no9`/`bb*`）是测量时点的固定定义，游戏侧改动不会自动同步（`difficulty-tests` 会在成员/权重层面报错提示）。
7. **Block Blast 无法测量**：我们跑不了它的引擎。涉及它的部分分两类——**精确几何**（落位数、占盘面、占行长、能否自清）与**第三方资料**（清单成员、发牌是否均匀、是否有复活/God Mode），后者在文档里都带 🔸 标记，属未核实。
8. **模拟不记分**：任何"分数被污染"的结论都是从 [02 §5](../Planning/02-核心规则与数值.md) 的计分公式推出来的，不是测出来的。

## 8. 复核检查点（建议评估者按此顺序看）

1. **口径自检**：`node tools/difficulty-tests.mjs` 必须 26/26——它锁定池成员与权重、随机流、面板计数口径、以及"5 长直线必清线"这类不变量。
2. **同一命令复跑**：种子固定，聚合值应**逐值一致**；不一致说明测量池或权重被动过（这是设计意图，不是噪声）。
3. **数字出处**：任一结论数字都能在 §9 的产物表里找到对应 `.summary.json` 字段；细粒度曲线在本机全量 `.json`。
4. **结论的适用范围**：对照 §7 逐条检查——凡是超出"模拟、无道具、机器人"三界的判断，都应视为假设而非结论。
5. **反例/负对照已存在**：救局判定有负对照（关掉 B1 分支，探针必须失败）；形状不变量有正断言（Line 5 每次合法落子必清线）。评估新结论时可要求同样的证据形式。
