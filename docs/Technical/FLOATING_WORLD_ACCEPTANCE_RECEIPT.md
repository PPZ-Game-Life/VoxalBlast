## 3. 与 V4 并排比较：仍有的差异

1. **盘面是空的，V4 有彩色块**（默认开局即空盘，属 fixture 差异，不是渲染缺陷）。
2. **可见天空比 V4 少约 20 个点**：地平线解到 `edgeFromTop 0.390`，V4 的蓝天空带约占画面 45%。
3. **主盘占屏比 33.8% vs V4 约 38%**——§1.3 明确「不为了像参考图首先改 FOV / 相机角度」，
   这是**刻意保留的偏离**。
4. **两侧积木的数量与体量低于 V4**：竖屏下主盘占屏宽约 72%，两侧各只剩约 55px，装饰只能是贴着
   画框的窄条。按 §4.2「侧边缺空间就减少，不缩主盘来迁就装饰」刻意保留。
5. **接缝比配方给的背壳色更暗。** 390×844 正面横向扫描（y=340 与 y=400 两条独立扫线，x 90..300，
   读数一致）：格体亮度 **227**、缝底亮度 **33**，**缝比面暗 85%**（比值 0.147），
   半深宽度 **11px**（该视口格距 48.9px，约 22% 一格）。而配方给的背壳色是 `#243A4A`、亮度 **49**
   ——**缝比它自己规定的颜色还暗 33%**。
   **关键一条：这个视口上 SSAO 根本没开**（`getRenderQuality().lowPower` 在 ≤700px 处为真，
   且 `SHADOW_STYLE.lowPowerSSAO = false` ⇒ `useSSAO = false`；探针里 `tier: "low"`、`tierSpec.ssao: false`）。
   所以**手机的接缝变黑不是 SSAO 造成的**，§6.3-A 的排除法必须在**桌面档**（1440×900，`tier: "high"`、
   SSAO 开）上跑，不能拿手机这张图下结论。
   **§6.3-A 的 A/B 已做（本轮）**：1440×900、其余不变，`__voxalblastDev.ssao(false)` 把
   `ssaoEnabled` 从 `true` 切到 `false` 后重拍，两条扫线（y=300 / y=380，x 500..780）读数
   **逐位相同**——格体 227、缝 33、比值 0.147、半深宽 12/14px 两边一模一样。
   **结论：接缝的 85% 变暗与 AO 无关**，AO/接触暗化这条排查项到此排除；下一个变量是
   背壳色与相对光比（§6.3-D），不是 AO。
   另一条顺带得到的：桌面与手机的接缝比值都是 **0.147**、格体都是 227——它在两档之间是**比例不变**的。
   与 V4 的同口径对比仍未成立：直接扫概念图那一版扫线落在棋盘外轮廓上
   （缝底亮度 1、半深宽 152px），量的是黑描边不是内部接缝——**无效，不入结论**。
6. **软投影偏淡**：`opacity 0.20` / `heightFactor 0.11`，V4 的影子更重更宽。
7. **主页**：纪录牌与主/次按钮**已换新皮**（`14bedd2`，本会话复拍确认）。旧金冠＋花叶＋金边全部消失。
   仍有的差异：V4 的纪录牌顶的是一顶**大金冠**，本实现是一枚**深蓝描边的小皇冠**——语义对、体量小。
8. **彩漆比配方 albedo 更饱和**：少数通道被压到 0.40–0.78。A/B 显示这一抬升在**蓝色上把画面推向了 V4**
   （Δ26 对配方 albedo 的 Δ36），但**紫色明显不够蓝**（B 183 对 V4 的 240）。

## 9. 侧边装饰被整层剔光：已修（`774fc4a`）

**已解决。** 三层根因，都是量出来的，不是猜的：

1. **禁带矩形是过期的。** 主盘禁带取自 `applyKeepOut` 在 `layout()` 里的快照，而主盘的投影轮廓
   不是常数（开场波次把它搭起来、闲时浮动在呼吸、翻面改变形状）。实测那次的盒子是
   `[-10,197,399,583]`——比主盘自己报出的 `solid 57.66..337.53` 两侧各宽约 65px，**已经横跨整幅画框**。
   改成每帧问一次 `boardBoxMoved()`（阈值 2 CSS px）就重跑 keep-out；修完盒子变成 `[34,205,362,571]`
   （正好是 solid + 24px padding）。
2. **全宽禁带被当成可避让的。** 顶栏与工具行横跨整幅，横向避让永远清不掉；原逻辑仍按「清到边」
   算位移，三个来回把装饰推到**画框外刚好 10px**处（诊断里每个左侧件都停在 `box.right = -10`）。
   改为：只有**窄**禁带才避让，全宽禁带按**面积占比**判（覆盖 > 35% 才剔）。
3. **亚像素残余被当成仍被挡。** 避让正好落在边界时残留 < 0.01px 重叠，而收敛判据在步长 < 0.01px 时
   退出，于是六个已经贴着主盘、可见像素为 0 的件被判为被挡。加 1px 避让余量。

`culled: 9 → 1`（390×844，只剩一个被顶栏盖住一半的散块）；`1440×900` 为 `culled 1 / dodged 0`。
门禁侧另加了三个可观测字段：`dodged`、`blockedBy`（每个被剔件的 id / 是否出屏 / 覆盖率 / 被谁挡）、
`keepOutDebug`（解析后的禁带矩形）——`culled` 一个数说不出「躲开了」与「没地方站」的区别。

**残留（未改，属构图判断）**：竖屏下主盘占屏宽约 72%，两侧各只剩约 55px，所以侧边景物现在是
**贴着画框的窄条**，广场中段仍偏空。§4.2 的处置是「侧边缺空间就减少，不缩主盘来迁就装饰」，
所以这是**刻意保留**而不是待修——但它让 §3 第 4 条（两侧体量低于 V4）依然成立。

**门禁缺口已补**（`a0721cb`）：`npm run shot` 现在除作者数量外，还断言
①存活件数不得低于作者件数的 60%——上一轮生存 1/10，按这条会直接红；
②被**避让**推出画框的件（`offFrame && |shiftedPx| > 1`）即失败。
第②条第一版写成「`offFrame` 就等于失败」，2048×900 立刻误报：那里的 `fore-right` 是**按设计
被画框裁切**（锚点在视口外，正是 §4.2 要的），不是被推出去的。所以模块侧补了 `shiftedPx`——
`offFrame` 单独一个布尔值说不出这两者的差别。

## 10. 彩漆五色正面读数（§6.2 第 2 条的三项判据）

四份 fixture 的调色板都没有青绿/青/紫这几个身份，所以此前量不到。本轮**没有改任何源码**：
在临时目录把 `visual-color-board-a.json` 里的 5 个存储色替换成

### 9.1 归属更正：`af63acb` 里混进了并行会话的 11 个文件

**处理**：**不改写已推送的历史**（`git reset` + force-push 会让对方的本地 main 变成非快进，

错的只是**这次提交的署名与切分**。本行即更正记录。

**教训（写给下一个接手的人）**：仓库里同时有第二个写入者时，
`git commit` 之前必须假定**索引里随时可能有别人 stage 好的东西**。
只提交本轮自己改的路径要用
`git commit -F <msg> -- <路径…>`（pathspec 形式隐含 `--only`，绕开索引），
而不是 `git add <路径> && git commit`。
