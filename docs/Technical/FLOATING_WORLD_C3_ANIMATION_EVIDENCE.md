# C3 动态证据：`npm run evidence:motion`

> 纠偏交接 §7.2 要的是两件**可复算**的东西，不是一句「动画已实现」：
>
> 1. 「交至少一段 8–12 秒片段或 t0/t+8s 对照，证明云和建筑确实移动」——单帧不能验收动画。
> 2. 「再交拖拽/暂停期间冻结、恢复不跳动的片段」。
>
> §C3 的另一半（「主页沿用同一个世界」）由 `14bedd2` 完成，见 [KNOWN_GAPS](KNOWN_GAPS.md) 的主页那一条。
> 本页只负责动态证据。**门禁**：`npm run evidence:motion`，任一断言失败即退出码 1。

## 1. 为什么是成对帧而不是视频

无头浏览器交不出视频。§7.2 自己给了「或」：t0 / t+8s 对照即可。所以本工具交的是**受控帧对**：
两个时钟都能钉死在**绝对时间**上（`__voxalblastDev.setAmbient` / `setBoardFloat`，§8.7 / C0.4），
`{ frozen: true, time: T }` 是**从 T 算出姿态**，不是"停住累加器"，所以同一构建、同一个 T 永远给出同一张图——
前后两张因此可比，而不是"两次随机时刻"。

三个阶段各自回答一个问题，而且**每一条都配了反向对照**，避免"因为什么都没发生所以看起来冻结"：

| 阶段 | 问题 | 正向证据 | 反向对照 |
| --- | --- | --- | --- |
| A | 云和建筑真的动了吗 | t=0 与 t=8 的天空带差异 | 候选托盘（DOM 板）必须 **0 像素**变化；同一 t 复拍必须 **逐像素相同** |
| B | 拖拽时主盘冻住了吗 | 按住 1.2s 前后主盘带 **0 像素**变化 | 同时天空带仍在动（世界没被冻住）；且真的抓起了一块（`preview().piece` 非空、5 格） |
| C | 冻结是「保持」还是「归零」 | 按帧采样主盘投影中心 | 保持值必须**离开中立位**，且等于按下前最后一帧的值 |
| D | reduced-motion 静止 | 全画面 1.5s 前后 **0 像素**变化（maxDelta 0） | ——（这一阶段非零才是失败） |

## 2. 实测（v0.13.1，1440×900，dpr 1，tier=high，云 6 / 纹理 3 / 建筑组 3 / 墙段 2 / 散块 3）

| 读数 | 值 |
| --- | --- |

| A 托盘对照 | **0.00%**（max 0） |
| A 全画面 t0↔t8 | 7.82% |
| A 同一 t=8 复拍 | **max 0**（逐像素相同） |
| A 同一 t=0 复拍 | **max 0** |
| B 拖拽按住 1.2s：主盘带 | **0.00%**（max 0） |
| B 拖拽按住 1.2s：托盘带 | **0.00%**（max 0） |
| B 拖拽按住 1.2s：天空带 | 3.86%（世界仍在动） |
| B 手里确实有块 | `U 5`，5 格，valid |
| C 中立位 / 保持值 | 394.112px / **395.309px**（Δ 1.197px = 振幅的 90%） |
| C 保持值 vs 按下前最后一帧 | **0.061px**（= 一帧的自由位移，不是 0.9px 的落差） |
| C 松手后第一帧 vs 保持值 | **0.000px**（不跳） |
| C 松手后逐帧最大步长 | **0.080px**（阈值 0.5px） |
| C 松手后 3.2s 内位移 | 0.512px（> 0.1px，确实恢复了） |
| D reduced-motion 全画面 | **0.00%**，max 0 |

主盘 bob 是 ±.02 世界单位 = ±1.33 CSS px（1440×900 取景），#C 的三条断言就是围绕这个量级设的：
**0.3px 的"离开中立位"下限**抓"归零型假冻结"，**0.05px 的不跳动上限**抓"相位重启型跳变"，**0.5px 的步长上限**抓瞬移。

## 3. 这一轮踩到并修掉的两个测量陷阱（写在这里，别踩第二次）

1. **`framing.solid` 的角是背景。** 立方体投影出来是六边形，它的 AABB 四角落在棋盘**外面**，
   用未内缩的整条带子量"主盘有没有动"，量到的是云的漂移（实测 418 px、最大 Δ134）。
   现在主盘带左右各内缩 22%、上下从 6% 起，落在棋盘轮廓内部。
2. **按住的那一刻恰好是中立位，就分不出「保持」和「归零」。** 所以按下**之前**会等 bob 走到
   接近极值（1.0px / 1.33px）再按，否则这条断言会在 0 附近随机地"通过"或"失败"。
   另外松手后要等 3.2s（> 半个周期）才读位移，否则落在极值附近会读到 0.4px 的假小值。

## 4. 明确未覆盖（不要把它读成通过）

- **不是视频**，是成对帧；§7.2 允许，但要清楚交的是哪一半。
- **无头软件渲染只有 ~7.6 fps**，而 `main.js` 把 dt 夹到 0.05s，所以这个台子上的**世界时钟只按墙钟的约 38% 走**
  （报告里的 `traceFps` / `gameClockShare` 记录了这一点）。所有位移都是"游戏时间"的读数，不等于真机节奏。
- **没有物理机 / 微信内嵌实测**；没有真机帧耗时。
- 性能档（high/medium/low 的 DPR 上限与装饰数）不在本工具内，见 [R7 性能与回归](FLOATING_WORLD_R7_PERF.md)。

## 5. 复跑

```bash
npm run evidence:motion                            # 1440×900 默认
npm run evidence:motion -- http://127.0.0.1:5173/ artifacts/visual-motion --size=390x844
```

产物落在 `artifacts/visual-motion/`（gitignored）：每个视口 11 张帧 + 一份 `motion-evidence-<WxH>.json`，
JSON 里带全部原始读数与逐帧 trace，报告里的每个数字都能从帧重新算一遍。
**并发编辑会让 dev server 重载页面、句柄短暂消失**，工具会明确报
`page handles missing at phase X`，而不是抛一个位置很深的 TypeError——那不是产品问题，换个没人保存文件的时机复跑。
