# 当前待办与验证边界

> **v0.9.0 / 2026-09-24 — 发牌与渐进难度 P1。** 一批三块不再由三次独立抽取决定：先抽最多 36 个互不重复的组合，逐个**证明**它在当前盘面上能否三块放完，再按"首步容错区间 + 整批压力变化"挑选后才发出去；已证明无解的组合直接淘汰。形状池 14 → **15 类**（`Line 4` 回池、显式权重 1），`Block 9` 权重 1 → **0.4**，并加"一批最多一个 + 发出后三次自然换批冷却"。步数/等级（`tier = min(3, 步数/30)`）与 warmup → 2~3 批 build → challenge → 1 批 relief 的阶段机落地；换批与救场走同一发牌服务；存档 v2 携带导演状态与随机流，v1 存档迁移后**步数从 0 起算并只给一次缓冲**。实现与全部证据见 [发牌与渐进难度 P1 实现记录](DEALING_P1.md)，规则口径见 [02 §3](../Planning/02-核心规则与数值.md)。
>
> **规格 §12.4 的两条判定（7200 局六臂实验，见实现记录 §6.1）**：
> - **#2「D 组卡局不应继续几乎完全由 Block9 支配」——不达标。** 卡住时手里含 `Block 9` 的比例：random **53%**、noise **97%**（v0.9.0 之前的 A 组是 85% / ≈100%）。降到 0.4 加冷却**没有**解除它对卡局的支配。
> - **#5「目标不可达时应调整配置；仍无法建立无 Block9 压力则报告结构性限制」——结构性限制成立。** 去掉 `Block 9`（C/F 臂）后 C/noise 自然结束只剩 **36.7%**、p50 打到 600 步上限，F/noise **13%**，卡局瓶颈换成 `Rect 6`。**没有 `Block 9` 就没有终局压力**，因此不再往"无 Block 9 也能压"的方向调参；保留它、把占比当难度旋钮。
> - **#1「C 组必须比 F 组更明显地出现阶段压力」——在有分辨力的地方成立**：random p50 +15 步、noise 结束率 −23.7pp；但 `clear`/`lookahead` 两臂在 600 步双双 100% 截断，这条对照在这两个策略上测不出来。
>
> **本轮新出现的、必须写清的边界**：
> 1. **没有真人试玩**。全部数字来自机器人与本机浏览器探针；`random`/`noise` 是算法策略，不是水平分层。
> 2. **P2 未实现**（无下一批预览、无跨批队列、无真正的五步规划）。P1 的"连续五步"是持续压力目标，不等于跨批解题；`dealQueuedBatch()` 存在但未被调用。
> 3. **发牌同步执行，没有 Worker**：`tools/deal-perf.mjs` 实测 p95 ≤ 49.9ms、p50 约 38–46ms（本机），满足规格 §11.2 的两条判据，因此没有引入"准备中"状态。**这是本机数据，不代表低端手机或微信/QQ 内嵌环境。**
> 4. **目标可达性**：稀疏盘面上几乎每批 `A = 1.0`，challenge 的 `[0.75, 0.95]` 在开局阶段**够不到**，实现按降级顺序处理（开局段兜底率高）。这是实测事实，不是规则错误，也没有被"修好"。

## 历史结论：v0.8.1 已重测，结论未变

归档 09/10 的模拟报告显示大量对局达到 600 步上限仍未结束，说明短局目标和阶位基准有问题。v0.8.1 用同一支模拟器（同源 import 现行规则）重跑：400 局近似真人模拟约 1% 自然结束、最优玩家 0%，"单局没有自然长度"成立，并解释了"道具整局用不上"——局终条件（三块候选同时无处可放）几乎不发生，换批/锤子/火箭/炸弹没有出手机会。v0.8.3 复核了结构性方案并修正了随机源偏差（旧 LCG 会按种子把整局聚簇，单种子数字可偏差 ~14pp），结论见 [难度与单局长度测量](DIFFICULTY_BASELINE.md)：候选池成分是唯一有效的低风险杠杆（约 28%），缩小棋盘反而更低。模拟不含道具与开局预置，因此表中比例是不救场的上限；短局目标（"2～5 分钟一局"）仍**不能**写成已达到。
