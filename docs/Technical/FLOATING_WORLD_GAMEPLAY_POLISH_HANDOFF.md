## 4. P0-B：主盘和候选共用“细而清楚”的线稿

### 4.1 明确裁决

- 背壳恢复读取 `palette.hull = #243A4A`；ink 继续 `palette.ink = #20334C`。本轮不追认把两者完全合并。
- 核心 block geometry、pitch、hullInset=.68、碰撞/拾取不变；只调整**装饰 ink 壳**。
- `boardInkScale` 不再使用1.055。先以 **1.020** 为候选，做 **1.015 / 1.020 / 1.025** 同状态并排 A/B；本轮上限1.030。它们不是最终像素保证，须看低DPR实图。
- 数学门禁：`blockSize × inkScale < pitch`。不能让装饰壳盖满格间实际空隙。不得把“缩 ink”误做成缩占用格。
- 顶面仍然是完整5×5，不隐藏行、不合并格、不把背面画成假贴纸。斜视内线可以比正面轻，但外轮廓保持完整；按视角/投影检查，不固定某个世界面永远更淡。

### 4.2 屏幕端目标（CSS像素，非949px上传图像素）

以390×844常规竖屏为首轮，区分**物理缝投影**与**额外 ink**：若一个格距约50 CSS px，.05的物理缝本来就约2.5px，不能要求在几何不变时把整条缝压成.5px。正面单侧新增 ink 可先以约.35–.65px为A/B窗口（对应上述scale试验），顶面随投影压缩但仍须可辨；重点消除 ink 侵入实体造成的额外黑带，而不是删除真实接缝。

整体外轮廓保持连续、清楚，格内线不比有效落点提示更醒目。检查320竖屏和844横屏，记录实际DPR与AA；细线不能闪烁、五行不能糊成黑带。数字是试验窗口而非机械相等门禁，不为描边另建三套几何或逐世界面硬编码；不靠大幅抬DPR或锐化掩盖。

### 4.3 候选、拖拽、回飞与落点一起接入

**选定方案：提取共享 ink 构建/更新配置，复用主盘的 back-face silhouette 语言。** 每个既有 renderer 内合批/共享资源，不新增WebGL上下文，不给98格各加后处理。

- 三个候选使用同一颜色映射、同类倒角和轻轮廓，不能比主盘像另一套无边线软糖。
- 拖拽 ghost、回飞快照同步，避免拿起时线稿突然换样。半透明状态的 ink 同步减弱，禁止留下不透明黑壳。
- 合法/非法 marker 保持原色义及优先级；轮廓不覆盖选中框，也不把非法态画成可放。
- 不以 `voxelEdgeOpacity` 从0改到1作为最终收口，它会恢复旧的完整12棱线，观感未必等于新 ink。
- ink mesh 不进入逻辑拾取；新增资源要有共享/释放策略。调整 ink 后，高档需复核 depth/normal/AO 一致性；目前只是风险项，不凭猜测重写 prepass。

## 5. P1：奶油与光影——先统一档位口径，再调材质

### 5.1 当前档位不是“所有手机都一样”

审阅基线的自动档与屏宽/核数相关：竖屏手机可能走 low（SSAO关、MSAA0、SMAA LOW），同设备横屏844可能走 high。DPR必须读实际renderer/缓冲，不能仅看旧 `quality.pixelRatioMax`；写作期间已有并行R7缓冲尺寸修正与C3/阴影证据提交，实施者要接续它们，不回退已修正的限幅。桌面高档的暖褐 SSAO 色 `#60422E` 与较强强度仍需在最新HEAD核对。**这能影响高档观感，不能拿它解释SSAO关闭时的竖屏截图。**

每张证据记录 viewport、DPR、实际quality、SSAO开关、AA、exposure、tone mapping链。开发环境可在初始化前用现有 `globalThis.__voxalblastQuality` 强制 high/low；生产不保证该覆盖入口可用，不把它包装成正式功能。

### 5.2 调整顺序与新裁决

1. 修完映射与线稿，先以 AO 关闭、exposure=1、同一灯光拍完整18色与空格；不改变已正确的单次色彩转换。
2. 空格先保留 `#F4E4C0`。若线密度降低后仍显灰黄，**只对空格试验 `#F8EACB`**，活动面仍可用原 `#FFF1CC`；与原色并排通过后再入配方。禁止一律纯白、发光或全局漂白。
3. 彩漆以 roughness .58、clearcoat .12 起；若倒角仍软塑料，只单独测试 clearcoat .06–.10 / roughness .60–.66，不同时缩圆角或加锐化。目标是宽、稳、轻的受光，不是消掉体积。
4. 高档 AO 不再沿用旧木作暖褐作为新主题目标。首轮允许与low一样关闭；若恢复，试中性蓝灰 `#52606B`、intensity .35（.20–.55范围），减小实际作用范围，单独审查凹缝而非整面脏灰。radius 的screen/scene语义先核实，不能把旧.075直接说成.075个格。
5. 候选与主盘统一 `toyLights.js` 入口，保留各自单次tone mapping。不要给候选偷偷补一盏独立强灯解决色差。

`material.toneMapped=false` 不能绕开末尾的整帧 ToneMappingEffect；`recipe.materials.shared` 当前也未完整接入。**每个新参数需列“配方→config→消费材质/效果→实际读数”路径**，不在死配置上来回试数。

### 5.3 投影沿用上一轮裁决，但必须实际可见

固定安全地面保留，不抬到旋转包围范围内，不恢复底座。优先一层艺术化程序软影；真实投影尚未胜出前，不要求high硬用出屏的真实影子。不能两层叠黑。

软影参考初值：宽约盘宽.65–.85、高约盘屏高.06–.12、中心距停靠盘底约.12–.18个盘屏高、opacity约.14。需要随地面透视定位、避开候选托盘；高度只轻调大小/浓度，不随每个旋转角点抖动。主要视口都要能读出“盘底与地面之间有空气”，而不是只在报告中 shadow=true。

## 6. P0-C：让侧边积木真正出现——本节修订过强的禁区规格

**原先“各旋转姿态AABB并集+24px，碰到就剔”的通用写法在窄屏过于保守，本轮明确替换为分级禁区。** 禁止继续用“减少装饰”无限退化到整层消失；也禁止缩主盘或改变手势视角来给布景让位。

### 6.1 分级规则

| 区域 | 新规则 |
| --- | --- |
| HUD、工具按钮、三候选、可见提示/标签 | 实际控件/内容矩形为硬保护，起始padding6–8 CSS px；不要直接拿整个全宽wrapper当一块不可布景的墙。命中区仍≥44，不缩hitbox |
| 不透明主盘的投影AABB | **布局软参考，不再相交就整件剔。** 背景可在更远深度被主盘正常遮挡；这是“在后面”，不是允许背景盖住主盘20% |
| 主盘边界与落点/共享线反馈附近 | 约8–12 CSS px的低干扰缓冲，控制背景边线对比与局部位置；动态提示优先，不能让高对比横线干扰判读 |
| 画框边缘 | 允许有设计的裁切，特别是近景大块；不能退到只剩几像素又计为“可见” |

背景始终排除 raycast。**不授权任何可见的背景像素覆盖棋盘/ghost/marker**；深度遮挡保持正确，不靠 clearDepth/renderOrder 将布景盖上来。

### 6.2 先布局，再局部避让；不全层删除

1. viewport/模式切换时选竖屏、横屏、桌面不同 anchor 集合；不是用同一个NDC点加无限平移。
2. 优先放能读出造型的拱门/台阶中景，其次近景裁切块，最后才散块。
3. 冲突时依次：沿边缘小幅外移 → 在授权的上/下缘锚点间切换 → 缩小到仍可辨识的尺寸 → 替换为同风格较窄片段 → 最后才隐藏该件。
4. 允许建筑一部分被棋盘正常遮住，只要剩余部分有可辨识形状且不扰接缝。不要要求每个prefab完整露出，亦不要把一个孤立方块算“建筑完成”。
5. 不每帧重抽位置；小幅浮动与转面期间用稳定布局/滞回，局部淡出也不能让两侧一起闪没。

**最低构图门槛：** 390竖屏与桌面，左右各至少一个可辨识的积木中景片段；320窄屏/low至少保住一组明确的建筑片段和另一侧一个有设计的近景点缀。作为初查，建筑有效可见片段宽≥约.06W、高≥约.08H；这只筛掉碎屑，最终仍须看是否像拱门/台阶，而不是一根残柱。

### 6.3 门禁必须验证“画出来”，不是只数作者建了几件

每组报告 `authored / visibleFlag / inViewport / effectiveVisible / projectedBounds / dodged / culledReason`，区分被HUD挡、被主盘遮、移出屏、质量档主动省略。**visible=true或AABB进屏都不自动算有效可见**。

探针按模式/档位验证上述最低构图，不盲目要求低档每个族都非空。开发诊断可用隔离渲染/实例ID图验证可见片段，必须恢复原渲染状态；不为生产新增一套常驻renderer。增加“故意隐藏全部中景→测试必须失败”的自检。修复WIP的 dodge 后要重新读数，不能因 dodged>0 就认定修好。

## 7. P0-D：云朵改按宽度设计，不再铺满半屏

### 7.1 首轮尺寸裁决

云纹理仍用现有512×192、aspect=2.667，不裁其透明安全边。

```text
cloudQuadWidthCss = viewportWidthCss × widthFraction
cloudQuadHeightCss = cloudQuadWidthCss / (512/192)
widthFraction 首轮取 .24 / .30 / .36，单朵上限 .40
```

这里是**整张透明四边形的尺寸**；素材实际云体只占约75%–81%宽，实绘约.18–.29W，最大约.32W。再用统一的全屏 renderCamera/depth 转换为世界尺寸。**不要把 .24 继续乘屏高**，也不要重复乘一次 aspect。

### 7.2 布局与遮挡

- 初轮手机用3–4朵，桌面4–6朵；上限不是必须全部同时入屏。露出大面积清亮蓝天，不叠成白墙。
- 云只在天空层，尽量置于两侧和顶部开口，避免横跨工具行和压住主盘上沿；主页不在Logo后堆一整团巨大奶白垫子。
- 给云独立的弱保护/覆盖率约束，而非完全不参与构图。目标云体占可见天空面积约10%–20%，超过25%需复评；并非每一帧强制相同百分比。
- 先缩尺寸、分层与数量，再调opacity。保持清楚双色轮廓；不是把巨大云调透明得到灰雾。
- 天空仍从 `#42ABF2` 到 `#B8E5F7`。先做只关云层的A/B；若露出的天空仍灰，再查实际输出链，不能凭截图断言palette错误。
- 横移速度沿用.006/.008/.010屏宽每秒，整朵离屏后再循环。尺寸修正不能使wrap提前跳位，也不新增第二套时钟。

### 7.3 地板先保持克制

恢复两侧建筑和合适云之后再看地板。现有大面积均匀网格显空，首先与场景被剔空有关，不先加噪声、污渍或密网格。仍显平时再单独测试：远处铺装线降低对比、近景增加少量有体积的侧边台阶；中央投影与棋盘识别区留净。不要改成另一种写实石地/草地主题。
