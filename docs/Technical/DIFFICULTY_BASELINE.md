# 难度与单局长度测量（v0.8.1 基线 / v0.8.3 复核）

> v0.8.3 / 2026-09-16。**纯测量**：两次都没有改动任何玩法文件。数字来自 `tools/reachability.mjs` 直接 import 规则层（board / shapes / scoring / honors）的对局模拟。
> 原始结果：[tools/reachability-pool-matrix.json](../../tools/reachability-pool-matrix.json)（v0.8.2，用旧 LCG）、[tools/reachability-lattice-matrix.json](../../tools/reachability-lattice-matrix.json)（v0.8.3 复核，mulberry32）。

## 阅读修正（A/B/C/D 测量工具升级）

本页保留 v0.8.3 的历史矩阵和原始数字，**下列修正优先于旧文中的解释**。新实验见 [结构化开局 × 阶段发牌 A/B/C/D](DIFFICULTY_ABCD.md)。本页候选池 A/C/D 与新实验 A/B/C/D 的命名空间不同，不可混用。

- 旧工具从空棋盘开始、无道具；不能称为完整正式玩法的基线。开局预设可能增加压力，也可能提供消除机会，**不能断言它一定让游戏更简单**，因此旧结束率不是有证明的真机上限。
- `noise` 是槽位优先、75%立即消除贪心＋25%随机的机器人，未做真人校准；`greedy` 同样槽位优先，不搜索全手牌顺序，**不是最优玩家或严格的高手上界**。
- `stepsWhenEnded` 仅描述已结束子样本，不能代替全体局长。若半数以上在观察上限仍未结束，全体中位结束步数应报告为 `>600`。旧工具会执行第601步，新工具修正为恰好600步并单独标记右删失。
- “没有参数解”“只能改终止条件”等旧断语仅能收窄为：**已测试的固定候选池/尺寸/手牌组合未解决长局问题**；未测试的开局、阶段发牌或其他生成策略不能据此否定。
- §2 的候选池结论（"唯一有效的低风险杠杆"）已在同口径下重测：现行池 1.0%，只留六种四格件 34.2%（弱机器人），**但换成更强策略后 5 个臂 750 局全部 0 自然结束**——池压缩的数字只在槽位优先的弱机器人上成立。另外"只留四格件"内部成分差异很大：去掉 Square 后结束率掉到 9.8%。见 [候选池与权重测量](DIFFICULTY_POOL.md)。
- “人工终止条件”方向已被制作人否决（2026-09-17，与最初设计冲突），局终只能是"手上三块同时无处可放"。§7 待决表里的"设计层终止条件"一行作废。
- §3 的 `4/N` 是面积比，不是拼块补满一整行的概率；当前四格池没有直线4，不能用“一块四格件自成满线”解释4×4结果。表中观测结果保留，机制应另测。
- **§2 与 §7 把 W90 写成"保留小件"是错的**：W90 的 Dot、Line 2、Corner 权重为 0，这三种形状不再发出——它与 D 的**组成员完全相同**，只差 Line 3 的占比。真正"保留十种、只调权重"的版本已补测（`soft75`/`soft82`），效果温和得多：典型玩家结束率 1.0% → 4.2% / 8.8%，而删掉小件的 D / W90 是 16.2% / 21.0%（Dot 与 Line 2 是拥挤时的救命小块）。见 [紧张度测量](DIFFICULTY_TENSION.md) §4.4。

## 0. 结论（历史记录；解释边界以上述修正为准）

1. **现行候选池下单局没有自然长度**：400 局近似真人模拟（noise）只有约 1% 自然结束，其余全部撞 600 手上限；最优玩家（greedy）0～0.3%。局终条件是"手里三块候选同时无处可放"，这几乎不发生——**换批、锤子、火箭、炸弹整局没有出手机会**。
2. **结构性缩小棋盘不加大难度，方向是反的**（本次要回答的问题）：同一套 4 格池下，4×4×4（56 格）**19.5%** 自然结束，比现行 5×5×5（98 格）的 **28.3%** 更低；6×6×6（152 格）也只有 **15.1%**。4×4 加上现行池则只有约 **1.8%**（和 5×5 的 1.1% 同级）。**现行 5×5 在这条轴上已经是峰值**，唯一的例外是极端的 3×3（100% 输、每局约 60 手，等于换了一个游戏）。
3. **唯一有效的低风险杠杆是候选池成分**：把池子改成"只有 4 格件"（去掉单格、直线 2、直线 3、三格转角），5×5 下自然结束从 1% 提到 **28%**；但只到 28%，而且结束局的中位手数仍在 300 手左右。
4. **"单局太长"没有参数解**：池 / 面宽 / 手牌三组参数全部试过，最好的组合仍有约 72% 的对局超过 600 手。要让单局明显变短，只能引入设计层终止条件（手数或时间预算）或改消除经济——那属于玩法改动，需要制作人拍板。
5. **手牌 3→4 无效**（24.7% vs 28.3%，方向还略差），这条路不必再试。

## 1. 方法学修正：旧 LCG 会按种子聚簇（先看这条）

v0.8.2 的矩阵用模拟器原有的 31 位 LCG。复核时发现同一配置换种子结果差得离谱（4×4 + 4 格池、noise、400 局）：

| 生成器 | 各种子的自然结束率 | 均值 | 极差 |
| --- | --- | --- | --- |
| LCG（旧） | seed 1 **30.8%**、2 **12.5%**、3 **32.3%**、12345 **12.5%**、777 **31.8%** | 24.0% | 19.8pp（双峰） |
| mulberry32（新） | seed 1 21.8%、2 16.8%、3 20.0% | 19.5% | 5.0pp |

LCG 的连续取值强相关，把**整局**聚成"好种子/坏种子"两簇，单种子结果不能当配置结论用。工具已加 `--rng=mulberry32` 与 `--seed=`（默认仍是 LCG，保证历史数字可复现）；**本文此后所有结论数字都是 mulberry32 三个种子的均值**。

**修正**：v0.8.2 写的"5×5 + 4 格池 = 42.3% 自然结束"偏高。同配置 mulberry32 三种子是 25.8/29.5/29.5 → **28.3%**。下表同时给出两版以便对账。

## 3. 结构性方案：4×4×4（56 格）实测——不成立

同一套 **4 格池（E）**、noise、400 局 × 3 种子（3×3 为 2 种子），只换晶格尺寸：

| 外壳 | 唯一格 | 线数 | 自然结束均值 | 结束局中位手数 |
| --- | --- | --- | --- | --- |
| 3×3×3 | 26 | 36 | **100%** | 53～59（整局约 60 手） |
| **4×4×4（提案）** | **56** | **48** | **19.5%**（21.8 / 16.8 / 20.0） | 270～370 |
| 5×5×5（现行） | 98 | 60 | **28.3%**（29.5 / 25.8 / 29.5） | 308～335 |
| 6×6×6 | 152 | 72 | **15.1%**（15.0 / 13.0 / 17.3） | 346～391 |

4×4 配**现行池**：1.0 / 2.5% → **约 1.8%**，与 5×5 的 1.1% 同级，等于没改善。

**机制读数（假设，与数据一致）**：一条线能被一块拼满的比例是 `拼块最大格数 / 面宽 = 4/N`——N=4 时正好 100%，一块 4 格件就能补满一整条线，等于"免费消除"；N=5 是 80%，N=6 是 67%。线密度 `12N / (N³-(N-2)³)` 则是 N=3 → 1.38 线/格、N=4 → 0.86、N=5 → 0.61、N=6 → 0.47。面越小越靠近"一块补满一条线"（更容易），面越大腾挪空间越多（也更容易），5×5 恰好夹在中间；3×3 是特例——4 格件占了面的近一半，一局活不过 60 手。

**改动成本**（供决策记账）：`board.js` 的 `SH`、`config.js` 的 `OPENING_LAYOUT` 目标值（现在按 98 格约 13% 定）、`tools/screenshot.mjs` 里"必须正好 98 个 mesh"的断言、渲染取景参数、存档校验（`session.js` 的 `isShell` 会静默丢弃旧坐标）、以及 15 处文档/注释里的"98 / 150 / 5×5×5"。成本最高、实测效果为负。

## 4. 手牌 3→4：无效

5×5 + 4 格池、noise、400 局 × 2 种子：批次 4 为 22.5 / 26.8% → 均值 **24.7%**，比批次 3 的 28.3% 还略低。v0.8.2 的 LCG 结果（C 池 3.5%→3.5%、D 池 9.8%→8.3%）方向一致。

## 5. 复现命令

```sh
# 5×5 候选池对照（本文 §2 的一行）
node tools/reachability.mjs p2 --rng=mulberry32 --seed=1 --games=400 --strategy=noise --pool="Square,L,J,T,S,Z"

# 结构性对照：同一套池，只换晶格（本文 §3）
node tools/reachability.mjs p2 --faces=4 --rng=mulberry32 --seed=1 --games=400 --pool="Square,L,J,T,S,Z"
node tools/reachability.mjs p2 --faces=6 --rng=mulberry32 --seed=3 --games=400 --pool="Square,L,J,T,S,Z"

# 旧 LCG 的聚簇现象（本文 §1）
node tools/reachability.mjs p2 --faces=4 --rng=lcg --seed=3 --games=400 --pool="Square,L,J,T,S,Z"
```

`--faces=` 按 `board.js` 的同一批公式重建晶格，并在 N = 5 时逐格与 board.js 比对（映射一改就抛错），同时校验 `N³-(N-2)³` 的唯一格数；`--pool=` 取形状子集（重名＝加权），`--batch=` 改手牌，`--rng=` / `--seed=` 换随机源；输出带本次实际使用的 lattice / pool / batch / rng / seed 与 `endedNaturallyPct`、`stepsWhenEnded`。

## 6. 判读边界

- 模拟**不含道具**（换批 ×2、锤子/火箭/炸弹各 ×1），也不含**开局预置**（从空棋盘开跑）。两者都让实际更简单，所以表中的"自然结束%"是**不救场的上限**，真机更低。
- noise = 每步 75% 取当前消除线数最多的落点、25% 随机（近似真人）；greedy = 总取最多消除线（最优玩家上界）。两者只给区间，**不能替代真人分位数**。
- `avgStepsPerGame` 在大量对局撞上限时接近 601，那不是局长；`stepsWhenEnded.p50` 才是"一局多长"的可读数字。601 手 = `STEP_CAP + 1`，代表"没结束"。
- 分数被抬高（现行池 170k → 4 格池约 200k → 4×4 约 310k～425k）。`tiers.js` 的阶位阈值仍全为 null，任何池或尺寸改动都会改变标定基准。
- 未测：开局预置加重、道具配额收窄、规则级终止条件（手数/时间预算）。这三项都不是本轮参数范围内能回答的。

## 7. 待决（制作人口径）

| 方案 | 实测效果 | 代价 / 判断 |
| --- | --- | --- |
| E：池只留 6 种 4 格件 | 自然结束 1% → 28%，结束局中位 300 手左右 | 删 4 类小块（含直线 3），手感变成"只发俄式方块"；**唯一低风险有效项** |
| W90 / D：4 格件为主，**删掉三种小件**（权重 0；早期写成"保留小件"是错的） | 16.4% / 14.1% | 温和，但解决不了"单局太长"；小块是拥挤时的救命手段，删掉代价真实 |
| 结构性 4×4（56 块） | **19.5%，比现行更低**；配现行池约 1.8% | **建议否决**：成本最高且方向相反 |
| 手牌 4 | 24.7%，无效 | 建议否决 |
| 设计层终止条件（手数/时间预算或改消除经济） | 未测 | 唯一能真正把单局缩短的方向，属玩法改动 |

下一步可选：① 先把"开局预置"纳入模拟（拆掉当前模型与真机的这处偏差），量"开局加重"这条零规则成本的杠杆；② 接受"能一直玩下去"并把难度交给候选池 E；③ 讨论设计层终止条件。
