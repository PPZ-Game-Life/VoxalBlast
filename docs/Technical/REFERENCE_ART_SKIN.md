拖动中的灰色无效态、回弹动画和同色预消除见 [拖动与预消除反馈](PLACEMENT_FEEDBACK.md)。

2026-09-23 开始制作，2026-09-24 完成验收。以本轮用户提供的横屏、竖屏截图为视觉目标。本记录覆盖旧版美术规范中的颜色、镜头、UI 实现和布局参数；游戏规则与 98 个共享棱角实体保持原实现。

## 资源与布局

生成并接入 12 张透明 UI 切图、横竖屏独立背景和透明花草石台；原图集、完整提示词、裁切坐标与来源见 [资源说明](../../public/art/reference/README.md)。分数、数量、选中/禁用状态仍由代码实时控制。音量按钮复用现有声音偏好存储。

`src/reference.css` 在旧样式之后加载，负责本轮参考皮肤。桌面左上两行分数牌、中央四道具、右上音量/帮助/设置；手机将道具下移到第二行。三格托盘位于底部。手机背景使用独立 portrait source，避免横图居中裁切后丢失小狗与城堡。保留程序 SVG 作为图片加载失败时的背景兜底。

石台为不参与输入的独立透明图片，按休止方块包围盒投影定位，跟随视口和缩放，不随翻面动画旋转。背景与石台没有烘焙游戏方块。

## 实时方块

- 共享 `RoundedBoxGeometry`：边长 0.97，倒角 0.14，segments 5，格间距 0.03。棋盘、候选和拖拽继续共用一套几何和材质入口。彩色方块的清漆强度为 1、粗糙度为 0.16，强化圆角反光。
- 空白方块：奶油桃木色 `#FFCFA3` / 活跃面 `#FFD3AC`；弱化原有灰色笔触与凹凸，保留细微表面变化。
- 占用方块：高饱和亮面红、蓝、绿、紫、黄等漆色。`referencePalette.js` 仅映射渲染 RGB，存档与规则仍使用原来的颜色标识；旧局无需重置即可应用皮肤。
- 统一 Neutral tone mapping，避免 ACES 将绿、蓝高光压成明显粉彩。保留清漆、环境反射和接触阴影。
- 候选相机接近正面，采用共同的 3×3 包围范围保持各候选单格等大；真实三维包围盒继续约束候选不被卡片裁切。预览区域缩入托盘内框，上下分别留出 14% / 17%，左右留出 5%。
- 相机方向为 `[0.429, 0.208, 0.879]`，相对既有 16° bearing dock 的侧视角约 10°、俯视角约 12°。根据用户反馈，收回 v0.8.27 的约 26° 侧视和 22° 俯视。既有微调范围、翻面阈值和拖拽代码保留。
- 分数牌的皇冠、标签和数字分别留出空间，字号随面板大小变化；分数更新及面板缩放时，按真实文字宽度缩小长数字字号，完整保留数值。数字行高 1.2，避免文字轮廓挤出行框。
- **皇冠只留给 BEST（v0.9.22，2026-09-29 制作人拍板）**：分数面板两行原本共用同一条 `.score-chip::before, .best-chip::before` 规则画 `crown.png`；制作人要求「左上角 BEST 那里保留皇冠 icon，SCORE 左边那个去掉」。现在只由 `.best-chip::before` 绘制，SCORE 行只剩标签和数字。
- **左上角整体对齐（v0.9.23，同日续修）**：制作人接着说「Score 标签往左顶到和皇冠同位，帮我调整下左上角整体的观感，对齐啥的」。
  - 横向：`.topbar .score-chip { padding-left: 0 }`——SCORE 的标签站到 chip 的左沿（`--plaque-width * .16`），也就是皇冠所在的同一条竖线；`.12` 的内边距只留给 BEST（它要躲开前面的皇冠）。数字仍右对齐在 `.82`（凹槽右沿内约 3.5px，视觉不变）。
  - 纵向：两行的 `top` 从 `.135/.315` 改成 **`.118/.303`**，让行盒子中心落在木牌两条凹槽的中心上。**这个数是量出来的**：3x `Page.captureScreenshot` 把 HUD 裁下来扫暗线，390×844 下凹槽内沿是 y 24.0/50.3（BEST 槽）与 55.7/80.7（SCORE 槽），中心 37.2/68.2；改前两行中心是 40.0/70.2，**都偏低约 2.5px**。`tools/art-alpha-box.mjs` 从美术本身算出同一条：槽在 295 高的切图里是 63..140 与 156..232，即 34.5%/65.9% 的高度，两边对得上才落码。
- 诊断 `preview().pieceColor` 表示当前渲染色，新增 `storedPieceColor` 表示游戏/存档 RGB；落点与候选颜色一致性断言继续有效。
- `placement().center` 提供操作面中心的真实投影。拖拽探针的吸附检查直接进入操作面中心，避免把“从托盘穿过边界产生的钳制偏移”误当成吸附映射；边界进出仍由独立 C 用例覆盖。翻面检查若已位于末行/末列，会向内移动一格，继续严格断言一格跟随，不放宽阈值。鼠标抬升与原有拖拽逻辑未改动。

## 游玩区优先布局（2026-09-24，基于 v0.9.0）

## 对话框表面：每个木面按钮都必须自己定位（v0.9.9，2026-09-25）

制作人报「设置界面显示有问题」。**所有几何断言都是绿的**：面板 `display: grid`、卡片盒子非零、五行都在正确坐标、`elementFromPoint` 返回卡片、UI 探针的开/关/焦点全过。真正的问题不在布局，而在**每个木面按钮的 `::before`**（v0.7 木质感那一层）：

- 那条规则给 `.icon-button` / `.item-button` / `.modal-close` / `.home-primary` / `.home-secondary` 统一画木面：`content:''; position: absolute; inset: 4px 4px 5px; border-radius: inherit; z-index: -1`。
- 它是 `position: absolute`，所以**宿主元素必须自己定位**，否则会去找最近的已定位祖先。`.icon-button` / `.home-primary` / `.home-secondary` 在 `.icon-button, .home-primary, .home-secondary { position: relative }` 里；`.item-button` 在 `styles.css` 里有；**`.modal-close` 谁都没有** → 它逃到了最近的已定位祖先，也就是 `.modal`（`position: fixed; inset: 0`），于是画出一块**内缩 4px 的整屏木板**，盖住卡片的标题与全部行。
- 压在文字上方而不是下方，是 `isolation: isolate`（同组规则）造成的：关闭按钮成了层叠上下文，按"已定位后代"这一步绘制，排在卡片文字之后。所以 设置 / 操作说明 / 排行榜 三个带关闭按钮的对话框都读成"一块空白木板 + 只剩 ✕ 和两个开关"。没有关闭按钮的结算卡（`#game-over`）一直是好的——这也解释了为什么它没被早发现。
- 实测指纹：木板的边界正好等于伪元素自己的 inset（390×844 下 x 4…385、y 4…838），据此定位到元凶。修复就是让 `.modal-close` 自己 `position: relative`（`toy.css` v0.7 段那一行），木面随即收进 38×38 的按钮里。

**回归防线**：`npm run probe:dialog`（`tools/dialog-surface-probe.mjs`）逐个打开设置 / 操作说明 / 排行榜三个对话框，断言 ①对话框内**不存在"宿主 static + 伪元素 absolute"的组合**（这条就是上面那个缺陷的不变量形式），②把卡片自己的盒子从合成帧里裁下来、统计深色文字像素（标题区 ≥60、整卡 ≥1200；坏版本标题区实测 **0**、修好后 **530~1613**），③卡片盒子在视口内。它对未修复的 CSS **确实会红**：负向对照实测三个对话框各报 `button#…-close ::before (inset 4px 4px 5px)` 加 `0 dark px`。


## 滑动归属：只有顶部能滚动（v0.9.8，2026-09-25）

制作人报「滑动整个窗口会上下滑动，整体滑动的区域最好只在顶部响应」。两个独立的成因：

1. **窗口本身能滚**：`styles.css` 的 `body { min-height: 100vh }` 是 v0.2 流式布局的遗留。手机上 `vh` 是**大视口**（地址栏收起时的高度），可见视口是 `dvh`，这条 100vh 地板让文档永远比可见区域高一条地址栏，滑动后整局（含顶部 HUD）被推上去；`.game-layout` 是 `position: absolute; inset: 0`，锚在初始包含块上，会跟着文档一起被推走。v0.9.8 把那行从 `styles.css` **删掉**（单一真源，不在 `reference.css` 再叠一条覆盖），文档高度 = `#app` 的 `100dvh` = 可见视口，并加 `overscroll-behavior: none` 关掉整页下拉刷新与橡皮筋。
2. **手势归属隐含**：玩家手指落点决定 `touch-action`。`.scene-wrap` / `.piece-slot` / `.item-button` 各自是 `none`，但**它们之间的空地不是**——顶部天空带、棋盘两侧草地、托盘木框、道具条缝隙命中的都是 `.game-layout`（`auto`），一滑就滚窗口。新增两个惰性层（`index.html` 里 `.game-layout` 的**前两个子元素**，因此棋盘/托盘/道具条作为后续兄弟永远画在其上、不会丢手势）：`.scroll-shield` 以 `touch-action: none` 铺满整屏兜住这些缝隙，`.scroll-strip` 只在顶部 HUD 带（`20vh`）放行 `pan-y`，保留"万一溢出还能从顶部滚"这条后路；三块游戏表面（`.board-section` / `.bottom-panel` / `#item-bar`）各自声明 `none`，因为它们在 shield 之上。

`npm run probe:scroll`（`tools/scroll-containment-probe.mjs`）用真实 CDP 触摸对账（合成两段溢出：`body` 强制 170vh 模拟手机的 vh>dvh、`#app` 内追加溢出块）：修复前顶带、托盘、两侧草地都能把窗口滚走 245px；修复后 390×844 与 1440×900 各 15 项全 PASS——只有顶带（`pan-y`）能滚，棋盘、托盘、道具条与两侧草地全部为 0，且 `body` 的 `min-height` 不再解析成视口高度。**未做物理机复测**（headless 没有地址栏，`vh === dvh`，故该差值用合成溢出代替）。
