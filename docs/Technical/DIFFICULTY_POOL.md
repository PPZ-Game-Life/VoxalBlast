# 候选池与权重测量：五种压缩池 × 两种发牌

> 测量 schema 1，基于正式游戏 v0.8.3（2026-09-17）。只修改 `tools/` 与技术文档：**不修改正式玩法、版本号、渲染、存档或依赖**。5×5×5 外壳、98 个唯一格、每批三候选、无道具保持不变。模拟无道具，不是完整真机局长预测。上一轮（结构化开局 × 阶段发牌）见 [A/B/C/D 测量](DIFFICULTY_ABCD.md)。

## 1. 结论

1. **池子成分确实能大幅改变弱机器人的自然结束率**：现行十种等权重 1.0% → 只留六种四格件 34.2%（配对差 +33.2pp，600 对里 87 对只有压缩池那一侧结束、0 对反过来）。这是本项目测过的所有杠杆里幅度最大的一个。
2. **但换成更强的策略后全部归零**：`space`（一步前瞻、考虑全部手牌槽位）下 5 个臂共 750 局，**自然结束 0 局**，包括压缩到极致的 e 池。也就是说 §1.1 的数字刻画的是"槽位优先的弱机器人"，**不是游戏本身的可输性**。
3. **阶段发牌的价值随池子压缩而消失**：uniform → staged 的配对差在现行池是 **+11.5pp**，到 e 池变成 **−2.2pp**。阶段发牌本质是"把配比推向四格件"，池子本身已经是四格件时它无事可做。
4. **新发现（机制未定）：把 Square 从四格池里去掉，结束率反而从 34.2% 掉到 9.8%**（配对差 −24.3pp）。同为四格件，成分不同差 24pp；这条不能用"越大件越难"解释，需要单独实验。
5. **讨论目标仍未达到**：最好的一臂（e/staged）自然结束 32.0%、S(300)=85.7%、已结束局中位 317 手；目标是"中位 60–120 手"，差一个数量级。池压缩是**音量旋钮，不是长度旋钮**——它把"结束"从 1% 抬到三成，但剩下的七成照样撞 600 手上限。
6. `w90/staged` 与 `d/staged` 逐局完全相同，这是设计使然而非 bug，见 §5。
7. 本轮**没有为追求好看的数字中途改配方**；六种池、两种发牌、种子与样本量在跑之前就固定下来了。

## 2. 臂设计

池定义在 `tools/difficulty-model.mjs` 的 `POOL_SPECS`，全部使用正式 `SHAPES` 里已有的形状；`current` 逐值等于正式十种等权重。

| 池 | 组成 | 四格件占比（等概率臂的期望） |
| --- | --- | --- |
| `current` | 十种全留，各权重 1 | 60% |
| `c` | 去 Dot、Line 2（8 种） | 75% |
| `d` | 再去 Corner（7 种，三格件只剩 Line 3） | 86% |
| `w90` | 六种四格件权重 3、Line 3 权重 2 | 90% |
| `e` | 只留 Square/L/J/T/S/Z（6 种） | 100% |
| `e5` | 只留 L/J/T/S/Z，**去 Square**（5 种） | 100% |

两种发牌臂：

- `uniform`：按池的权重累计表抽取，等价于现行正式发牌（`SHAPE_NAMES[floor(r*10)]`）在 `current` 下的行为。
- `staged`：沿用上一轮固定的阶段配方（入局 20/30/50、建压 10/20/70、挑战 0/10/90、缓和 10/20/70，54 步后 18+6 循环），阶段权重只决定**组**（补洞组＝Dot/Line 2、三格组＝Line 3/Corner、四格组＝六个四格件），组内等概率。
- **阶段臂把阶段权重在"该池仍有成员的组"上重新归一化**：`e`/`e5` 池没有补洞组与三格组的成员，于是 0.2/0.3/0.5 之类的配比落到剩下的组上按比例放大，不会留下发给空组的配额。
- 两种臂每槽都恰好消耗两个随机数（第二个在等概率臂丢弃），配对随机流因此保持对齐；配对发生在同种子、同局编号。
- 配对比较只落在"**只差一个因子**"的臂之间：同池不同发牌、同发牌不同池。因此 12 个臂产生 21 组配对，而不是把它当成一个混合排名。

## 4. 敏感性检查：space，每个臂 150 局（3 种子 × 50 局）

| 臂 | 自然结束 | S(600) | 截断平均步 | 消除落子占比 | tight 落子占比 |
| --- | --- | --- | --- | --- | --- |
| `current/uniform` | 0 / 150 | 100% | 600.0 | 61.2% | 0.00% |
| `current/staged` | 0 / 150 | 100% | 600.0 | 69.1% | 0.00% |
| `e/uniform` | 0 / 150 | 100% | 600.0 | 72.3% | 0.00% |
| `e/staged` | 0 / 150 | 100% | 600.0 | 72.4% | 0.00% |
| `e5/staged` | 0 / 150 | 100% | 600.0 | 72.7% | 0.00% |

全部配对差为 0。压缩池确实让强策略**更频繁地消除**（61.2%→72.4% 的落子带消除），但它从不把自己逼到"三块都放不下"。这与上一轮 `space` 下阶段发牌归零的结论一致：**弱机器人测出的难度差异，在强策略下普遍消失**。

## 5. 两个必须写清的性质

### 5.1 `w90/staged` 与 `d/staged` 逐局完全相同

不是 bug，是阶段配方的定义决定的：阶段臂只按**组**配比发牌，组内等概率，**池的相对权重在阶段臂里不可表达**。`d` 与 `w90` 的组成员恰好相同（补洞组为空、三格组只剩 Line 3、四格组六种齐全），所以两者的阶段发牌逐槽位、逐局一致（600 对逐局 `steps` 相同、首手相同）。工具里已把这条写成断言。

实践含义：**加权只在等概率发牌下有效**；如果将来正式发牌要阶段化，权重表就不能同时作为难度旋钮。

### 5.2 阶段发牌 ≈ 弱化的池压缩

§3.2 的单调下降（现行池 +11.5pp → d 池 +1.0pp → e 池 −2.2pp）说明阶段发牌与池压缩在打同一件事：把手上三块推向更大的四格件。池子本身已经是四格件时，阶段配方无事可做，甚至因为上下震荡（挑战/缓和）略微损失效果。

## 6. 判读边界

- 机器人仍**不是真人水平**：`noise` 是槽位优先的弱策略（只考虑第一个可放的槽位），`space` 是一步前瞻的固定启发式、被剪枝的动作无法胜出。真人的真实水平大概率落在两者之间，因此真实自然结束率大概率落在 **0% 与 34% 之间**——这个区间太宽，不足以支撑"池压缩能解决单局过长"的结论。
- 未跑实机截图、物理机、帧率或触感；模拟不含道具（换批 ×2、锤子/火箭/炸弹各 ×1）、开局预置之外的救场手段、观察时间、手势失误与主动退出。
- 所有生存数字受 600 手上限饱和：`e/staged` 仍有 68.0% 的对局在观测窗内没有结束，因此"中位局长"只能报告为 `>600`。
- `S(n)`、自然结束率的 Wilson 区间只代表该机器人在该模型内的抽样不确定性；另有逐种子列，`d/staged` 的三种子是 23 / 10.5 / 18%，说明单种子不能当配置结论用。
- 本轮只测了六个预先固定的池。没有测别的形状（例如重新引入 Line 4、引入五格件、方形与长条的混合池），也没有测"同池但开局密度不同"的组合。
- §1.4 的 Square 效应只有一条观测：**机制未定**，不能写成"Square 让游戏更难"这样的因果结论。

## 7. 运行与复现

无需安装新依赖，不启动网页服务器，不构建游戏产物。

```powershell
# 专项验证：规则差分、随机流、阶段边界、池定义与加权、配对统计
node tools/difficulty-tests.mjs

# 主对照：6 池 × 2 发牌 × 3 种子 × 200 局 = 7200 局（约 115 秒）
node tools/difficulty-abcd.mjs --arms=current/uniform,current/staged,c/uniform,c/staged,d/uniform,d/staged,w90/uniform,w90/staged,e/uniform,e/staged,e5/uniform,e5/staged --games=200 --seeds=1,2,3 --strategies=noise --out=tools/results/difficulty-pools.json

# 敏感性检查：5 臂 × 3 种子 × 50 局 = 750 局（约 233 秒）
node tools/difficulty-abcd.mjs --arms=current/uniform,current/staged,e/uniform,e/staged,e5/staged --games=50 --seeds=1,2,3 --strategies=space --out=tools/results/difficulty-pools-space.json
```

`--arms=<池>/<uniform|staged>` 与 `--groups=A,B,C,D` 互斥；池 id 或发牌名拼错、参数重复、范围非法都直接报错，不会静默使用默认值。输出为完整 JSON（逐局记录，不入库）、`.summary.json`（聚合、配对、阈值生存与源码指纹，约 60 KB）与同名离线 HTML 图表。

交付数据：[主对照聚合摘要](../../tools/results/difficulty-pools.summary.json) · [主对照图表](../../tools/results/difficulty-pools.html) · [space 聚合摘要](../../tools/results/difficulty-pools-space.summary.json) · [space 图表](../../tools/results/difficulty-pools-space.html)。

## 8. 改动成本（供制作人记账）

池是**内容**，不是参数：正式游戏的十种形状写在 `src/game/shapes.js`，`src/main.js` 有三处等概率抽取（首手、换批补位、续玩补位），都在 `SHAPES` 上均匀取。

| 方案 | 实现成本 | 备注 |
| --- | --- | --- |
| 删形状（`e`、`d`、`c`） | 低：改 `shapes.js` 的 `SHAPES` 数组即可，三处抽取自动跟随 | 但**手感直接变化**（只剩"俄式方块"），且 `Corner`/`Line 3` 的颜色与文档 02/05 需同步；`session.js` 已有"池外形状的候选被丢弃"的过滤逻辑，删形状后仍需复验旧存档 |
| 加权池（`w90`） | 中：三处抽取要换成按权重表抽取，新增一个权重真源 | 权重表必须进 `src/rendering/config.js` 之外的规则层单一真源，避免三处各写一份 |
| 任何池改动 | —— | `tiers.js` 的阶位阈值当前全是 `null`，所以现在改池**不会**产生重标定欠账；一旦标定过，池改动就要重标 |

历史背景：形状池已经被设计层动过两次（v0.2.24 去掉 Line 5、v0.2.31 去掉 Line 4，理由都是"贴合面宽、读起来像白送一条线"）。因此删/加形状属于制作人级决定，本报告只提供测量。

## 9. 待决（制作人口径）
