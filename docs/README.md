## 目录职责与维护

- **Planning/**：01～08 按源码描述现行实现；09 是特效升级设计提案，不代表当前能力。研究、建议和待实施段必须显式标注，不因放在该目录就自动生效。
- **Technical/**：工程事实、具名实验、流程规范和历史验证；文件类型与版本决定用途，不统一视为现行需求。
- **Archive/**：历史原稿，保留旧决策以便溯源，不覆盖现行文档。
- **Temporary/**：本机临时交接资料（当前受 Git 忽略），不是现行规范，也不作为版本库导航的必要依赖。仓库根的 `temp/`（重构交接单、逐阶段 surgery/fidelity 脚本与探针日志）和 `output/`（生图工作产物）同样不入库，见 `.gitignore`；结论进 commit 与 04 验收记录，工作文件留在本机。旋转旧稿的 82%～88% 主面目标、短滑一律弹回等已被后续实现取代，以 03/04 为准。

维护时遵循：

1. 实现事实以对应源码为准；需求变更须单独决策，不用文档整理暗中创造新规则。
2. 纯文档纠错不升级游戏版本；功能变更只同步涉及的文档，不强制把所有文件刷成同一历史日期。
3. 回归空框表示待执行，不表示代码缺失；勾选必须带版本、环境和范围，本轮静态核对不刷新旧通过记录。
4. 机器人策略不等于真人分层；模拟步数不等于游玩分钟，未含道具的结果不能直接描述救场后的局终率。
5. 远端部署、SDK、广告、线上榜单和物理设备表现必须另有实际证据；统一在 KNOWN_GAPS 说明边界。
6. 本地链接使用相对路径；源码中旧章节号可到 Archive 原稿追溯。
